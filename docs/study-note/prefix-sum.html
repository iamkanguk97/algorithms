누적합과 차분 배열

수정이 없는 구간 조회는 누적합으로, 한꺼번에 몰아서 하는 구간 수정은 차분 배열로 처리한다. 두 기술은 서로 거울처럼 대칭이다.

한 줄 정리 누적합은 구간 get을 점 get 두 번으로, 차분 배열은 구간 update를 점 update 두 번으로 바꾼다.

용어 먼저 — get / update, 점 / 구간

이 단원 전체가 네 단어의 조합으로 설명된다.

  • get = 값을 읽는 작업(조회). 배열은 바뀌지 않는다.
  • update = 값을 고치는 작업(수정). 배열이 바뀐다.
  • 점 = 칸 하나. 예) arr[3]
  • 구간 = 연속된 여러 칸. 예) arr[2] ~ arr[4], 줄여서 arr[2..4]

배열 arr = [3, 1, 4, 1, 5](1번 ~ 5번)로 네 가지 조합을 보면 이렇다.

작업예시결과그냥 배열에서 드는 시간
점 getarr[3]은?4O(1) — 칸 하나만 본다
구간 getarr[2..4]의 합은?1 + 4 + 1 = 6O(N) — 구간을 다 훑는다
점 updatearr[3]에 2 더하기[3, 1, 6, 1, 5]O(1) — 칸 하나만 고친다
구간 updatearr[2..4]에 모두 2 더하기[3, 3, 6, 3, 5]O(N) — 구간을 다 고친다

그냥 배열은 점 작업은 빠르고 구간 작업은 느리다. 구간 작업이 Q번 들어오면 O(Q·N)이 되어 시간 초과가 난다.

"구간 get을 점 get으로 바꾼다"의 뜻

이 단원의 두 기술은 배열을 다른 모양으로 한 번 바꿔 저장해서, 느린 구간 작업을 빠른 점 작업 두 번으로 만든다.

기술원래 배열에서는바꾼 배열에서는
누적합arr[2..4]의 합 = 구간 get, O(N)prefix[4] - prefix[1] = 점 get 두 번, O(1)
차분 배열arr[2..4]에 +2 = 구간 update, O(N)diff[2] += 2, diff[5] -= 2 = 점 update 두 번, O(1)

대신 공짜는 아니다. 한쪽이 빨라지면 반대쪽 작업이 느려진다. 이 대가는 각 절에서 다시 다룬다.

큰 그림 — 쿼리 문제의 두 상황

"arr[s] ~ arr[e]의 합(최대, 최소, xor, gcd, k보다 큰 원소 수 …)은?" 같은 구간 질문이 여러 번 들어오는 문제를 다룬다. 매번 구간을 직접 훑으면 질문 하나에 O(N)이 들어서, 질문이 많으면 시간 초과가 난다.

상황도구무엇을 바꾸나대가
수정 없이 조회만 있음누적합구간 get → 점 get점 update가 구간 update로 바뀜
수정을 다 끝낸 뒤 조회만 함차분 배열구간 update → 점 update조회 전에 누적합을 한 번 돌려야 함
수정과 조회가 섞여서 들어옴펜윅 트리 / 세그먼트 트리둘 다 O(log N)이 강의 범위 밖

1차원 누적합

prefix[i]는 1번부터 i번까지의 합이다. 0번 칸은 0으로 비워 두면 경계 처리가 편하다.

i012345678910
arr07324-516-309
prefix07101216111218151524

구간 합은 큰 앞부분에서 작은 앞부분을 빼서 구한다.

arr[s] + ... + arr[e] = prefix[e] - prefix[s - 1]

예) arr[3..6] = prefix[6] - prefix[2] = 12 - 10 = 2   (2 + 4 - 5 + 1 = 2)

왜 s−1인가: prefix[e]에는 arr[1..e]가 들어 있다. 여기서 arr[1..s-1]만 지워야 arr[s]가 답에 남는다. prefix[s]를 빼면 arr[s]까지 지워진다.

prefix = [0] * (n + 1)
for i in range(1, n + 1):
    prefix[i] = prefix[i - 1] + arr[i]

def range_sum(s, e):
    return prefix[e] - prefix[s - 1]
대가: 점 update가 구간 update가 된다. arr에서는 칸 하나를 고치는 점 update였던 작업이, prefix에서는 prefix[i] ~ prefix[N]을 전부 고치는 구간 update가 된다. 예를 들어 arr[3]에 2를 더하면 3번 이후의 누적합이 모두 2씩 커진다. 그래서 누적합은 수정이 없을 때만 쓴다.

같은 방식으로 뒤에서부터 쌓으면 suffix_sum[i](i번부터 N번까지의 합)이 된다.

응용 — 길이 k인 연속 구간의 최대 합

arr[1..3], arr[2..4], …, arr[N-2..N] 중 합이 가장 큰 구간을 찾는 문제다. 누적합을 한 번 만들어 두면 구간 하나의 합이 O(1)에 나오므로, N번 조회해도 전체가 O(N)이다.

best = max(prefix[i] - prefix[i - k] for i in range(k, n + 1))

관련 문제: 백준 2559 수열.

"누적합"이라는 이름의 함정

영어로는 prefix sum, 즉 "접두사 합"이다. 그런데 둘 다 고정된 조건이 아니다.

  • 꼭 합일 필요가 없다. 최대, 최소, 곱, xor로도 만들 수 있다.
  • 꼭 앞에서부터일 필요가 없다. 뒤에서부터 쌓으면 suffix(접미사)다.
# prefix_max[i] := arr[1..i] 중 최댓값
# suffix_max[i] := arr[i..N] 중 최댓값
NEG_INF = float('-inf')
prefix_max = [NEG_INF] * (n + 2)
suffix_max = [NEG_INF] * (n + 2)

for i in range(1, n + 1):
    prefix_max[i] = max(prefix_max[i - 1], arr[i])

for i in range(n, 0, -1):
    suffix_max[i] = max(suffix_max[i + 1], arr[i])
주의: 임의 구간은 "되돌릴 수 있는" 연산만 된다. prefix[e] - prefix[s-1]처럼 앞부분을 지우려면 연산에 역연산이 있어야 한다. 합은 빼기로, xor는 xor로 되돌릴 수 있다. 하지만 max·min·gcd는 되돌릴 수 없어서 prefix_max로는 1 ~ i 같은 앞부분 구간만 답할 수 있다. 임의 구간의 최댓값이 필요하면 희소 테이블이나 세그먼트 트리를 쓴다.
연산임의 구간 [s, e]이유
합가능빼기로 앞부분을 지운다
xor가능같은 값을 다시 xor하면 지워진다
곱0이 없을 때만나누기로 지우는데, 0으로는 나눌 수 없다
max / min / gcd불가 (앞부분·뒷부분만)역연산이 없다

예제 — 창고 다각형 (백준 2304)

폭 1인 기둥들 위에 빗물이 고이지 않는 지붕을 씌울 때 창고 다각형의 넓이를 구하는 문제다. 강의에서는 세 가지 풀이를 소개했다.

  1. 가장 높은 기둥 기준, O(N) — 가장 높은 기둥을 찾는다. 그 왼쪽은 왼쪽 끝부터, 오른쪽은 오른쪽 끝부터 읽으면서 "지금까지 본 최댓값"을 넓이에 더한다.
  2. 칸마다 min(왼쪽 최대, 오른쪽 최대), O(N²) → O(N) — 각 칸의 지붕 높이는 "내 왼쪽(나 포함)의 최고 높이"와 "내 오른쪽(나 포함)의 최고 높이" 중 낮은 쪽이다. 칸마다 양쪽을 훑으면 O(N²)이지만, prefix_max와 suffix_max를 미리 만들어 두면 O(N)이다. 누적합 단원에서 다루는 핵심 풀이다.
  3. 높이별로 자르기 — 높이 h마다 h 이상인 기둥만 남기고, 가장 오른쪽 기둥과 가장 왼쪽 기둥 사이의 폭을 더한다. 기둥 폭이 1이므로 폭은 오른쪽 − 왼쪽 + 1이다.
# 풀이 2 — heights[x] = 위치 x의 기둥 높이 (없으면 0), x = 1..W
prefix_max = [0] * (W + 2)
suffix_max = [0] * (W + 2)
for x in range(1, W + 1):
    prefix_max[x] = max(prefix_max[x - 1], heights[x])
for x in range(W, 0, -1):
    suffix_max[x] = max(suffix_max[x + 1], heights[x])

area = sum(min(prefix_max[x], suffix_max[x]) for x in range(1, W + 1))

백준 예제(기둥 7개)에 넣으면 정답 98이 나온다.

2차원 누적합

prefix[i][j]는 (1,1)부터 (i,j)까지 직사각형 안의 합이다. 겹치는 영역을 한 번 빼고 한 번 더하는 포함-배제로 만든다.

# 만들기: 위 + 왼쪽 - 겹친 왼쪽위 + 자기 자신
prefix[i][j] = prefix[i-1][j] + prefix[i][j-1] - prefix[i-1][j-1] + arr[i][j]

# (x1, y1) ~ (x2, y2) 직사각형의 합
total = (prefix[x2][y2]
         - prefix[x1-1][y2]
         - prefix[x2][y1-1]
         + prefix[x1-1][y1-1])

왜 마지막에 더하나: prefix[x1-1][y1-1] 영역(왼쪽 위 모서리)은 두 번 빼기에 모두 포함되어 두 번 빠진다. 그래서 한 번 다시 더해 준다.

관련 문제: 백준 11660 구간 합 구하기 5.

구간 update — 차분 배열

"l ~ r에 v를 더하라"는 수정이 여러 번 들어오고, 수정이 모두 끝난 뒤에 결과를 묻는 상황이다. 구간 전체를 고치는 대신 시작점과 끝 다음 칸만 기록한다.

diff[l] += v       # 여기서부터 v만큼 올라간다
diff[r + 1] -= v   # 여기서부터 다시 원래대로

수정을 모두 기록한 뒤 diff를 누적합하면, 각 칸에 "지금까지 켜져 있는 +v"가 모두 더해져 실제 배열이 된다.

수정기록
2 ~ 4에 +1diff[2] += 1, diff[5] -= 1
1 ~ 5에 +1diff[1] += 1, diff[6] -= 1
3 ~ 4에 +3diff[3] += 3, diff[5] -= 3
i0123456
diff01130-4-1
누적합0125510
 
diff = [0] * (n + 2)
for l, r, v in updates:
    diff[l] += v
    diff[r + 1] -= v

result = [0] * (n + 1)
for i in range(1, n + 1):
    result[i] = result[i - 1] + diff[i]
대가: 점 get이 구간 get이 된다. arr에서는 칸 하나를 읽는 점 get이었던 작업이, diff에서는 diff[1] ~ diff[i]를 전부 더하는 구간 get이 된다. 그래서 수정 도중에 값을 하나씩 읽지 않고, 수정을 모두 모은 뒤 누적합을 한 번 돌려 전체 값을 한꺼번에 얻는다.

예제 — 개똥벌레 (백준 3020)

길이 N, 높이 H인 동굴에 장애물이 번갈아 있다. 홀수 번째는 바닥에서 솟은 석순, 짝수 번째는 천장에 매달린 종유석이다. 높이 1 ~ H 중 하나를 골라 직선으로 날 때, 부딪히는 장애물 수의 최솟값과 그 높이의 개수를 구한다.

핵심 관찰: 장애물 하나는 "높이 구간에 +1"하는 구간 update다. 수정을 다 끝낸 뒤 높이별 값을 조회하니 차분 배열 상황 그대로다.

  • 길이 L인 석순 → 높이 1 ~ L에 +1
  • 길이 L인 종유석 → 높이 H−L+1 ~ H에 +1
diff = [0] * (H + 2)
for idx, length in enumerate(obstacles):
    if idx % 2 == 0:              # 1, 3, 5 ... 번째: 석순 (바닥부터)
        diff[1] += 1
        diff[length + 1] -= 1
    else:                         # 2, 4, 6 ... 번째: 종유석 (천장부터)
        diff[H - length + 1] += 1
        diff[H + 1] -= 1

hits, current = [], 0
for h in range(1, H + 1):
    current += diff[h]
    hits.append(current)

print(min(hits), hits.count(min(hits)))

예제(N=14, H=5, 1 3 4 2 2 4 3 4 3 3 3 2 3 3)를 넣으면 높이별로 부딪히는 수가 7 8 10 8 7이고, 출력은 정답과 같은 7 2다. N개 장애물마다 O(1), 높이 H개를 한 번 훑으니 O(N + H)다.

정리 — 두 기술의 대칭

누적합차분 배열
빨라지는 것구간 get → 점 get 두 번구간 update → 점 update 두 번
느려지는 것점 update → 구간 update (prefix[i..N] 전부)점 get → 구간 get (diff[1..i]의 합)
쓰는 상황수정 없음, 조회 많음수정을 모두 모은 뒤 조회
관계차분 배열을 누적합하면 원래 배열, 원래 배열을 차분하면 차분 배열. 서로 역연산이다.

수정과 조회가 번갈아 들어오면 둘 다 한쪽이 O(N)이 되어 버린다. 그때 필요한 것이 펜윅 트리와 세그먼트 트리다.
