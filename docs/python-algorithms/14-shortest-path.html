본문으로 건너뛰기

최단 경로

간선에 거리나 요금 같은 비용이 붙는 순간, 간선 수만 세는 BFS로는 가장 싼 길을 찾을 수 없습니다. 다익스트라, 벨만-포드, 플로이드-워셜이 어떤 원리로 동작하고 각각 언제 꺼내 쓰는지 정리합니다.

다익스트라heapq벨만-포드플로이드-워셜완화(relax)

이 장에서 배울 것

  • 가중치가 있는 그래프에서 BFS가 왜 틀리는지 설명할 수 있다
  • heapq로 다익스트라를 짜고, 오래된 힙 항목을 건너뛰는 이유를 안다
  • 최단 거리와 함께 실제 경로를 복원할 수 있다
  • 벨만-포드로 음수 간선을 다루고 음수 사이클을 찾을 수 있다
  • 플로이드-워셜에서 k가 가장 바깥 반복문이어야 하는 이유를 안다

최단 경로 문제 세 가지

핵심

가중치가 모두 같으면 BFS, 음수 간선이 없으면 다익스트라, 음수 간선이 있으면 벨만-포드, 모든 쌍이 필요하고 정점이 적으면 플로이드-워셜을 쓴다.

최단 경로 문제는 두 질문으로 갈린다. 출발점이 하나인가, 모든 쌍인가. 그리고 음수 가중치가 있는가. 두 답이 정해지면 쓸 알고리즘도 정해진다(비교표는 6절).

BFS로는 모자란 이유

BFS는 가까운 층부터 퍼지므로 간선 수가 가장 적은 길을 찾는다(13장). 간선마다 비용이 다르면 간선 수가 적은 길이 꼭 싼 길은 아니다.


# 그림 14-1 의 간선 가중치. (출발, 도착): 비용
weight = {(0, 1): 2, (0, 2): 5, (1, 2): 1, (1, 3): 6,
          (2, 3): 2, (2, 4): 7, (3, 4): 3}


def cost(path: list[int]) -> int:
    return sum(weight[u, v] for u, v in zip(path, path[1:]))


print(cost([0, 2, 4]))           # BFS 가 고르는 길: 간선 2개
print(cost([0, 1, 2, 3, 4]))     # 간선 4개지만 더 싸다

12
8

이 그래프의 간선은 방향이 있다. 0→1은 갈 수 있어도 1→0은 못 간다. 그래서 인접 리스트(13장)에 한쪽만 넣고, 이웃은 (도착 정점, 가중치) 튜플로 담는다.

완화: 세 알고리즘의 공통 동작

완화(relax)는 더 짧은 경로를 찾으면 거리를 갱신하는 일이다. 출발점에서 지금까지 찾은 가장 짧은 거리를 dist에 적어 두고, 간선 u→v를 볼 때마다 "u를 거쳐 가면 더 짧은가"를 확인한다.


INF = float('inf')
dist = [0, INF, INF]                     # 0 번이 시작점


def relax(u: int, v: int, w: int) -> None:
    if dist[u] + w < dist[v]:            # u 를 거치는 길이 더 짧으면
        dist[v] = dist[u] + w


relax(0, 1, 7); print(dist)              # 처음 찾은 길: INF → 7
relax(0, 1, 4); print(dist)              # 더 짧은 길: 7 → 4
relax(0, 1, 9); print(dist)              # 더 긴 길: 그대로
relax(1, 2, 2); print(dist)              # 1 을 거쳐 2 로

[0, 7, inf]
[0, 4, inf]
[0, 4, inf]
[0, 4, 6]

처음에는 시작점만 0이고 나머지는 "길을 모른다"는 뜻의 INF다. 완화를 거듭할수록 dist는 줄어들기만 한다. 세 알고리즘은 어떤 순서로, 몇 번 완화하느냐만 다르다.

다익스트라: 가까운 정점부터 확정

다익스트라 알고리즘은 출발점에서 가까운 정점부터 차례로 거리를 확정하고, 확정한 정점에서 나가는 간선을 완화한다. 이 방법이 맞는 이유는 음수 간선이 없어서다. 아직 확정하지 않은 정점 중 dist가 가장 작은 정점을 u라고 하자. u로 가는 다른 길은 확정 안 된 어떤 정점 x를 지나야 한다. x까지만 해도 이미 dist[u] 이상이고, 음수가 없으니 더 가면 늘어날 뿐이다. 그래서 확정 안 된 정점 중 가장 가까운 정점은 더 짧아질 수 없다.

"가장 가까운 정점"을 매번 빨리 꺼내려고 힙을 쓴다. heapq(7장)에 (거리, 정점) 튜플을 넣으면 첫 값인 거리가 작은 것부터 나온다.


import heapq


def dijkstra(graph: list[list[tuple[int, int]]], start: int) -> list[float]:
    dist = [float('inf')] * len(graph)
    dist[start] = 0
    heap = [(0, start)]                  # (거리, 정점)
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:                  # 오래된 항목이면 건너뛴다
            continue
        for v, w in graph[u]:
            if d + w < dist[v]:          # 완화
                dist[v] = d + w
                heapq.heappush(heap, (d + w, v))
    return dist


edges = [(0, 1, 2), (0, 2, 5), (1, 2, 1), (1, 3, 6),
         (2, 3, 2), (2, 4, 7), (3, 4, 3)]
graph = [[] for _ in range(5)]
for u, v, w in edges:
    graph[u].append((v, w))              # 방향 그래프: 한쪽만 넣는다

print(dijkstra(graph, 0))

오래된 항목 건너뛰기

heapq에는 "힙 안의 값을 줄이는" 기능이 없다. 그래서 거리가 줄 때마다 새 튜플을 하나 더 넣고, 옛 거리 항목은 힙에 남는다. 표의 4단계 (5, 2)가 그런 항목이다.

if d > dist[u]: continue는 꺼낸 거리가 이미 아는 거리보다 크면 버리는 줄이다. 없어도 답은 맞다(오래된 거리로는 더 짧아지지 않는다). 하지만 같은 정점의 이웃을 또 훑어 느려진다.


import heapq


def count_scans(graph: list[list[tuple[int, int]]], skip_stale: bool) -> int:
    dist = [float('inf')] * len(graph)
    dist[0] = 0
    heap = [(0, 0)]
    scans = 0                            # 이웃을 훑은 횟수
    while heap:
        d, u = heapq.heappop(heap)
        if skip_stale and d > dist[u]:
            continue
        for v, w in graph[u]:
            scans += 1
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(heap, (d + w, v))
    return scans


# i 에서 모든 j > i 로 가는 간선. 멀리 뛸수록 비싸서 dist 가 자주 줄어든다.
graph = [[(j, (j - i) ** 2) for j in range(i + 1, 12)] for i in range(12)]
print(count_scans(graph, True), count_scans(graph, False))

66 231

건너뛰면 간선 66개를 한 번씩만 보고, 아니면 231번 본다. 그래프가 커질수록 차이는 더 벌어진다.

부분시간이유
간선 완화O(E)정점마다 확정할 때 한 번만 이웃을 훑는다
힙 연산O(E log V)완화에 성공할 때만 넣으니 많아야 E번, 한 번에 O(log E)다. E ≤ V²이라 log E ≤ 2 log V다
전체O((V+E) log V)정점을 꺼내는 일과 간선마다 힙에 넣는 일의 합

경로까지 복원하기

"어떤 길로 가는지"도 필요하면, 완화에 성공할 때마다 prev[v] = u로 "v에는 u를 거쳐 왔다"고 적어 둔다. 끝난 뒤 도착점에서 prev를 따라 거꾸로 올라가고, 모은 목록을 뒤집는다.


import heapq

edges = [(0, 1, 2), (0, 2, 5), (1, 2, 1), (1, 3, 6),
         (2, 3, 2), (2, 4, 7), (3, 4, 3)]
graph = [[] for _ in range(5)]
for u, v, w in edges:
    graph[u].append((v, w))

dist = [float('inf')] * 5
prev = [-1] * 5                          # 어느 정점에서 왔는지
dist[0] = 0
heap = [(0, 0)]
while heap:
    d, u = heapq.heappop(heap)
    if d > dist[u]:
        continue
    for v, w in graph[u]:
        if d + w < dist[v]:
            dist[v] = d + w
            prev[v] = u                  # v 로는 u 를 거쳐 오는 것이 가장 짧다
            heapq.heappush(heap, (d + w, v))


def build_path(goal: int) -> list[int]:
    path = []
    while goal != -1:                    # 시작점의 prev 는 -1
        path.append(goal)
        goal = prev[goal]
    return path[::-1]                    # 거꾸로 모았으니 뒤집는다


print(prev)
print(build_path(4), dist[4])
print(build_path(3), dist[3])

[-1, 0, 1, 2, 3]
[0, 1, 2, 3, 4] 8
[0, 1, 2, 3] 5

prev[v]는 거리가 줄 때마다 덮어쓰므로, 끝났을 때 남은 값이 가장 짧은 길의 바로 앞 정점이다. 배열 하나에 모든 정점까지의 최단 경로가 담기며, 이것을 최단 경로 트리라고 한다. 갈 수 없는 정점도 prev가 -1이니 먼저 dist[goal]이 INF인지 확인한다.

벨만-포드: 음수 간선이 있을 때

지나가면 돈을 받는 길처럼 가중치가 음수이면, 나중에 음수 간선을 타고 돌아와 더 짧아질 수 있어 다익스트라의 전제가 깨진다. 벨만-포드 알고리즘은 순서를 따지지 않고 모든 간선을 한 바퀴씩 완화하는 일을 V−1번 되풀이한다.

V−1번이면 충분한 이유

음수 사이클이 없다면 최단 경로는 같은 정점을 두 번 지나지 않으므로 간선이 많아야 V−1개다. 그리고 모든 간선을 k바퀴 완화하면, 간선 k개 이하인 최단 경로는 모두 맞게 구해진다. 첫 바퀴에 경로의 첫 간선이, 둘째 바퀴에 둘째 간선이 완화되듯 한 바퀴마다 한 칸씩 확실해지기 때문이다.

돌 때마다 비용이 줄어드는 고리를 음수 사이클이라고 한다. 거기에 닿을 수 있으면 고리를 돌수록 거리가 한없이 줄어 최단 거리가 없다. 음수 사이클이 없으면 V−1바퀴 뒤에는 줄어들 것이 없다. 그러니 V번째 바퀴에서도 줄어드는 간선이 있으면 음수 사이클이 있다.


def bellman_ford(n: int, edges: list[tuple[int, int, int]]) -> str:
    INF = float('inf')
    dist = [INF] * n
    dist[0] = 0                          # 0 번에서 출발
    for round_no in range(1, n):         # 많아야 n-1 바퀴
        updated = False
        for u, v, w in edges:
            if dist[u] == INF:           # 못 간 정점에서는 완화하지 않는다
                continue
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                updated = True
        print(f'{round_no}바퀴: {dist}')
        if not updated:                  # 한 바퀴 내내 변화가 없으면 끝
            break
    for u, v, w in edges:                # 한 바퀴 더: 줄어들면 음수 사이클
        if dist[u] != INF and dist[u] + w < dist[v]:
            return '음수 사이클이 있다'
    return f'결과: {dist}'


# 그림 14-4. 간선 순서를 일부러 나쁘게 두었다.
edges = [(3, 4, 1), (1, 3, 2), (2, 1, -4), (0, 2, 3), (0, 1, 1), (2, 3, 6)]
print(bellman_ford(5, edges))
# 1 → 2 → 1 을 한 번 돌 때마다 비용이 2 씩 준다
print(bellman_ford(4, [(0, 1, 1), (1, 2, -1), (2, 1, -1), (2, 3, 2)]))

첫 그래프의 최단 경로 0→2→1→3→4는 간선이 4개라, 바퀴마다 한 칸씩 맞춰져 정확히 4바퀴(V−1)째에 4번이 2가 된다. 둘째 그래프는 V−1바퀴 뒤에도 줄어드는 간선이 남아 음수 사이클로 판정된다. 음수 간선만으로는 괜찮고, 닿을 수 있는 음수 사이클이 있을 때만 답이 없다.

if dist[u] == INF: continue는 정수 INF를 쓸 때 꼭 필요하다(자주 하는 실수). 시간은 O(VE)다. 간선 E개를 훑는 바퀴를 많아야 V번 돈다.

플로이드-워셜: 모든 쌍을 한 번에

모든 쌍의 최단 거리가 필요하면 플로이드-워셜 알고리즘이 가장 짧게 짜인다. 2차원 표 dist[i][j]에 처음에는 대각선에 0, 간선이 있는 칸에 가중치, 나머지에 INF를 넣는다.


INF = float('inf')
n = 4
edges = [(0, 1, 10), (0, 3, 1), (3, 2, 1), (2, 1, 1), (1, 2, 4)]

dist = [[INF] * n for _ in range(n)]     # 행마다 새 리스트 (3장)
for i in range(n):
    dist[i][i] = 0
for u, v, w in edges:
    dist[u][v] = min(dist[u][v], w)      # 같은 쌍의 간선이 여럿이면 가장 싼 것

for k in range(n):                       # k: 거쳐 가도 되는 정점. 가장 바깥
    for i in range(n):
        for j in range(n):
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]

for row in dist:
    print(*('INF' if d == INF else d for d in row))

INF 0 4 INF
INF 1 0 INF
INF 2 1 0

i행 j열이 i에서 j까지의 최단 거리다. 1에서 0이나 3으로 가는 길은 없어 INF로 남았다.

k가 가장 바깥에 있는 이유

바깥 k 반복이 한 번 끝날 때마다 표의 뜻이 넓어진다. k번 반복이 끝나면 dist[i][j]는 "0번부터 k번까지의 정점만 거쳐 갈 때"의 최단 거리가 된다.

k번 정점을 새로 허락하면, i에서 j로 가는 길은 k를 거치지 않거나(지금 값), k를 한 번 거친다(dist[i][k] + dist[k][j]). 이때 i→k와 k→j는 이미 "k−1번까지만 거치는 최단"으로 표에 완성되어 있다. 그러니 둘 중 작은 값을 고르면 된다. 위 예에서는 k=2일 때 3→2→1이 2로 생기고, 마지막 k=3일 때 그 앞에 0→3을 붙여 0→1이 10에서 3으로 준다. k를 안쪽에 두면 이 순서가 깨진다.

얼마나 큰 V까지 버티나

시간은 O(V³)(세 겹 반복이 각각 V번), 공간은 O(V²)(표 하나)다. 이 노트를 쓴 환경(Python 3.13)에서 재 보니 V = 100이면 0.1초, 200이면 0.6초, 400이면 5초쯤 걸렸다(dist[i], dist[k]를 지역 변수에 담으면 3초쯤). 200 안팎까지가 편하다.

어떤 것을 고를까

알고리즘쓰는 조건시간전형적인 크기
BFS (13장)가중치가 모두 같다O(V+E)V, E가 100만 안팎
다익스트라출발점 하나, 음수 없음O((V+E) log V)V, E가 10만~수십만
벨만-포드출발점 하나, 음수 있음, 음수 사이클 판정O(VE)V×E가 수백만 이하
플로이드-워셜모든 쌍 (음수 간선 있어도 됨)O(V³)V가 200 안팎 이하

모든 쌍이 필요해도 V가 크고 음수가 없으면, 정점마다 다익스트라를 한 번씩 돌리는 편이 빠를 수 있다.

INF는 무엇으로 둘까

무한대는 float('inf')나 math.inf(7장, 둘은 같은 값)가 가장 안전하다. 어떤 정수보다 크고, 더하거나 빼도 무한대로 남는다. 다만 print([0, 3, INF])는 [0, 3, inf]를 찍으니, 출력할 때 'INF' if d == INF else d처럼 형식에 맞춰 바꾼다. 정수 INF(10**9, 10**18)를 쓴다면 두 가지를 지킨다. 나올 수 있는 가장 긴 거리(가중치 최댓값 × (V−1))보다 크게 잡고, INF인 정점에서는 완화하지 않는다.

음수 간선에 다익스트라 쓰기

에러 없이 답만 틀린다. 확정한 정점을 done 배열로 막는 흔한 꼴은, 음수 간선 때문에 나중에 줄어든 거리를 뒤쪽 정점에 퍼뜨리지 못한다.


import heapq

# 그림 14-4 의 그래프: 2 → 1 이 -4
edges = [(0, 1, 1), (0, 2, 3), (2, 1, -4), (1, 3, 2), (3, 4, 1), (2, 3, 6)]
graph = [[] for _ in range(5)]
for u, v, w in edges:
    graph[u].append((v, w))

dist = [float('inf')] * 5
dist[0] = 0
done = [False] * 5
heap = [(0, 0)]
while heap:
    d, u = heapq.heappop(heap)
    if done[u]:
        continue
    done[u] = True                       # 한 번 확정하면 다시 보지 않는다
    for v, w in graph[u]:
        if d + w < dist[v]:
            dist[v] = d + w
            heapq.heappush(heap, (d + w, v))
print(dist)                              # 정답은 [0, -1, 3, 1, 2]

[0, -1, 3, 3, 4]

1번이 거리 1로 먼저 확정되어 3번을 3으로 만들었다. 뒤에 2→1(−4)로 1번이 −1이 되었지만 다시 꺼내지 않아 3번과 4번이 틀린 채 남았다.

오래된 힙 항목을 건너뛰지 않기

빠뜨려도 답은 맞아서 예제로는 못 잡는다. stale_entries.py처럼 같은 간선을 여러 번 훑어 큰 입력에서 시간 초과가 난다.

플로이드-워셜에서 k를 안쪽에 두기

for i / for j / for k 순서로 쓰면 i→j를 계산할 때 필요한 i→k, k→j가 아직 완성되지 않았을 수 있다. 에러 없이 일부 칸만 틀린다.


INF = float('inf')
n = 4
dist = [[0 if i == j else INF for j in range(n)] for i in range(n)]
for u, v, w in [(0, 1, 10), (0, 3, 1), (3, 2, 1), (2, 1, 1), (1, 2, 4)]:
    dist[u][v] = w

for i in range(n):
    for j in range(n):
        for k in range(n):               # k 가 가장 안쪽: 틀린 순서
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
print(dist[0])                           # 정답은 [0, 3, 2, 1]

[0, 10, 2, 1]

dist[0][1]을 계산할 때 dist[3][1](실제로는 2)이 아직 INF라 0→3→2→1을 못 찾았다. 순서는 언제나 k, i, j다.

방향 그래프에 간선을 양쪽으로 넣기

13장의 무방향 그래프 코드를 그대로 가져와 graph[v].append((u, w))까지 쓰면, 없는 역방향 길이 생겨 거리가 실제보다 짧게 나온다. 문제가 "u에서 v로 가는"이라고 했는지, "u와 v를 잇는"이라고 했는지 먼저 확인한다.

정수 INF에서 완화하기

INF를 10**9로 두고 갈 수 없는 정점에서도 완화하면, 음수 간선을 더한 값이 INF보다 작아져 갈 수 없는 정점이 갈 수 있는 정점처럼 보인다. if dist[u] == INF: continue로 막는다.


INF = 10**9
dist = [0, INF, INF]
for u, v, w in [(1, 2, -3)]:             # 1 번에는 아직 못 갔다
    if dist[u] + w < dist[v]:            # 10**9 - 3 < 10**9 라서 참
        dist[v] = dist[u] + w
print(dist)

[0, 1000000000, 999999997]

대표 문제

Problem보통다익스트라

한 정점에서 모든 정점까지

정점 V개(1번부터 V번)와 간선 E개로 이루어진 방향 그래프가 있다. 간선 u v w는 u에서 v로 가는 비용이 w라는 뜻이고, w는 양의 정수다. 같은 두 정점 사이에 간선이 여러 개 있을 수 있다. 시작 정점 S에서 1번부터 V번까지 각 정점으로 가는 최소 비용을 한 줄에 하나씩 출력하라. 갈 수 없으면 INF를 출력한다.

첫째 줄에 V와 E(1 ≤ V ≤ 20,000, 0 ≤ E ≤ 200,000), 둘째 줄에 S가 주어진다. 다음 E줄에 u v w(1 ≤ w ≤ 10)가 주어진다.

접근 방법먼저 생각해 보고 펼치세요

출발점이 하나이고 가중치가 모두 양수다. 출발점 하나 + 음수 없음이면 다익스트라다.

  1. 가중치가 서로 다르니 BFS는 아니다. 예시 1의 4번처럼 간선 수가 적은 길이 더 비쌀 수 있다.
  2. 음수가 없으니 벨만-포드는 필요 없다. V × E가 40억이라 시간 안에 끝나지도 않는다.
  3. 방향 그래프이므로 graph[u]에만 넣는다. 같은 쌍의 간선이 여럿이어도 모두 넣으면 다익스트라가 싼 것을 고른다.
  4. 정점 번호가 1부터이므로 리스트를 V+1칸으로 만든다. 끝나고 INF로 남은 정점은 문자열 INF로 바꿔 출력한다.
풀이 코드 

import heapq
import sys

input = sys.stdin.readline
INF = float('inf')

v_count, e_count = map(int, input().split())
start = int(input())
graph = [[] for _ in range(v_count + 1)]   # 정점 번호가 1부터라 한 칸 더
for _ in range(e_count):
    u, v, w = map(int, input().split())
    graph[u].append((v, w))                # 방향 그래프: u → v 만

dist = [INF] * (v_count + 1)
dist[start] = 0
heap = [(0, start)]
while heap:
    d, u = heapq.heappop(heap)
    if d > dist[u]:                        # 오래된 항목
        continue
    for v, w in graph[u]:
        if d + w < dist[v]:
            dist[v] = d + w
            heapq.heappush(heap, (d + w, v))

lines = ['INF' if dist[i] == INF else str(dist[i])
         for i in range(1, v_count + 1)]
print('\n'.join(lines))                    # 한 번에 모아 출력한다 (1장)

복잡도
시간
O((V+E) log V) 정점마다 한 번 확정하며 이웃을 훑고, 완화에 성공할 때마다 힙에 O(log V)로 넣는다.
공간
O(V+E) 인접 리스트에 간선 E개, dist에 V칸, 힙에는 많아야 E개가 들어간다.

입력이 더 커지면 입력 읽기와 힙에 쌓이는 튜플 수에서 먼저 막힌다.

스스로 확인

가중치가 1과 10뿐인 그래프에서 BFS로 최소 비용을 구하면 왜 틀릴 수 있는가?

BFS는 간선 수가 적은 순서로 거리를 정한다. 10짜리 간선 하나로 가는 길(비용 10)을 1짜리 간선 세 개로 가는 길(비용 3)보다 먼저 확정해 버린다. 가중치가 다르면 다익스트라를 쓴다.

다익스트라에서 if d > dist[u]: continue를 지우면 답이 틀리는가?

틀리지 않는다. 오래된 거리로 완화해 봐야 이미 더 짧은 값이 있어 바뀌는 것이 없다. 하지만 같은 정점의 이웃을 여러 번 다시 훑으므로 간선이 많으면 시간 초과가 난다.

벨만-포드가 모든 간선을 V−1번 완화하면 충분한 이유와, V번째에도 값이 줄면 무엇을 뜻하는가?

음수 사이클이 없으면 최단 경로의 간선은 많아야 V−1개이고, 한 바퀴마다 경로의 한 칸씩이 확실해진다. 그런데도 V번째에 줄어든다면 돌수록 짧아지는 음수 사이클이 있다는 뜻이다.

플로이드-워셜에서 바깥 k 반복이 한 번 끝날 때마다 dist[i][j]는 무엇을 뜻하는가?

"0번부터 k번까지의 정점만 거쳐 갈 때의 최단 거리"다. k를 새로 허락할 때 i→k와 k→j가 이미 앞 단계의 답으로 완성되어 있어야 하므로 k가 가장 바깥에 온다.

정리

  1. 가중치가 모두 같으면 BFS, 음수 간선이 없으면 다익스트라, 음수 간선이 있으면 벨만-포드, 모든 쌍이 필요하고 정점이 적으면 플로이드-워셜을 쓴다.
  2. 세 알고리즘은 모두 완화(더 짧은 길을 찾으면 거리를 고치는 일)를 되풀이하고, 어떤 순서로 몇 번 완화하느냐만 다르다.
  3. 다익스트라는 확정 안 된 정점 중 가장 가까운 정점은 더 짧아질 수 없다는 사실(음수가 없으니까)에 기댄다. heapq에 (거리, 정점)을 넣고 O((V+E) log V)다.
  4. if d > dist[u]: continue로 오래된 힙 항목을 건너뛴다. 빠뜨려도 답은 맞지만 느려진다.
  5. 완화할 때 prev[v] = u를 적어 두면, 도착점부터 거꾸로 따라가 뒤집어 경로를 복원한다.
  6. 벨만-포드는 모든 간선을 V−1번 완화한다. V번째 바퀴에서도 줄어드는 간선이 있으면 음수 사이클이다. 시간은 O(VE)다.
  7. 플로이드-워셜은 k, i, j 순서로 돈다. k번 반복 뒤 표는 "k번까지의 정점만 거쳐 가는 최단 거리"다. O(V³)이라 파이썬에서는 V가 200 안팎까지가 편하다.
