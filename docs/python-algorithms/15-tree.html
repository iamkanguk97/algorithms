트리

폴더 구조, 회사 조직도, 토너먼트 대진표처럼 위에서 아래로 갈라져 내려가는 데이터를 다룹니다. 트리는 그래프의 특별한 경우라서 13장의 탐색을 그대로 쓰되, 부모와 자식이라는 방향이 하나 더 생깁니다.

루트 · 리프깊이 · 높이이진 트리전위 · 중위 · 후위레벨 순회

이 장에서 배울 것

  • 트리가 어떤 그래프인지, 왜 간선이 n−1개인지 설명할 수 있다
  • 간선 목록으로 주어진 트리에서 부모와 깊이를 구할 수 있다
  • 포화·완전·균형 이진 트리를 구분하고, 완전 이진 트리의 높이가 log n인 이유를 안다
  • 전위·중위·후위·레벨 순회를 재귀와 스택으로 짤 수 있다
  • 서브트리 크기, 높이, 리프 수를 "자식의 답으로 내 답 만들기"로 구할 수 있다

트리란

핵심

트리는 사이클이 없고 모두 이어진 그래프다. 그래서 어느 두 정점 사이든 길이 딱 하나다.

트리(tree)는 13장의 그래프 중 모두 이어져 있고 사이클이 없는 것이다. 트리의 정점은 보통 노드(node)라고 부른다.

컴퓨터의 폴더를 떠올리면 쉽다. 어떤 파일이든 맨 위 폴더에서 가는 경로는 하나뿐이다. 경로가 둘이면 한 길로 갔다가 다른 길로 돌아올 수 있고, 그것이 곧 사이클이다.

노드가 n개면 간선은 n−1개

맨 위 노드 하나를 루트(root)로 정한다. 루트가 아닌 노드는 루트 쪽으로 올라가는 간선을 딱 하나 가진다. 둘이면 루트까지 가는 길이 둘이 되기 때문이다. 그래서 간선은 n−1개다. 거꾸로 간선이 n−1개이고 모두 이어져 있으면 트리다.


def is_tree(n: int, edges: list[tuple[int, int]]) -> bool:
    if len(edges) != n - 1:                 # 간선 수부터 본다
        return False
    graph = [[] for _ in range(n + 1)]
    for u, v in edges:
        graph[u].append(v)
        graph[v].append(u)

    seen = {1}
    stack = [1]                             # 스택 DFS(13장)로 1에서 닿는 곳을 센다
    while stack:
        for v in graph[stack.pop()]:
            if v not in seen:
                seen.add(v)
                stack.append(v)
    return len(seen) == n                   # 모두 이어져 있어야 한다


print(is_tree(4, [(1, 2), (2, 3), (2, 4)]))
print(is_tree(4, [(1, 2), (2, 3), (3, 1)]))   # 사이클이 있고 4는 떨어져 있다
print(is_tree(4, [(1, 2), (3, 4)]))           # 간선이 모자란다

트리를 코드로

일반 트리: 인접 리스트와 한 번의 탐색

자식 수에 제한이 없는 일반 트리는 13장의 인접 리스트에 담는다. 입력은 대개 "노드 수 n, 이어서 간선 n−1줄"이다. 어느 쪽이 부모인지 모르므로 양쪽에 넣고, 루트에서 한 번 탐색하며 부모와 깊이를 채운다.


import sys
from collections import deque

input = sys.stdin.readline

n = int(input())
tree = [[] for _ in range(n + 1)]          # 정점이 1번부터라 n+1 칸
for _ in range(n - 1):
    a, b = map(int, input().split())
    tree[a].append(b)
    tree[b].append(a)

root = 1
parent = [0] * (n + 1)
depth = [0] * (n + 1)
parent[root] = -1                           # 루트는 부모가 없다
order = []
queue = deque([root])
while queue:
    u = queue.popleft()
    order.append(u)
    for v in tree[u]:
        if v == parent[u]:                  # 부모로는 돌아가지 않는다
            continue
        parent[v] = u
        depth[v] = depth[u] + 1
        queue.append(v)

print('parent', parent[1:])
print('depth ', depth[1:])
print('order ', order)

이진 트리: Node 클래스

자식이 많아야 둘이고 왼쪽과 오른쪽을 구분하는 트리를 이진 트리(binary tree)라고 한다. 노드마다 두 칸을 따로 두는 클래스로 표현한다.


class Node:
    def __init__(self, val: str, left=None, right=None) -> None:
        self.val = val
        self.left = left                    # 왼쪽 자식 (없으면 None)
        self.right = right                  # 오른쪽 자식 (없으면 None)


#        A
#      B   C
#     D E    F
root = Node('A',
            Node('B', Node('D'), Node('E')),
            Node('C', None, Node('F')))

print(root.val, root.left.val, root.right.val)
print(root.left.left.val, root.right.left, root.right.right.val)

이진 트리의 종류

이진 트리는 모양에 따라 이름이 붙는다.

  • 포화 이진 트리(perfect) — 모든 층이 꽉 찼다. 리프가 모두 같은 깊이에 있다.
  • 완전 이진 트리(complete) — 마지막 층만 빼고 꽉 찼고, 마지막 층은 왼쪽부터 빈틈없이 채운다. 17장의 힙이 이 모양이다.
  • 균형 이진 트리(balanced) — 모든 노드에서 왼쪽과 오른쪽 서브트리의 높이 차가 1 이하다. 16장의 AVL 트리가 이 약속을 지킨다.

용어는 책마다 다르다. full binary tree를 "포화"로 옮기기도, "자식이 0개 또는 2개인 트리"로 쓰기도 한다. 정의를 확인한다.

노드 수와 높이

높이 h인 포화 이진 트리는 층마다 노드가 두 배로 늘어 1 + 2 + … + 2h = 2h+1 − 1개다. 높이 h인 완전 이진 트리는 2h ≤ n ≤ 2h+1 − 1이고, log₂를 씌우면 h = ⌊log₂n⌋이다(⌊ ⌋는 내림).


print([2 ** (h + 1) - 1 for h in range(5)])    # 높이 0~4 포화 트리의 노드 수

for n in [7, 8, 1000, 1_000_000]:
    print(n, n.bit_length() - 1)            # 완전 이진 트리의 높이 ⌊log₂ n⌋

전위·중위·후위 순회

순회(traversal)는 모든 노드를 한 번씩 방문하는 일이다. 재귀 순회는 왼쪽 서브트리 돌기, 오른쪽 서브트리 돌기, 지금 노드 방문하기를 한다. 왼쪽은 언제나 오른쪽보다 먼저이므로 루트를 언제 방문하느냐가 순회의 이름을 정한다.

이름순서그림 15-3 결과어디에 쓰나
전위(preorder)루트 → 왼쪽 → 오른쪽A B D E C F폴더 목록 출력, 트리 복사
중위(inorder)왼쪽 → 루트 → 오른쪽D B E A C F이진 탐색 트리를 정렬 순서로 읽기(16장)
후위(postorder)왼쪽 → 오른쪽 → 루트D E B F C A자식 결과로 부모 계산(폴더 용량)
 

class Node:                                 # 2절의 Node 를 줄여 쓴다
    def __init__(self, val: str, left=None, right=None) -> None:
        self.val, self.left, self.right = val, left, right


def preorder(node: Node | None, out: list[str]) -> None:
    if node is None:
        return
    out.append(node.val)                    # 루트를 먼저
    preorder(node.left, out)
    preorder(node.right, out)


def inorder(node: Node | None, out: list[str]) -> None:
    if node is None:
        return
    inorder(node.left, out)
    out.append(node.val)                    # 루트를 가운데
    inorder(node.right, out)


def postorder(node: Node | None, out: list[str]) -> None:
    if node is None:
        return
    postorder(node.left, out)
    postorder(node.right, out)
    out.append(node.val)                    # 루트를 마지막에


root = Node('A', Node('B', Node('D'), Node('E')), Node('C', None, Node('F')))
for name, visit in [('전위', preorder), ('중위', inorder), ('후위', postorder)]:
    result = []
    visit(root, result)
    print(name, ' '.join(result))

중위 D B E A C F
후위 D E B F C A

세 함수는 out.append 한 줄의 위치만 다르다. 노드마다 한 번씩 방문하니 O(n)이고, 호출 스택은 높이만큼인 O(h)다. [node.val] + left + right처럼 이어 붙여 반환하면 매번 복사해 치우친 트리에서 O(n²)이 된다.

레벨 순회와 재귀 없는 순회

레벨 순회: 층마다 한 줄씩

레벨 순회(level-order)는 깊이 순으로, 같은 깊이에서는 왼쪽부터 방문한다. 13장의 BFS 그대로다. 층을 나누려면 한 층을 시작할 때 큐에 든 노드 수만큼만 꺼낸다.


from collections import deque


class Node:
    def __init__(self, val: str, left=None, right=None) -> None:
        self.val, self.left, self.right = val, left, right


def level_order(root: Node) -> list[list[str]]:
    levels = []
    queue = deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):          # 지금 큐에 든 것이 정확히 한 층
            node = queue.popleft()
            level.append(node.val)
            for child in (node.left, node.right):
                if child is not None:
                    queue.append(child)
        levels.append(level)
    return levels


root = Node('A', Node('B', Node('D'), Node('E')), Node('C', None, Node('F')))
for depth, level in enumerate(level_order(root)):
    print(depth, ' '.join(level))

1 B C
2 D E F

range(len(queue))는 한 번만 계산되어, 중간에 자식이 들어와도 이번 층의 개수는 그대로다.

스택으로 전위 순회

트리가 깊으면 재귀 한도(6장)가 걱정이다. 호출 스택을 리스트로 직접 만들면 한도에 걸리지 않는다. 스택은 나중에 넣은 것이 먼저 나오므로 오른쪽 자식을 먼저 넣어야 왼쪽이 먼저 나온다.


class Node:
    def __init__(self, val: str, left=None, right=None) -> None:
        self.val, self.left, self.right = val, left, right


def preorder_iter(root: Node) -> list[str]:
    result = []
    stack = [root]
    while stack:
        node = stack.pop()
        result.append(node.val)
        if node.right is not None:          # 오른쪽을 먼저 넣는다
            stack.append(node.right)
        if node.left is not None:
            stack.append(node.left)
    return result


root = Node('A', Node('B', Node('D'), Node('E')), Node('C', None, Node('F')))
print(' '.join(preorder_iter(root)))

A B D E C F

두 if의 순서를 바꾸면 에러 없이 A C F B E D가 나온다. 후위 순회는 왼쪽을 먼저 넣어 "루트 → 오른쪽 → 왼쪽"으로 모은 뒤 뒤집으면 된다.

재귀로 트리의 값 구하기

서브트리의 크기, 높이, 리프 수는 모두 같은 틀로 구한다. 자식의 답을 받아 내 답을 만든다. 6장의 "작은 호출은 정답을 준다고 믿기"와 같다.

  • 크기 = 1 + 자식들의 크기의 합
  • 높이 = 자식이 없으면 0, 있으면 1 + 자식들의 높이 중 최댓값
  • 리프 수 = 자식이 없으면 1, 있으면 자식들의 리프 수의 합

import sys

sys.setrecursionlimit(10**6)                # 사슬 모양이면 깊이가 n 까지 간다

n = 9
edges = [(1, 2), (1, 3), (1, 4), (2, 5), (2, 6), (4, 7), (4, 8), (6, 9)]
tree = [[] for _ in range(n + 1)]
for a, b in edges:
    tree[a].append(b)
    tree[b].append(a)

size = [0] * (n + 1)
height = [0] * (n + 1)
leaves = [0] * (n + 1)


def dfs(u: int, par: int) -> None:
    size[u] = 1
    for v in tree[u]:
        if v == par:
            continue
        dfs(v, u)                           # 자식의 답을 먼저 구한다
        size[u] += size[v]
        height[u] = max(height[u], height[v] + 1)
        leaves[u] += leaves[v]
    if leaves[u] == 0:                      # 자식이 없으면 나 자신이 리프
        leaves[u] = 1


dfs(1, 0)                                   # 루트의 부모는 없는 번호 0
print('size  ', size[1:])
print('height', height[1:])
print('leaves', leaves[1:])

size   [9, 4, 1, 3, 1, 2, 1, 1, 1]
height [3, 2, 0, 1, 0, 1, 0, 0, 0]
leaves [5, 2, 1, 2, 1, 1, 1, 1, 1]

내 답을 만드는 줄이 모두 dfs(v, u) 다음에 있어 후위 순회와 같은 모양이고, 전체 O(n)이다. 이진 트리라면 답을 반환값으로 올린다. 높이는 max(height(left), height(right)) + 1이고, None에서 −1을 돌려주면 리프의 높이가 0이 된다.

재귀 없이: BFS 순서를 거꾸로

BFS 방문 순서에서는 부모가 언제나 자식보다 앞에 있다. 그러니 거꾸로 훑으며 자식의 답을 부모에게 더하면 재귀 없이 같은 값이 나온다.


from collections import deque


def subtree_sizes(n: int, edges: list[tuple[int, int]],
                  root: int) -> list[int]:
    tree = [[] for _ in range(n + 1)]
    for a, b in edges:
        tree[a].append(b)
        tree[b].append(a)

    parent = [0] * (n + 1)
    parent[root] = -1
    order = []
    queue = deque([root])
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in tree[u]:
            if v != parent[u]:
                parent[v] = u
                queue.append(v)

    size = [1] * (n + 1)
    for u in reversed(order):               # 깊은 노드부터: 자식이 먼저 끝난다
        if parent[u] > 0:
            size[parent[u]] += size[u]
    return size


edges = [(1, 2), (1, 3), (1, 4), (2, 5), (2, 6), (4, 7), (4, 8), (6, 9)]
print(subtree_sizes(9, edges, 1)[1:])               # 재귀 버전과 같다
print(subtree_sizes(100_000, [(i, i + 1) for i in range(1, 100_000)], 1)[1])

부모로 되돌아가 무한 재귀

무방향 인접 리스트에는 부모도 이웃으로 들어 있다. 부모를 건너뛰지 않으면 자식과 부모가 서로를 끝없이 부른다. 부모를 인자로 넘기거나 visited를 쓴다.


tree = {1: [2, 3], 2: [1, 4], 3: [1], 4: [2]}     # 간선 1-2, 1-3, 2-4


def count_wrong(u: int) -> int:
    return 1 + sum(count_wrong(v) for v in tree[u])   # 부모로도 내려간다


def count_right(u: int, par: int) -> int:
    return 1 + sum(count_right(v, u) for v in tree[u] if v != par)


try:
    print(count_wrong(1))
except RecursionError as e:
    print(f'{type(e).__name__}: {e}')
print(count_right(1, 0))

4
사슬 모양 트리에서 RecursionError

노드 10만 개가 한 줄로 이어지면 재귀 깊이도 10만이라 기본 한도 1000(6장)에 걸려 RecursionError가 난다. sys.setrecursionlimit(10**6)을 넣거나 6절의 BFS 역순 방식을 쓴다.

순회 이름 헷갈리기

왼쪽이 언제나 오른쪽보다 먼저라는 것만 기억하고, 이름은 루트의 위치로 읽는다. 앞이면 전위, 가운데면 중위, 뒤면 후위다.

높이를 간선으로 셀지 노드로 셀지

이 책은 높이를 간선 수로 세서 노드 하나짜리 트리의 높이가 0이다. 노드 수로 세는 문제도 많아 답이 1씩 어긋난다. 예시로 정의를 맞추고, 빈 트리를 −1로 둘지 0으로 둘지 정한다.

간선의 앞쪽을 부모로 단정하기

입력이 a b 꼴의 간선이면, 문제가 밝히지 않는 한 어느 쪽이 부모인지 정해져 있지 않다. parent[b] = a로 바로 적으면 2절 입력의 3 1에서 루트 1에 부모가 생긴다. 양쪽에 넣고 루트에서 탐색한다.

이름으로 자식을 찾아가야 하니 노드 이름을 키로, (왼쪽, 오른쪽)을 값으로 하는 딕셔너리가 곧 트리다. 그다음은 4절의 세 순회 그대로다.

  1. 줄의 순서가 섞여 있으므로 읽는 대로 딕셔너리에 담는다. 루트는 A로 정해져 있다.
  2. 빈 자리는 '.'로 들어오니 기저 조건을 "노드가 '.'이면 돌아간다"로 쓴다.
  3. 세 순회는 방문 줄의 위치만 다르다. 순서를 인자로 받는 함수 하나로 묶어 세 번 부른다.
  4. 노드가 많아야 26개라 재귀 한도는 걱정하지 않는다.
풀이 코드 

import sys

input = sys.stdin.readline

EMPTY = '.'


def traverse(node: str, order: str,
             children: dict[str, tuple[str, str]],
             out: list[str]) -> None:
    if node == EMPTY:                        # 빈 자리면 돌아간다
        return
    left, right = children[node]
    if order == 'pre':
        out.append(node)
    traverse(left, order, children, out)
    if order == 'in':
        out.append(node)
    traverse(right, order, children, out)
    if order == 'post':
        out.append(node)


n = int(input())
children = {}
for _ in range(n):
    node, left, right = input().split()
    children[node] = (left, right)

for order in ('pre', 'in', 'post'):
    out = []
    traverse('A', order, children, out)
    print(''.join(out))

스스로 확인

노드가 n개이고 간선이 n−1개인 그래프는 언제나 트리인가?

아니다. 모두 이어져 있어야 트리다. 간선이 n−1개인데 사이클이 있으면 어딘가 떨어진 노드가 생긴다. 간선 수를 센 뒤 한 번 탐색해 모든 노드에 닿는지 본다.

루트 A에 왼쪽 자식 B, 오른쪽 자식 C만 있는 트리의 전위·중위·후위 순회 결과는? 이름은 무엇을 기준으로 붙었나?

전위 A B C, 중위 B A C, 후위 B C A다. 이름은 루트를 앞·가운데·뒤 중 어디서 방문하느냐로 붙는다.

스택으로 전위 순회할 때 오른쪽 자식을 왼쪽 자식보다 먼저 넣는 이유는?

스택은 나중에 넣은 것이 먼저 나온다. 왼쪽을 먼저 꺼내려면 오른쪽을 먼저 넣어야 한다. 반대로 넣으면 에러 없이 오른쪽부터 방문한다.

서브트리 크기를 구하는 재귀는 세 순회 중 어느 것과 모양이 같은가? BFS 순서를 거꾸로 훑어도 되는 이유는?

후위 순회다. 자식의 답이 모두 나와야 내 답을 만들 수 있어 내 계산이 자식 호출 뒤에 온다. BFS 순서에서는 부모가 자식보다 앞이니, 거꾸로 훑으면 자식이 언제나 먼저 끝난다.

정리

  1. 트리는 사이클이 없고 모두 이어진 그래프다. 어느 두 노드 사이든 길이 딱 하나이고, 노드가 n개면 간선은 n−1개다.
  2. 루트를 정하면 부모·자식·리프·깊이·높이·서브트리가 정해진다. 이 책은 깊이와 높이를 간선 수로 센다.
  3. 일반 트리는 인접 리스트에 양방향으로 담고, 루트에서 한 번 탐색해 부모와 깊이를 채운다.
  4. 완전 이진 트리의 높이는 ⌊log₂n⌋이다. 노드 100만 개도 높이가 19다.
  5. 전위·중위·후위는 루트를 언제 방문하느냐로 이름이 정해진다. 레벨 순회는 BFS다.
  6. 스택으로 전위 순회할 때는 오른쪽 자식을 먼저 넣어야 왼쪽이 먼저 나온다.
  7. 서브트리 값은 자식의 답을 받아 내 답을 만든다. 재귀가 걱정되면 BFS 순서를 거꾸로 훑는다.
