문자열 다루기

문자열은 글자를 순서대로 늘어놓은 값이고, 한 번 만들면 바꿀 수 없습니다. 이 성질 하나로 메서드가 왜 새 문자열을 돌려주는지, 반복문에서 왜 +=를 피하는지가 모두 설명됩니다.

str불변split · joinf-stringord · chr

이 장에서 배울 것

  • 문자열이 불변이라는 것이 코드에서 무엇을 뜻하는지 설명할 수 있다
  • split, join, strip, find 같은 메서드를 골라 쓸 수 있다
  • 문자열을 뒤집고, 반복문에서 효율적으로 이어 붙이는 법을 안다
  • f-string 포맷 지정자로 소수점 자리, 폭, 정렬을 맞춰 출력할 수 있다
  • ord와 chr로 글자를 숫자로 바꿔 계산할 수 있다

문자열은 바꿀 수 없는 시퀀스

핵심

문자열은 한 번 만들면 내용을 바꿀 수 없는 글자의 나열이다. 바꾸는 것처럼 보이는 연산은 모두 새 문자열을 만든다.

문자열(str)은 작은따옴표로 감싸도, 큰따옴표로 감싸도 같다. 따옴표 세 개(""" 또는 ''')로 감싸면 여러 줄을 그대로 담는다.

역슬래시(\)로 시작하는 이스케이프 문자는 키보드로 바로 쓰기 어려운 글자를 나타낸다. \n은 줄바꿈, \t는 탭이다. 두 글자처럼 보여도 실제로는 글자 하나다.


single = '파이썬'
double = "it's ok"       # 작은따옴표가 들어 있어 큰따옴표로 감쌌다
multi = """첫째 줄
둘째 줄"""

print(single, double)
print(multi)
print('이름\t점수')
print(len('a\nb'))       # \n 은 글자 하나로 센다

인덱싱과 슬라이싱은 리스트와 같다

문자열도 리스트처럼 시퀀스(값이 순서대로 늘어선 묶음)다. 그래서 3장에서 배운 인덱싱과 슬라이싱이 그대로 통한다. s[0]은 첫 글자, s[-1]은 마지막 글자, s[1:4]는 1번부터 4번 바로 앞까지다.

바꾸려 하면 에러가 난다

리스트와 다른 점이 하나 있다. 문자열은 불변(immutable, 만든 뒤에는 내용을 바꿀 수 없음)이다. 인덱스로 글자 하나를 바꾸려고 하면 TypeError가 난다.


s = 'hello'
print(s[0], s[-1], s[1:4])

try:
    s[0] = 'H'
except TypeError as e:
    print(f'{type(e).__name__}: {e}')

t = 'H' + s[1:]          # 바꾸고 싶으면 새 문자열을 만든다
print(s, t)
print('ell' in s, 'xyz' in s)

h o ell
TypeError: 'str' object does not support item assignment
hello Hello
True False

마지막 줄의 in은 리스트에서는 "이 원소가 있는가"를 묻지만, 문자열에서는 "이 부분 문자열(문자열 안에 연속으로 들어 있는 조각)이 있는가"를 묻는다. 그래서 'ell'처럼 여러 글자도 한 번에 찾는다.

바뀌지 않는 값은 여러 곳에서 마음 놓고 함께 쓸 수 있다. 문자열을 딕셔너리의 키로 쓸 수 있는 것도 이 덕분이다(4장). 대신 고친 문자열이 필요할 때마다 새로 만드는 비용이 따른다.

자주 쓰는 메서드

문자열 메서드는 모두 원래 문자열을 그대로 두고 결과를 새로 돌려준다. 그러니 결과를 쓰려면 반드시 변수에 받아야 한다.

나누고 합치기: split과 join

split은 문자열을 잘라 리스트로 만들고, join은 리스트를 이어 문자열로 만든다. 서로 반대 방향의 짝이다. '-'.join(words)는 "'-'로 words를 잇는다"라고 읽는다.


line = '  apple, banana ,cherry  '
print(line.strip())
print(line.split(','))
print([w.strip() for w in line.split(',')])

words = 'to be  or not'.split()   # 공백 여러 개도 한 번에 자른다
print(words)
print('-'.join(words))
print(''.join(['a', 'b', 'c']))

['  apple', ' banana ', 'cherry  ']
['apple', 'banana', 'cherry']
['to', 'be', 'or', 'not']
to-be-or-not
abc

인자 없는 split()은 이어진 공백(스페이스, 탭, 줄바꿈)을 한 덩어리로 보고 자르며, 양 끝 공백도 버린다. 입력 한 줄을 나눌 때 input().split()을 쓰는 이유다. split(',')처럼 구분자를 주면 그 글자마다 정확히 자르므로, 조각에 붙은 공백은 strip으로 따로 지운다.

숫자 리스트를 join할 때

join에 넘기는 원소는 모두 문자열이어야 한다. ' '.join([3, 1, 4])는 TypeError를 낸다. 숫자 리스트는 ' '.join(map(str, nums))처럼 먼저 문자열로 바꾼다.

찾기: find, index, count, in

print(s.find('na'), s.find('x'))     # 처음 나온 위치, 없으면 -1
print(s.count('a'), s.count('ana'))  # 겹치는 것은 세지 않는다
print(s.startswith('ba'), s.endswith('na'))

try:
    s.index('x')                     # 없으면 에러를 낸다
except ValueError as e:
    print(f'{type(e).__name__}: {e}')

find와 index는 둘 다 처음 나온 위치를 돌려주고, 없을 때만 다르다. find는 -1을 돌려주고 index는 ValueError를 낸다. 있는지만 궁금하면 in이 가장 읽기 쉽다.

count('ana')가 1인 이유는 하나를 찾으면 그 뒤부터 다시 찾기 때문이다. 1번과 3번에서 시작하는 두 'ana'처럼 겹치는 경우는 한 번만 센다.

뒤집기와 이어 붙이기

뒤집기

문자열을 뒤집는 가장 짧은 방법은 슬라이싱 s[::-1]이다. 간격을 -1로 주면 끝에서부터 거꾸로 한 글자씩 읽는다. reversed(s)도 거꾸로 읽지만 문자열이 아니라 반복자(값을 차례로 하나씩 꺼내 주는 객체)를 돌려주므로, ''.join으로 다시 이어야 문자열이 된다.


s = 'stressed'
print(s[::-1])
print(''.join(reversed(s)))
print(s == s[::-1], 'level' == 'level'[::-1])

반복문에서 이어 붙이기

반복문에서 결과 문자열을 조금씩 키울 때 result += piece에는 비용이 숨어 있다. 문자열은 고칠 수 없으므로 +=는 뒤에 글자를 덧붙이지 못하고, 두 문자열을 합친 새 문자열을 만들며 기존 글자를 모두 복사한다.

한 번이면 문제없다. 그런데 글자를 하나씩 n번 덧붙이면 복사하는 글자 수가 1 + 2 + … + n으로 불어나, 최악에는 O(n²)이 된다. 그래서 조각은 리스트에 모아 두었다가 마지막에 join으로 한 번에 잇는다. 리스트의 append는 O(1)이고, join은 전체 길이를 먼저 계산한 뒤 한 번만 복사하므로 O(n)이다.


pieces = []
for i in range(1, 6):
    pieces.append(str(i * i))   # 조각은 리스트에 모은다

print(''.join(pieces))          # 마지막에 한 번만 잇는다
print(', '.join(pieces))

1491625
1, 4, 9, 16, 25
CPython의 최적화에 기대지 않는다

가장 널리 쓰는 구현인 CPython은 문자열을 가리키는 이름이 하나뿐일 때 s += t를 같은 자리에서 늘려 빠르게 처리하기도 한다. 하지만 언어가 약속한 동작이 아니라 조건이 조금만 달라져도 사라진다. 공식 스타일 가이드(PEP 8)도 여기에 기대지 말고 ''.join()을 쓰라고 권한다.

연산별 시간복잡도

n은 문자열의 길이다. 불변이라서, 새 문자열을 만드는 연산은 만들어지는 문자열의 길이만큼 시간이 든다.

슬라이싱도 글자를 복사한다는 점을 기억하자. 반복문 안에서 s[i:]처럼 긴 조각을 매번 잘라 내면 O(n)을 n번 해서 O(n²)이 된다. 인덱스만으로 풀 수 있다면 잘라 내지 않는다.

포맷팅으로 자릿수 맞추기

1장에서 f'{x}'로 값을 문자열 속에 넣는 법을 봤다. 중괄호 안에서 콜론(:) 뒤에 포맷 지정자(값을 어떤 모양으로 쓸지 정하는 짧은 규칙)를 붙이면 소수점 자리, 폭, 정렬까지 정할 수 있다.


pi = 3.14159
n = 42

print(f'{pi:.2f}')                     # 소수점 아래 2자리
print(f'[{n:>5}] [{n:<5}] [{n:^7}]')   # 폭을 정하고 정렬
print(f'{n:05d}')                      # 빈자리를 0으로 채운다
print(f'{1234567:,}')                  # 세 자리마다 쉼표
print(f'{n:b} {n:o} {n:x}')            # 2진수, 8진수, 16진수
print(f'{n=}, {pi * 2=:.1f}')          # 식과 값을 함께

f'{2.675:.2f}'는 2.68이 아니라 2.67이다. 2.675는 컴퓨터 안에서 2.67499…로 저장되기 때문이다(실수 오차는 2장). 포맷 지정자는 저장된 값을 정직하게 반올림할 뿐이다.

문자와 코드값

컴퓨터는 글자를 숫자로 저장한다. 파이썬 문자열은 유니코드(전 세계의 글자마다 번호를 하나씩 붙인 표준)를 따르고, 글자마다 붙은 번호를 코드 포인트라고 한다. ord는 글자를 번호로, chr는 번호를 글자로 바꾼다.


print(ord('a'), ord('A'), ord('0'), ord('가'))
print(chr(97), chr(44032))
print(ord('b') - ord('a'), ord('z') - ord('a'))

글자코드값기억할 점
'0' ~ '9'48 ~ 57숫자 글자는 숫자 값과 다르다. '0'은 48이다
'A' ~ 'Z'65 ~ 90대문자가 소문자보다 앞선다

알파벳은 a부터 z까지 번호가 빈틈없이 차례로 붙어 있다. 그래서 ord(c) - ord('a')를 하면 a는 0, z는 25가 되고, 번호 i는 chr(ord('a') + i)로 다시 글자가 된다. 글자를 리스트 인덱스로 바꾸는 이 계산은 코딩 테스트에 아주 자주 나온다.

글자 수 세기


word = 'banana'
counts = [0] * 26                  # a부터 z까지 26칸

for ch in word:
    counts[ord(ch) - ord('a')] += 1

for i, c in enumerate(counts):
    if c > 0:
        print(chr(ord('a') + i), c)

b 1
n 2

소문자만 나온다는 조건이 있으면 길이 26짜리 리스트로 세는 것이 간단하고, 결과도 a부터 차례로 나온다. 어떤 글자가 나올지 모를 때는 4장의 딕셔너리나 Counter로 센다.

글자 밀기

알파벳을 정해진 칸만큼 뒤로 미는 암호(시저 암호)도 코드값으로 계산한다.


def shift(text: str, k: int) -> str:
    result = []
    for ch in text:
        if 'a' <= ch <= 'z':
            idx = (ord(ch) - ord('a') + k) % 26   # z 다음은 a
            result.append(chr(ord('a') + idx))
        else:
            result.append(ch)        # 소문자가 아니면 그대로 둔다
    return ''.join(result)


print(shift('xyz abc', 3))
print(shift(shift('hello', 3), -3))

abc def
hello

핵심은 % 26이다. x(23)에 3을 더한 26을 26으로 나눈 나머지는 0이므로 a로 돌아온다. 파이썬의 %는 나누는 수가 양수면 음수를 돌려주지 않으므로(1장), -3만큼 되돌릴 때도 같은 식을 쓴다. 조건의 'a' <= ch <= 'z'는 바로 아래의 문자열 비교다.

문자열 비교는 사전 순서

문자열끼리 <, >로 비교하면 사전 순서를 따진다. 첫 글자부터 하나씩 코드값을 비교하다가, 처음으로 다른 글자가 나온 곳에서 크기가 정해진다. 끝까지 같은데 한쪽이 먼저 끝나면 짧은 쪽이 작다.


print('apple' < 'banana', 'app' < 'apple')
print('Z' < 'a')                  # 90 < 97
print('10' < '9')                 # 첫 글자 '1'(49) < '9'(57)
print(sorted(['banana', 'Cherry', 'apple']))
print(sorted(['banana', 'Cherry', 'apple'], key=str.lower))
print(sorted(['10', '9', '100'], key=int))

대문자는 모두 소문자보다 번호가 작아서 'Z' < 'a'가 참이고, 그냥 정렬하면 대문자로 시작하는 단어가 앞에 온다. 대소문자를 무시하려면 key=str.lower를 준다(정렬의 key는 3장). '10' < '9'가 참인 것도 첫 글자의 코드값만으로 정해지기 때문이다. 숫자 크기로 비교하려면 int로 바꾸거나 key=int를 준다.

앞에서 읽으나 뒤에서 읽으나 같은 문자열을 팰린드롬(회문)이라고 한다. 문자열 s에서 문자와 숫자만 남기고 대문자를 모두 소문자로 바꿨을 때 팰린드롬이면 True, 아니면 False를 돌려주는 함수 is_palindrome(s)를 작성하라.

"정리"와 "비교" 두 단계로 나누면 단계마다 이 장의 도구 하나로 끝난다.

  1. 정리: 글자를 하나씩 보며 isalnum()이 참인 것만 lower()로 바꿔 모은다. 조각은 리스트에 모아 join으로 한 번에 잇는다.
  2. 비교: 정리한 문자열이 그것을 뒤집은 cleaned[::-1]과 같은지 본다.

isalnum()은 유니코드 문자를 이해하므로 한글을 따로 처리하지 않아도 문자로 남는다.

풀이 코드 

def is_palindrome(s: str) -> bool:
    cleaned = ''.join([ch.lower() for ch in s if ch.isalnum()])
    return cleaned == cleaned[::-1]


print(is_palindrome('Top spot!'))
print(is_palindrome('Level 7'))
print(is_palindrome('다시 합창합시다'))
print(is_palindrome('?!'))

정리한 문자열을 따로 만들지 않고, 양 끝에서 가운데로 다가오며 한 쌍씩 비교할 수도 있다. 두 위치를 함께 움직이는 이 방식을 투 포인터라고 하며 21장에서 자세히 다룬다.


def is_palindrome(s: str) -> bool:
    left, right = 0, len(s) - 1
    while left < right:
        if not s[left].isalnum():      # 문자나 숫자가 아니면 건너뛴다
            left += 1
        elif not s[right].isalnum():
            right -= 1
        elif s[left].lower() != s[right].lower():
            return False
        else:
            left += 1
            right -= 1
    return True


print(is_palindrome('다시 합창합시다'), is_palindrome('Level 7'))

스스로 확인

s = 'abc'에서 s.upper()를 실행한 뒤 print(s)를 하면 무엇이 나오는가?

abc가 나온다. upper는 대문자로 바꾼 새 문자열을 돌려줄 뿐이다. 문자열은 불변이라 어떤 메서드도 원래 문자열을 바꿀 수 없다. s = s.upper()로 다시 받아야 한다.

' a b '.split(' ')의 결과는?

['', 'a', 'b', '']이다. 구분자를 주면 그 글자가 나올 때마다 정확히 자르므로, 맨 앞과 맨 뒤의 공백 바깥쪽에 빈 문자열이 생긴다. 인자 없는 split()이었다면 ['a', 'b']다.

소문자 c를 0~25 사이의 번호로 바꾸는 식과, 번호 i를 다시 소문자로 바꾸는 식은?

ord(c) - ord('a')와 chr(ord('a') + i)다. 소문자는 a(97)부터 z(122)까지 빈틈없이 차례로 번호가 붙어 있어서, a의 번호를 빼기만 하면 0부터 시작하는 순번이 된다.

반복문에서 result += piece 대신 리스트에 모았다가 join하는 이유는?

문자열은 불변이라 +=가 지금까지 쌓인 글자를 모두 복사한 새 문자열을 만들 수 있다. n번 반복하면 최악에 O(n²)이다. 리스트의 append는 O(1)이고, join은 마지막에 한 번만 O(n)으로 복사한다. CPython이 +=를 빠르게 처리할 때도 있지만 보장된 동작은 아니다.

정리

  1. 문자열은 불변이다. 바꾸는 것처럼 보이는 연산과 메서드는 모두 새 문자열을 돌려주므로 결과를 변수에 받아야 한다.
  2. 인덱싱과 슬라이싱은 리스트와 같다. 문자열의 in은 부분 문자열이 들어 있는지 검사한다.
  3. split()은 이어진 공백을 한 덩어리로, split(',')은 구분자 하나마다 자른다. join은 그 반대이며 원소가 모두 문자열이어야 한다.
  4. 찾는 것이 없을 때 find는 -1, index는 ValueError다. 있는지만 볼 때는 in을 쓴다.
  5. 뒤집기는 s[::-1]이다. 반복해서 이어 붙일 때는 조각을 리스트에 모아 ''.join으로 한 번에 잇는다.
  6. f-string 지정자로 소수점 자리(.2f), 폭과 정렬(>5), 0 채우기(05d), 쉼표(,)를 정한다.
  7. ord와 chr로 글자와 코드값을 오간다. 문자열 비교는 이 코드값을 앞에서부터 비교하는 사전 순서다.
