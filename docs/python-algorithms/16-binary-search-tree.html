이진 탐색 트리

"왼쪽은 작고 오른쪽은 크다"는 규칙 하나로 찾기, 넣기, 지우기가 모두 트리의 높이만큼만 걸리는 트리입니다. 넣는 순서가 나빠 한쪽으로 치우치면 왜 느려지는지, 그래서 균형 트리가 무엇을 보장하고 파이썬에서는 무엇으로 대신하는지까지 정리합니다.

왼쪽 < 루트 < 오른쪽찾기 · 넣기 · 지우기O(h)균형 트리bisect

이 장에서 배울 것

  • 이진 탐색 트리의 규칙을 말하고, 규칙을 어긴 트리를 가려낼 수 있다
  • 찾기와 넣기를 짜고, 재귀 넣기가 노드를 돌려주는 이유를 안다
  • 지우기의 세 경우를 구분하고, 자식이 둘일 때 후계자를 쓰는 이유를 설명할 수 있다
  • 중위 순회가 정렬된 순서인 이유를 알고, k번째로 작은 값을 구할 수 있다
  • 모든 연산이 O(h)인 이유와, AVL·레드-블랙 트리·B-트리가 무엇을 보장하는지 안다

이진 탐색 트리란

핵심

이진 탐색 트리는 모든 노드에서 왼쪽 서브트리의 값은 전부 그 노드보다 작고, 오른쪽 서브트리의 값은 전부 그 노드보다 크다.

이진 탐색 트리(binary search tree, BST)는 이진 트리(15장)에 규칙 하나를 더한 것이다. 규칙은 바로 밑의 자식 둘이 아니라 서브트리 전체에 걸린다. 그림 16-1에서 30은 50의 왼쪽에 있으니, 30 아래의 20과 40도 모두 50보다 작아야 한다.

그래서 부모와 자식만 비교하는 검사는 "할아버지보다 큰 손자"를 놓친다. 조상들이 정해 준 범위 (lo, hi)를 아래로 넘겨야 한다. 이 장의 Node는 15장과 같되, 만들 때 자식을 함께 넘길 수 있게 했다.


import math


class Node:
    def __init__(self, val: int, left: 'Node | None' = None,
                 right: 'Node | None' = None) -> None:
        self.val, self.left, self.right = val, left, right


def is_bst(node: Node | None,
           lo: float = -math.inf, hi: float = math.inf) -> bool:
    """모든 값이 조상들이 정해 준 범위 (lo, hi) 안에 있는지 확인한다."""
    if node is None:
        return True
    if not lo < node.val < hi:
        return False
    return (is_bst(node.left, lo, node.val)
            and is_bst(node.right, node.val, hi))


sample = Node(50, Node(30, Node(20), Node(40)), Node(70, Node(60), Node(80)))
hidden = Node(50, Node(30, None, Node(60)))    # 60 은 부모 30 보다는 크다
print(is_bst(sample), is_bst(hidden))

True False

hidden의 60은 50의 왼쪽 서브트리에 있으니 50보다 작아야 한다. 내려갈 때마다 범위가 좁혀져 60에 닿을 때의 범위는 (30, 50)이다.

이진 탐색과 같은 모양이 되는 이유

스무고개와 같다. "50보다 커?"에 답하면 후보의 한쪽이 통째로 사라진다. 이진 탐색(20장)이 가운데 값으로 절반을 버리듯, BST에서는 루트가 그 노릇을 한다. 다만 루트는 처음 넣은 값이라 "절반"이 보장되지 않는다(6절).

찾기

루트에서 출발해 찾는 값이 작으면 왼쪽으로, 크면 오른쪽으로 내려간다. 내려갈 자식이 없으면(None) 없는 값이다.


class Node:
    def __init__(self, val: int, left: 'Node | None' = None,
                 right: 'Node | None' = None) -> None:
        self.val, self.left, self.right = val, left, right


def search(root: Node | None, target: int) -> list[int]:
    """반복문 버전. 거쳐 간 값들을 돌려준다."""
    path = []
    node = root
    while node is not None:
        path.append(node.val)
        if target == node.val:
            break
        node = node.left if target < node.val else node.right
    return path


def contains(node: Node | None, target: int) -> bool:
    """재귀 버전."""
    if node is None:
        return False
    if target == node.val:
        return True
    if target < node.val:
        return contains(node.left, target)
    return contains(node.right, target)


root = Node(50, Node(30, Node(20), Node(40)), Node(70, Node(60), Node(80)))
print(search(root, 60), search(root, 45))
print([x for x in (20, 45, 60, 99) if contains(root, x)])

[50, 70, 60] [50, 30, 40]
[20, 60]

45는 40의 오른쪽이 비어 있어 멈춘다. 45가 있다면 바로 거기 있어야 하니 "없다"고 확신할 수 있다. 이렇게 비교 한 번마다 서브트리 하나를 통째로 버리고 한 층 내려간다. 층마다 비교가 한 번이니 찾기는 O(h)다(h는 높이). 재귀 버전은 깊이만큼 프레임이 쌓이므로(6장) 깊은 트리에는 반복문이 안전하다. 가장 작은 값은 왼쪽 끝까지 내려가면 나온다. 해시(12장)와 달리 순서 질문에도 O(h)로 답한다.

넣기

넣기는 찾기와 같은 길로 내려가 빈자리에 새 노드를 붙인다. 45의 자리는 40의 오른쪽이다. 즉 새 값은 언제나 리프 자리에 붙는다. 기존 관계를 바꾸지 않으니 규칙이 깨지지 않는다.


class Node:
    def __init__(self, val: int, left: 'Node | None' = None,
                 right: 'Node | None' = None) -> None:
        self.val, self.left, self.right = val, left, right


def insert(node: Node | None, val: int) -> Node:
    """재귀 버전. 넣은 뒤 이 서브트리의 루트를 돌려준다."""
    if node is None:
        return Node(val)                       # 빈자리의 새 주인
    if val < node.val:
        node.left = insert(node.left, val)
    elif val > node.val:
        node.right = insert(node.right, val)
    return node                                # 같은 값이면 무시한다


def insert_loop(root: Node | None, val: int) -> Node:
    """반복문 버전. 붙인 새 노드로 내려가면 val == node.val 이라 멈춘다."""
    if root is None:
        return Node(val)
    node = root
    while val != node.val:
        if val < node.val:
            if node.left is None:
                node.left = Node(val)
            node = node.left
        else:
            if node.right is None:
                node.right = Node(val)
            node = node.right
    return root


def inorder(node: Node | None) -> list[int]:
    if node is None:
        return []
    return inorder(node.left) + [node.val] + inorder(node.right)


a = b = None
for x in [50, 30, 70, 20, 40, 60, 80, 30]:     # 마지막 30 은 중복
    a = insert(a, x)
    b = insert_loop(b, x)
print(inorder(a) == inorder(b), inorder(a))

True [20, 30, 40, 50, 60, 70, 80]

빈자리에 닿은 호출이 받은 것은 None이라, 그 안에서 node = Node(val)이라고 써도 지역 이름만 바뀐다(6장의 스코프). 부모의 칸은 부모만 바꿀 수 있다. 그래서 재귀 넣기는 "이 자리의 새 주인"을 돌려주고, 부모가 그것을 자기 칸에 다시 건다. 빈 트리에서는 루트가 바뀌니 맨 바깥에서도 a = insert(a, x)로 받는다.

규칙에 "같다"는 없으니 중복 정책도 정한다. 이 책은 같은 값을 무시한다. 개수가 필요하면 노드에 count를 둔다.

지우기: 세 가지 경우

지울 노드까지 내려간 뒤에는 자식 수에 따라 나뉜다.

  1. 리프 — 부모의 칸을 None으로 만든다.
  2. 자식 하나 — 부모가 손자를 직접 가리키게 한다.
  3. 자식 둘 — 후계자(successor: 정렬 순서에서 바로 다음 값)의 값을 옮겨 오고, 원래 후계자 노드를 지운다.

오른쪽 서브트리의 최솟값은 왼쪽의 모든 값보다 크고 오른쪽에 남는 모든 값보다 작아서, 그 자리에 놓아도 규칙이 지켜진다. 또 후계자는 왼쪽 자식이 없어(있다면 그것이 더 작다) 경우 1이나 2로 끝난다. 즉 자식이 둘인 노드는 후계자의 값을 옮겨 오고, 후계자 노드를 대신 지운다.


class Node:
    def __init__(self, val: int, left: 'Node | None' = None,
                 right: 'Node | None' = None) -> None:
        self.val, self.left, self.right = val, left, right


def delete(node: Node | None, val: int) -> Node | None:
    """val 을 지운 뒤 이 서브트리의 루트를 돌려준다."""
    if node is None:
        return None                            # 없는 값
    if val < node.val:
        node.left = delete(node.left, val)
    elif val > node.val:
        node.right = delete(node.right, val)
    elif node.left is None:                    # 리프 또는 오른쪽 자식만
        return node.right
    elif node.right is None:                   # 왼쪽 자식만
        return node.left
    else:                                      # 자식 둘
        successor = node.right
        while successor.left is not None:
            successor = successor.left
        node.val = successor.val
        node.right = delete(node.right, successor.val)
    return node


def preorder(node: Node | None) -> list[int]:
    if node is None:
        return []
    return [node.val] + preorder(node.left) + preorder(node.right)


root = Node(50, Node(30, Node(20), Node(40)), Node(70, Node(60), Node(80)))
for target in [20, 30, 50, 99]:
    root = delete(root, target)
    print(target, preorder(root))

20 [50, 30, 40, 70, 60, 80]
30 [50, 40, 70, 60, 80]
50 [60, 40, 70, 80]
99 [60, 40, 70, 80]

리프에서는 node.right, 즉 None을 돌려줘 부모의 칸이 비워진다. 전위 순회(15장) 결과가 그림 16-3과 같다. 후계자까지 가도 루트에서 리프까지 한 번이라 O(h)다.

중위 순회는 정렬이다

중위 순회(15장)는 "왼쪽 서브트리 전부 → 나 → 오른쪽 서브트리 전부" 순서다. 나보다 작은 값이 모두 먼저, 큰 값이 모두 나중에 나오고, 서브트리 안에서도 마찬가지다. 그래서 중위 순회는 BST의 값을 오름차순으로 내놓는다. k번째로 방문하는 값이 k번째로 작은 값이다.


class Node:
    def __init__(self, val: int, left: 'Node | None' = None,
                 right: 'Node | None' = None) -> None:
        self.val, self.left, self.right = val, left, right


def kth_smallest(root: Node | None, k: int) -> int | None:
    """스택으로 중위 순회를 하다가 k 번째에서 멈춘다."""
    stack = []
    node = root
    while stack or node is not None:
        while node is not None:                # 왼쪽 끝까지 쌓는다
            stack.append(node)
            node = node.left
        node = stack.pop()
        k -= 1
        if k == 0:
            return node.val
        node = node.right
    return None                                # 노드가 k 개보다 적다


root = Node(41, Node(7, Node(3), Node(23, Node(12))),
            Node(88, Node(65, Node(59))))
print([kth_smallest(root, k) for k in range(1, 10)])

[3, 7, 12, 23, 41, 59, 65, 88, None]

스택 맨 위에는 언제나 "아직 방문하지 않은 값 중 가장 작은 값"이 있다. 왼쪽 끝까지 쌓으며 내려갔기 때문이다. 처음 내려가는 h와 k개 방문을 합쳐 O(h + k)다.

높이가 성능을 정한다

찾기·넣기·지우기는 모두 한 길로 내려가므로 시간은 높이 h가 정한다. 이 장에서 높이는 루트에서 가장 깊은 리프까지의 간선 수다. 그런데 1, 2, 3, 4, 5를 차례로 넣으면 새 값이 매번 오른쪽 끝에 붙어 사슬이 된다(그림 16-4). 높이 n − 1의 연결 리스트(9장)다. 즉 모든 연산은 O(h)이고, h는 넣는 순서에 따라 log n에서 n까지 변한다.

값 1000개로 재 보면, 정렬된 순서로 넣은 트리의 높이는 999, 고정한 씨앗으로 섞은 순서는 21이었다. 가장 고른 모양이면 ⌊log₂1000⌋ = 9다. 그런데 실제 입력은 정렬된 경우가 흔하다.

균형 트리: 높이를 log n에 묶어 두는 BST

균형 트리(self-balancing BST)는 넣거나 지울 때마다 모양을 고쳐 높이를 O(log n)으로 묶어 두는 BST다. 고칠 때는 회전(rotation: 부모와 자식의 위아래를 바꿔 쏠린 높이를 옮기는 일)을 쓴다. 중위 순서는 그대로라 규칙이 깨지지 않는다. 구현이 길어 직접 짜는 일은 드무니, 보장과 쓰임만 정리한다.

트리지키는 규칙보장하는 높이고치는 비용쓰이는 곳
AVL 트리 모든 노드에서 왼쪽과 오른쪽 서브트리의 높이 차가 1 이하 약 1.44·log₂n 미만. 셋 중 가장 낮다 넣기는 회전 한 번(꺾인 모양은 이중 회전). 지우기는 루트까지 여러 번 회전할 수 있다 찾기가 넣기·지우기보다 훨씬 잦은 곳
레드-블랙 트리 노드마다 빨강·검정을 칠한다. 빨강은 연달아 오지 않고, 어느 노드에서든 아래 빈자리까지 가는 모든 길에 검정 노드 수가 같다 2·log₂(n+1) 이하. 가장 긴 길이 가장 짧은 길의 2배 이하인 느슨한 균형 대부분 색만 바꾼다. 회전은 넣기 최대 2번, 지우기 최대 3번 C++ std::map·std::set(주요 구현), Java TreeMap·TreeSet, 충돌이 많이 쌓인 Java HashMap의 칸(12장), 리눅스 커널의 프로세스 스케줄러
B-트리 한 노드에 키 여러 개(수십~수백)를 정렬해 담고 자식도 그만큼 둔다. 모든 리프가 같은 깊이이고, 루트 말고는 노드가 절반 이상 차 있다 logmn 정도(m은 한 노드의 자식 수). m이 수백이면 높이 3~4로 수억 개를 담는다 노드가 넘치면 둘로 쪼개고, 모자라면 이웃에게 빌리거나 합친다 데이터베이스 인덱스(MySQL InnoDB, PostgreSQL의 기본 인덱스), 파일 시스템(NTFS, Btrfs 등). 실제로는 값을 리프에만 두는 변형인 B+트리가 많다

셋 모두 찾기·넣기·지우기가 최악에도 O(log n)이다. 레드-블랙 트리는 높이를 조금 양보해 고칠 일을 줄였기 때문에, 넣기·지우기가 섞이는 표준 라이브러리가 고른다. B-트리는 디스크용이다. 디스크 읽기는 메모리 비교보다 수만 배 이상 느려서, 블록 하나를 노드로 삼아 갈래를 늘리고 높이(= 읽는 횟수)를 낮춘다.

파이썬에서는

파이썬 표준 라이브러리에는 균형 트리가 없다. 그래서 파이썬에서는 정렬된 리스트와 bisect로 BST를 대신한다(7장·20장). 정렬된 리스트는 중위 순회 결과를 펼쳐 놓은 것이다.


from bisect import bisect_left, insort

scores = []
for x in [50, 30, 70, 20, 40, 60, 80]:
    insort(scores, x)                      # 정렬을 유지하며 넣는다
print(scores)

i = bisect_left(scores, 45)
print(scores[i])                           # 45 이상인 가장 작은 값
i = bisect_left(scores, 60)
print(i < len(scores) and scores[i] == 60)  # 60 이 있는가
print(scores[2])                           # 3번째로 작은 값
scores.pop(bisect_left(scores, 30))        # 30 지우기
print(scores)

재귀 넣기의 반환값을 버리기

insert(node.left, val)처럼 호출만 하고 node.left = 로 받지 않으면 새 노드가 바로 버려진다. 루트 50에 30, 70, 20을 넣어도 root.left와 root.right는 None이고, 에러도 없다.

자식 둘인 노드에서 후계자를 지우지 않기

값을 옮겨 온 뒤 node.right = delete(node.right, successor.val)를 빠뜨리면 같은 값이 둘 남는다. 그림 16-1의 트리에서 50을 지우면 중위 순회가 [20, 30, 40, 60, 60, 70, 80]이 된다.

중복 값 정책을 정하지 않기

넣기는 같은 값을 오른쪽에 넣는데 세기는 "같으면 멈춤"이면, 세 번 넣어도 1개라고 답한다. 정책 하나를 모든 연산에 똑같이 적용한다.

정렬된 입력에서 재귀 깊이 초과

1부터 차례로 재귀 넣기를 하면 사슬이 깊어져 1000번째 값 근처에서 RecursionError: maximum recursion depth exceeded가 난다(6장). 한도를 올리거나 반복문 넣기를 쓴다.

"BST니까 빠르다"고 믿기

정렬된 입력 10만 개를 직접 만든 BST에 넣으면 비교가 약 50억 번이다. 채점 데이터에는 정렬된 입력이 거의 꼭 있다. 순서 질문만 필요하면 정렬된 리스트와 bisect를 먼저 떠올린다.

접근 방법먼저 생각해 보고 펼치세요
  1. 전위 순회는 루트를 가장 먼저 방문한다. 첫 값이 루트다.
  2. 그 뒤로 왼쪽 서브트리 전부, 오른쪽 서브트리 전부가 나온다. 그래서 루트보다 큰 첫 값이 오른쪽의 시작이다.
  3. 먼저 떠오르는 방법은 분할점을 매번 훑어 찾고 양쪽을 재귀로 처리하는 것이다. 치우친 트리에서는 구간이 하나씩만 줄어 O(n²), 1만 개면 5천만 번 가까이 비교한다.
  4. 왼쪽 서브트리를 읽다 보면 루트보다 큰 값에서 저절로 멈춘다. 즉 범위를 벗어나는 첫 값이 곧 분할점이다. 범위 (lo, hi)를 넘기며 한 번만 읽는다.
  5. 후위 순회는 "왼쪽 → 오른쪽 → 루트"이므로 두 재귀 호출 뒤에 루트를 붙인다. 노드는 만들지 않는다.
풀이 코드 

import math
import sys

sys.setrecursionlimit(10**6)   # 치우친 트리면 재귀가 n 단계까지 깊어진다


def preorder_to_postorder(preorder: list[int]) -> list[int]:
    postorder = []
    index = 0                          # 다음에 읽을 전위 순회 위치

    def build(lo: float, hi: float) -> None:
        """값이 (lo, hi) 안인 동안 읽어서 서브트리 하나를 처리한다."""
        nonlocal index
        if index == len(preorder) or not lo < preorder[index] < hi:
            return                     # 끝났거나 이 서브트리 범위 밖
        root = preorder[index]
        index += 1
        build(lo, root)                # 왼쪽: root 보다 작은 값들
        build(root, hi)                # 오른쪽: root 보다 큰 값들
        postorder.append(root)         # 자식을 다 처리한 뒤에 루트

    build(-math.inf, math.inf)
    return postorder


# 줄 수가 없으니 끝까지 읽는다
values = [int(token) for token in sys.stdin.read().split()]
print('\n'.join(map(str, preorder_to_postorder(values))))

index는 모든 호출이 함께 쓰는 읽는 위치라 nonlocal이다(6장). build(lo, root)가 돌아오면 index는 오른쪽 서브트리의 첫 값을 가리킨다.

복잡도
시간
O(n) build는 값을 하나 읽거나 바로 돌아간다. 값을 읽은 호출만 자식 호출을 두 번 하므로 전체 호출은 2n + 1번이다.
공간
O(n) 결과 리스트에 n개를 담는다. 재귀 깊이는 트리 높이와 같아 치우치면 n까지 간다.

값이 수십만 개이고 사슬 모양이면 재귀 깊이가 먼저 막힌다. 그때는 같은 아이디어를 스택(10장)으로 옮긴다.

스스로 확인

모든 노드에서 "왼쪽 자식 < 부모 < 오른쪽 자식"이 성립하면 BST인가?

아니다. 규칙은 서브트리 전체에 걸린다. 50의 왼쪽 자식 30의 오른쪽에 60이 있으면 부모·자식 비교는 통과하지만 BST가 아니다. 조상이 정한 범위 (lo, hi)를 넘기며 검사한다.

재귀 insert가 노드를 돌려주고, 호출하는 쪽이 node.left = insert(node.left, val)로 받는 이유는?

빈자리에 닿은 호출은 None만 받아 부모의 칸을 바꿀 수 없다. 그래서 새 노드를 돌려주고 부모가 자기 칸에 건다. 빈 트리는 루트가 바뀌므로 바깥에서도 root = insert(root, x)로 받는다.

자식이 둘인 노드를 지울 때 오른쪽 서브트리의 최솟값을 쓰는 이유와, 그 노드를 지우는 일이 간단한 이유는?

그 값은 왼쪽의 모든 값보다 크고 오른쪽에 남는 모든 값보다 작아 규칙이 지켜진다. 최솟값 노드는 왼쪽 자식이 없어 리프나 자식 하나인 경우로 끝난다.

1부터 n까지 차례로 넣은 BST에서 찾기는 왜 O(n)인가? 균형 트리는 이것을 어떻게 막는가?

새 값이 매번 오른쪽 끝에 붙어 높이 n − 1인 사슬이 되고, 찾기는 O(h)이기 때문이다. AVL이나 레드-블랙 트리는 넣고 지울 때마다 중위 순서를 지키는 회전으로 모양을 고쳐 높이를 O(log n)으로 묶는다.

정리

  1. BST는 모든 노드에서 왼쪽 서브트리가 전부 작고 오른쪽 서브트리가 전부 크다. 검사할 때는 조상이 정한 범위를 넘긴다.
  2. 찾기는 비교 한 번마다 서브트리 하나를 통째로 버리고 한 층 내려간다.
  3. 새 값은 언제나 리프 자리에 붙는다. 재귀 넣기·지우기는 "이 자리의 새 주인"을 돌려주고 부모가 다시 건다.
  4. 자식이 둘인 노드는 후계자(오른쪽 최솟값)의 값을 옮겨 오고 후계자 노드를 대신 지운다.
  5. 중위 순회는 BST의 값을 오름차순으로 내놓는다. k번째에서 멈추면 k번째로 작은 값이다.
  6. 모든 연산은 O(h)이고, h는 넣는 순서에 따라 log n에서 n까지 변한다. 균형 트리는 높이를 O(log n)에 묶는다.
  7. 파이썬에는 내장 균형 트리가 없어 정렬된 리스트와 bisect로 대신한다. 최솟값만이면 heapq, 키로 찾기만이면 dict다.
