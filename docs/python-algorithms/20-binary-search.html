본문으로 건너뛰기

이진 탐색

정렬된 범위에서 가운데를 보고 절반을 버리는 일을 되풀이해, 100만 개 중 하나를 20번 남짓한 비교로 찾는 방법입니다. 이 장에서는 값 찾기에서 시작해 "답을 찾는 문제"를 "가능한지 묻는 문제"로 바꾸는 파라메트릭 서치까지 다룹니다.

정렬된 배열lower boundbisect파라메트릭 서치O(log n)

이 장에서 배울 것

  • 이진 탐색이 왜 O(log n)인지, 어떤 조건에서만 쓸 수 있는지 설명할 수 있다
  • while lo <= hi 꼴의 이진 탐색을 직접 짤 수 있다
  • lower bound와 upper bound를 구현하고 bisect와 대응시킬 수 있다
  • 최댓값·최솟값을 묻는 문제를 "x가 가능한가?" 판정으로 바꿔 풀 수 있다
  • lo, hi의 초기값과 반복 조건을 실수 없이 잡는 법을 안다

절반씩 줄여 찾기

핵심

답이 될 수 있는 범위가 정렬(단조)돼 있으면, 가운데 하나만 보고 절반을 통째로 버릴 수 있다. 그래서 O(log n)에 찾는다.

1부터 100 사이의 수를 맞히는 업다운 게임에서 50부터 부르는 것과 같은 원리다. "업"이라는 답 한 번으로 1~50이 모두 지워진다.

정렬된 리스트에서 값 x를 찾을 때도 같다. 찾는 범위의 왼쪽 끝을 lo, 오른쪽 끝을 hi, 가운데를 mid라고 하자. a[mid]가 x보다 작으면, 리스트가 정렬돼 있으니 mid와 그 왼쪽은 모두 x보다 작다. 볼 필요가 없으므로 lo를 mid + 1로 옮긴다. 크면 반대로 hi를 mid - 1로 옮긴다.

범위가 매번 절반이 되므로, n개가 1개로 줄어들 때까지의 횟수는 log₂ n번 정도다(로그는 2장). 직접 세어 보자.


def halving_count(n: int) -> int:
    """n개를 절반씩 버려 1개가 남을 때까지 몇 번 걸리는지."""
    count = 0
    while n > 1:
        n = (n + 1) // 2      # 홀수면 큰 쪽이 남는다고 본다
        count += 1
    return count


for n in (8, 1000, 1_000_000, 10**9):
    print(n, halving_count(n))

직접 구현하기

가장 기본형은 lo와 hi를 둘 다 포함하는 닫힌 구간 [lo, hi]로 보는 방식이다. 구간에 원소가 하나라도 남아 있는 동안(lo <= hi) 반복하고, 찾으면 위치를, 구간이 비면 -1을 돌려준다.


def binary_search(a: list[int], x: int) -> int:
    """정렬된 a에서 x의 위치를 돌려준다. 없으면 -1."""
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x:
            return mid
        if a[mid] < x:
            lo = mid + 1        # x 는 오른쪽 절반에 있다
        else:
            hi = mid - 1        # x 는 왼쪽 절반에 있다
    return -1


a = [3, 7, 11, 15, 19, 24, 30]
print(binary_search(a, 24))
print(binary_search(a, 3))
print(binary_search(a, 30))
print(binary_search(a, 20))

mid는 이미 확인했으므로 다음 구간에서 뺀다. 그래서 mid가 아니라 mid + 1, mid - 1로 옮긴다. 이 한 칸 덕분에 구간이 매번 반드시 줄어들고, 반복이 끝난다. 그림 20-1의 과정을 출력해 보면 이렇다.


def binary_search_trace(a: list[int], x: int) -> int:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        print(f'lo={lo} mid={mid} hi={hi}  a[mid]={a[mid]}')
        if a[mid] == x:
            return mid
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

def binary_search_count(a: list[int], x: int) -> tuple[int, int]:
    """(위치, 비교 횟수)를 돌려준다."""
    lo, hi = 0, len(a) - 1
    compares = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        compares += 1
        if a[mid] == x:
            return mid, compares
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, compares

mid 계산과 오버플로

C++이나 Java 책에서는 lo + (hi - lo) // 2로 쓰라고 한다. lo + hi가 정수 범위를 넘을 수 있어서다. 파이썬 정수는 크기 제한이 없어(2장) (lo + hi) // 2로 써도 된다.

lower bound와 upper bound

값이 여러 개 들어 있으면 "있는지"보다 "어디부터 어디까지인지"가 더 궁금하다. 이때 쓰는 두 가지 위치가 있다.

  • lower bound — x 이상인 값이 처음 나오는 위치
  • upper bound — x 초과인 값이 처음 나오는 위치

둘 다 "조건을 처음 만족하는 위치"를 찾는다. 답이 len(a)(모든 값이 조건을 만족하지 않음)일 수도 있으므로 hi를 len(a)로 잡고, 구간을 [lo, hi)처럼 오른쪽 끝을 빼는 반열린 구간으로 본다. lo == hi가 되면 후보가 하나로 좁혀진 것이라 멈춘다.


def lower_bound(a: list[int], x: int) -> int:
    """a[i] >= x 인 첫 i. 모두 x 보다 작으면 len(a)."""
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1        # mid 는 답이 아니다
        else:
            hi = mid            # mid 가 답일 수 있어 남겨 둔다
    return lo


def upper_bound(a: list[int], x: int) -> int:
    """a[i] > x 인 첫 i. 모두 x 이하면 len(a)."""
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo


a = [1, 3, 3, 3, 5, 8, 8, 10]
print(lower_bound(a, 3), upper_bound(a, 3))     # 3 이 차지한 구간 [1, 4)
print(upper_bound(a, 3) - lower_bound(a, 3))    # 3 의 개수
print(lower_bound(a, 4), upper_bound(a, 4))     # 없는 값이면 둘이 같다
print(lower_bound(a, 11), upper_bound(a, 0))    # 양 끝을 벗어난 값

3
4 4
8 0

두 함수는 비교 하나만 다르다. lower bound는 a[mid] < x일 때, upper bound는 a[mid] <= x일 때 오른쪽으로 간다. 그리고 upper bound − lower bound = x의 개수다. 정렬된 리스트에서 개수 세기를 O(log n)에 할 수 있다.

파라메트릭 서치

이진 탐색은 리스트 안의 값만 찾는 도구가 아니다. 답의 범위를 대상으로도 쓸 수 있다. "조건을 만족하는 최댓값(최솟값)을 구하라"는 문제를 "x로 하면 조건을 만족하는가?"라는 예/아니오 질문으로 바꾸고, 그 답이 바뀌는 경계를 이진 탐색으로 찾는다. 이것을 파라메트릭 서치(parametric search)라고 한다.

예를 들어 보자. 무게가 [7, 2, 5, 10, 8, 3, 6]인 짐을 순서대로 상자에 담는다. 상자 하나의 용량을 정하면, 짐을 앞에서부터 넣다가 넘치면 새 상자를 연다. 상자를 2개 이하로 쓰려면 용량이 최소 얼마여야 할까?

최솟값을 바로 계산하기는 어렵다. 하지만 "용량이 c일 때 2개로 되는가?"는 짐을 한 번 훑으면 O(n)에 알 수 있다. 용량 20부터 27까지 물어보자.


def boxes_needed(weights: list[int], capacity: int) -> int:
    """용량이 capacity 인 상자에 순서대로 담을 때 필요한 상자 수."""
    boxes, load = 1, 0
    for w in weights:
        if load + w > capacity:    # 안 들어가면 새 상자를 연다
            boxes += 1
            load = 0
        load += w
    return boxes


weights = [7, 2, 5, 10, 8, 3, 6]
for capacity in range(20, 28):
    print(capacity, boxes_needed(weights, capacity) <= 2)

용량이 커지면 상자 수는 줄면 줄었지 늘지 않는다. 그래서 판정 결과는 False … False True … True처럼 한 번만 바뀐다. 이렇게 한쪽 방향으로만 변하는 성질을 단조성이라고 한다. 단조이면 결과 줄 전체가 "정렬된 배열"과 같으므로, lower bound를 찾듯 첫 True를 이진 탐색으로 찾으면 된다.


def boxes_needed(weights: list[int], capacity: int) -> int:
    boxes, load = 1, 0
    for w in weights:
        if load + w > capacity:
            boxes += 1
            load = 0
        load += w
    return boxes


def min_capacity(weights: list[int], m: int) -> int:
    """상자 m 개 이하로 다 담을 수 있는 가장 작은 용량."""
    lo, hi = max(weights), sum(weights)       # 답이 있을 수 있는 범위
    while lo < hi:
        mid = (lo + hi) // 2
        if boxes_needed(weights, mid) <= m:   # True: 첫 True 는 mid 이거나 왼쪽
            hi = mid
        else:                                 # False: 첫 True 는 오른쪽
            lo = mid + 1
    return lo


weights = [7, 2, 5, 10, 8, 3, 6]
for m in (1, 2, 3, 7):
    print(m, min_capacity(weights, m))

1 41
2 24
3 17
7 10

판정 한 번이 O(n)이고 답의 범위 크기가 W라면 전체는 O(n log W)다. 용량을 1부터 하나씩 늘려 보는 O(n·W)와 비교하면, W가 10억일 때 판정 횟수가 10억 번에서 30번으로 준다.

범위와 조건 잡는 법

파라메트릭 서치에서 틀리는 곳은 대부분 세 군데다. 범위, 판정 함수, 반복 조건이다.

lo와 hi는 답이 반드시 그 안에 있게

lo는 답이 될 수 있는 가장 작은 값, hi는 가장 큰 값으로 잡는다. 앞 절에서 용량은 가장 무거운 짐보다 작을 수 없으니 lo = max(weights), 모두 한 상자에 넣는 sum(weights)면 반드시 되니 hi = sum(weights)다. 범위를 넉넉히 잡는 것은 괜찮다. 로그라서 범위를 두 배로 늘려도 반복은 한 번 늘 뿐이다. 반대로 답을 범위 밖에 두면 절대 찾지 못한다.

판정 함수가 단조인지 먼저 확인

코드를 짜기 전에 "x에서 되면 x보다 큰(작은) 값에서도 반드시 되는가?"를 한 문장으로 확인하는 습관을 들인다. 확인이 안 되면 파라메트릭 서치를 쓸 수 없다. 앞 절의 표처럼 작은 범위에서 판정 결과를 찍어 보면 빨리 확인된다.

두 가지 틀

닫힌 구간 + 답 기록반열린 구간
반복 조건while lo <= hiwhile lo < hi
이동lo = mid + 1, hi = mid - 1lo = mid + 1, hi = mid
답True일 때 answer = mid로 기록끝난 뒤의 lo

둘 다 맞는 방법이다. 한 문제 안에서 두 틀을 섞지만 않으면 된다.

정수 답과 실수 답

답이 실수라면 mid + 1처럼 한 칸 옮길 수 없다. 이때는 lo = mid, hi = mid로 옮기고, 조건 대신 횟수로 반복을 끝낸다. 100번 반으로 나누면 구간이 처음의 2¹⁰⁰분의 1이 되어 실수 오차보다 작아진다.


def sqrt_bisect(n: float) -> float:
    lo, hi = 0.0, max(1.0, n)      # 1보다 작은 n 의 제곱근은 n 보다 크다
    for _ in range(100):           # 횟수를 고정하면 끝나지 않을 걱정이 없다
        mid = (lo + hi) / 2
        if mid * mid < n:
            lo = mid
        else:
            hi = mid
    return lo


print(f'{sqrt_bisect(2):.6f}')
print(f'{sqrt_bisect(0.25):.6f}')

정렬하지 않은 리스트에 쓰기

정렬되지 않은 리스트에서는 에러 없이 틀린 답이 나온다. 그래서 더 찾기 어렵다. 입력이 정렬돼 있다는 말이 없으면 먼저 sort()한다(19장).


def binary_search(a: list[int], x: int) -> int:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x:
            return mid
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

print(binary_search(a, 23))           # 분명히 있는데 -1
print(binary_search(sorted(a), 23))   # 정렬한 리스트에서의 위치

단조가 아닌 판정에 적용하기

판정 결과가 True False True처럼 오락가락하면 이진 탐색은 경계 하나를 아무렇게나 골라 돌려준다. 예를 들어 "합이 정확히 S인가?"는 단조가 아니다. "합이 S 이상인가?"처럼 단조가 되도록 질문을 바꿀 수 있는지 먼저 본다.

대표 문제

Problem보통파라메트릭 서치

막대 자르기

길이가 제각각인 막대 K개가 있다. 이 막대들을 모두 같은 길이 L(양의 정수)로 잘라 토막을 N개 이상 만들려고 한다. 막대를 이어 붙일 수는 없고, L보다 짧게 남는 자투리는 버린다. 가능한 L 중 가장 큰 값을 출력하라. 길이 1로도 N개를 만들 수 없으면 0을 출력하라.

첫 줄에 K와 N이, 둘째 줄에 막대 길이 K개가 공백으로 주어진다. K는 1 이상 100,000 이하, N은 1 이상 10억 이하, 막대 길이는 1 이상 10억 이하의 정수다.

L이 짧을수록 토막이 많이 나온다. 그래서 "길이 L로 N개 이상 만들 수 있는가?"는 L이 커질수록 True에서 False로 한 번만 바뀐다. 마지막 True를 찾으면 된다.

  1. 판정 함수를 만든다. 길이 L일 때 토막 수는 sum(막대 // L)이다.
  2. 답의 범위를 잡는다. L은 1 이상이고, 가장 긴 막대보다 길면 그 막대에서도 토막이 안 나오므로 hi = max(막대)다.
  3. 닫힌 구간 틀로 탐색한다. 가능하면 answer = mid로 기록하고 더 긴 쪽(lo = mid + 1), 불가능하면 더 짧은 쪽(hi = mid - 1)을 본다.
  4. answer를 0으로 시작하면, 한 번도 가능하지 않은 경우 0이 그대로 출력된다.
풀이 코드 

import sys

input = sys.stdin.readline


def pieces(sticks: list[int], length: int) -> int:
    """길이 length 로 잘랐을 때 나오는 토막 수."""
    return sum(stick // length for stick in sticks)


k, n = map(int, input().split())
sticks = list(map(int, input().split()))

lo, hi = 1, max(sticks)
answer = 0
while lo <= hi:
    mid = (lo + hi) // 2
    if pieces(sticks, mid) >= n:      # 가능하다: 기록하고 더 긴 쪽을 본다
        answer = mid
        lo = mid + 1
    else:                             # 불가능하다: 더 짧은 쪽을 본다
        hi = mid - 1
print(answer)

lo를 0이 아니라 1에서 시작하는 것이 중요하다. mid가 0이 되면 stick // 0에서 ZeroDivisionError가 난다.

복잡도
시간
O(K log M) M은 가장 긴 막대의 길이다. 판정 한 번에 막대 K개를 훑고, 판정은 log₂ M ≈ 30번 한다.
공간
O(K) 막대 길이를 담는 리스트뿐이다.

스스로 확인

정렬된 원소 1,000개에서 이진 탐색으로 값을 찾을 때 비교는 최대 몇 번쯤인가?

약 10번이다. 2¹⁰ = 1024이므로 1,000개는 절반씩 10번 줄이면 1개가 된다. 순차 탐색은 최악에 1,000번이다.

bisect_right(a, x) - bisect_left(a, x)는 무엇을 뜻하는가?

정렬된 a에 들어 있는 x의 개수다. bisect_left는 x가 시작하는 위치, bisect_right는 x가 끝난 다음 위치라서 그 차가 x가 차지한 칸 수다. 없으면 둘이 같아 0이다.

파라메트릭 서치를 쓰기 전에 판정 함수에 대해 반드시 확인할 것은?

단조성이다. x에서 가능하면 x보다 큰(또는 작은) 모든 값에서도 가능해야 한다. 그래야 결과가 False … True …처럼 한 번만 바뀌고, 이진 탐색이 그 경계를 정확히 찾는다.

막대 자르기에서 lo를 0으로 시작하면 어떤 일이 생길 수 있는가?

탐색 중 mid가 0이 되면 stick // 0을 계산하다 ZeroDivisionError가 난다. 예를 들어 길이 1로도 N개가 안 되는 입력에서는 hi가 계속 줄어 lo = hi = 0까지 간다. 답의 범위는 실제로 가능한 값(1 이상)으로 잡는다.

정리

  1. 이진 탐색은 정렬(단조)된 범위에서 가운데를 보고 절반을 버린다. n개를 O(log n)번 만에 1개로 줄인다.
  2. 기본형은 lo, hi = 0, len(a) - 1, while lo <= hi, mid ± 1로 옮기기다. 확인한 mid는 다음 구간에서 뺀다.
  3. lower bound는 x 이상, upper bound는 x 초과가 처음 나오는 위치다. 둘의 차가 x의 개수다.
  4. 실전에서는 bisect_left, bisect_right를 쓴다. 값이 있는지는 돌려받은 위치의 값을 한 번 더 확인한다.
  5. 최댓값·최솟값 문제는 "x로 가능한가?" 판정으로 바꾸고, 판정이 단조이면 경계를 이진 탐색으로 찾는다(파라메트릭 서치).
  6. lo와 hi는 답이 반드시 안에 있게 잡고, 닫힌 구간과 반열린 구간 틀을 섞지 않는다. 실수 답은 횟수를 정해 반복한다.
