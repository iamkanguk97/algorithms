본문으로 건너뛰기

스택

접시를 쌓듯 맨 위에만 넣고 맨 위에서만 꺼내는 자료구조입니다. 파이썬에서는 리스트 하나로 바로 쓸 수 있고, 괄호 검사부터 재귀를 반복문으로 바꾸는 일까지 "가장 최근 것부터 처리하는" 문제에 두루 쓰입니다.

LIFOappend · pop괄호 검사호출 스택단조 스택

이 장에서 배울 것

  • 스택이 왜 "나중에 넣은 것을 먼저 꺼내는" 구조인지 설명할 수 있다
  • 파이썬 리스트로 push, pop, peek을 쓰고, 각 연산이 O(1)인 이유를 안다
  • 문제에서 스택을 떠올려야 하는 신호(짝 맞추기, 되돌리기, 중첩)를 안다
  • 호출 스택이 왜 스택인지 알고, 재귀 함수를 반복문과 스택으로 바꿀 수 있다
  • 단조 스택으로 "다음 큰 수"를 O(n)에 구할 수 있다

스택이란

핵심

스택은 마지막에 넣은 것이 가장 먼저 나오는 자료구조다. 이 성질을 LIFO(Last In, First Out)라고 부른다.

식당에서 접시를 쌓는 모습을 떠올리면 쉽다. 새 접시는 맨 위에 올리고, 꺼낼 때도 맨 위부터 집는다. 가운데 접시를 빼려면 그 위의 접시를 모두 먼저 치워야 한다. 이 제약이 불편해 보이지만, 거꾸로 말하면 "가장 최근 것"이 언제나 맨 위에 있다는 뜻이다. 스택이 유용한 이유는 전부 여기서 나온다.

그래서 스택이 하는 일은 사실상 세 가지뿐이다.

  • push — 맨 위에 넣는다
  • pop — 맨 위에서 꺼낸다
  • peek — 꺼내지 않고 맨 위만 본다

7장의 큐와 비교하면 차이가 분명하다. 큐는 먼저 넣은 것을 먼저 꺼내고(FIFO), 스택은 나중에 넣은 것을 먼저 꺼낸다. 넣는 순서는 같아도 꺼내는 순서가 반대다. 큐는 11장에서 다룬다.

파이썬 리스트로 스택 쓰기

파이썬에는 스택 전용 자료형이 따로 없다. 리스트의 끝을 스택의 맨 위로 삼으면 그대로 스택이 된다. append가 push, pop()이 pop, [-1]이 peek이다.


stack = []

stack.append(1)        # push
stack.append(2)
stack.append(3)
print(stack)

top = stack[-1]        # peek: 꺼내지 않고 맨 위만 본다
print(top)

print(stack.pop())     # pop: 맨 위를 꺼내서 돌려준다
print(stack)
print(not stack)       # 비었는가

빌 때까지 꺼내기

스택을 쓰는 코드는 대개 while stack:으로 시작한다. 비어 있지 않은 동안 하나씩 꺼내 처리하고, 처리하다 새로 생긴 일은 다시 쌓는다. 꺼낸 순서를 모아 보면 쌓은 순서의 정반대다. 이 "넣었다 빼면 뒤집힌다"는 성질은 뒤에서 여러 번 쓰인다.


stack = []
for ch in 'abc':
    stack.append(ch)       # a, b, c 순서로 쌓인다

popped = []
while stack:               # 빌 때까지 하나씩 꺼낸다
    popped.append(stack.pop())
print(popped)              # 꺼낸 순서는 쌓은 순서의 반대
print(''.join(popped))

cba

연산별 시간복잡도

스택 연산은 모두 리스트의 끝에서만 일어난다. 끝에서 넣고 빼면 다른 원소를 옮길 필요가 없어서, 원소가 몇 개든 거의 같은 시간이 걸린다. 리스트의 앞을 맨 위로 삼으면 안 되는 이유도 같다. 맨 앞에 넣거나 맨 앞에서 빼면 뒤의 원소를 모두 한 칸씩 밀거나 당겨야 해서 O(n)이 된다(7장).

표에서 눈여겨볼 곳은 x in stack이다. 스택 가운데를 뒤지는 일은 O(n)이고, 애초에 스택이 잘하는 일이 아니다. 풀이 도중 "스택 안에 이 값이 있나?"를 자주 묻게 된다면, 집합(4장)을 하나 더 두거나 스택이 맞는 도구인지 다시 생각해 본다.

스택이 어울리는 신호

문제를 읽다가 다음 세 가지 중 하나가 보이면 스택을 먼저 떠올린다. 셋 다 "가장 최근 것이 맨 위에 있다"는 성질을 쓴다.

  • 가장 최근 것과 짝을 맞춘다 — 닫는 괄호는 가장 최근에 연 괄호와 짝이다.
  • 되돌린다 — 실행 취소, 뒤로 가기. 가장 최근 상태로 돌아간다.
  • 중첩을 안에서 밖으로 처리한다 — 괄호 안의 괄호, 폴더 안의 폴더, 리스트 안의 리스트. 안쪽이 먼저 끝나야 바깥쪽이 끝난다.

짝 맞추기: 괄호 검사

괄호 ( ) [ ] { }로 된 문자열이 올바른지 판단해 보자. 닫는 괄호는 언제나 가장 최근에 열렸고 아직 닫히지 않은 괄호와 짝이 맞아야 한다. "가장 최근에 열린 것"은 스택의 맨 위다. 그러니 여는 괄호는 쌓고, 닫는 괄호를 만나면 맨 위를 꺼내 짝인지 본다.


def is_valid(s: str) -> bool:
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []

    for ch in s:
        if ch in pairs:                       # 닫는 괄호
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:                                 # 여는 괄호
            stack.append(ch)

    return not stack                          # 남은 괄호가 없어야 한다


print(is_valid('([]{})'))
print(is_valid('([)]'))
print(is_valid('(('))
print(is_valid(''))

True
False
False
True

실패하는 길은 두 가지다. 닫는 괄호를 만났는데 스택이 비어 있거나(열지 않고 닫음) 맨 위가 짝이 아니면 그 자리에서 False다. 끝까지 읽었는데 스택에 무언가 남아 있으면(열고 닫지 않음) 마지막 return not stack이 False를 돌려준다. 빈 문자열은 열지도 닫지도 않았으니 True다.

괄호가 ( ) 한 종류뿐이라면 스택 대신 "열린 개수"를 세는 변수 하나로 충분하다. 종류가 둘 이상이면 개수만으로는 ([)]를 걸러내지 못한다. 무엇을 열었는지, 그것도 어떤 순서로 열었는지 기억해야 하므로 스택이 필요해진다.

되돌리기: 뒤로 가기

브라우저의 뒤로 가기 버튼은 "바로 직전에 보던 페이지"로 돌아간다. 새 페이지로 갈 때 떠나는 페이지를 쌓아 두고, 뒤로 가기는 맨 위를 꺼내 그리로 간다. 두 번 누르면 그 전 페이지, 곧 가장 최근 것부터 차례로 되돌아간다.


back = []                  # 지나온 페이지. 맨 위가 바로 직전 페이지
page = 'home'

for action in ['news', 'sports', 'back', 'weather', 'back', 'back']:
    if action == 'back':
        if back:                       # 돌아갈 곳이 있을 때만
            page = back.pop()
    else:
        back.append(page)              # 떠나기 전 페이지를 기억한다
        page = action
    print(f'{action:8} -> {page}')

news     -> news
sports   -> sports
back     -> news
weather  -> weather
back     -> news
back     -> home

편집기의 실행 취소도 같은 구조다. 바뀌기 전 상태를 쌓아 두고 취소할 때마다 하나씩 꺼낸다. 세 번째 신호인 중첩은 다음 절에서 리스트 안의 리스트로 다룬다.

호출 스택과 재귀를 스택으로 바꾸기

6장에서 함수를 호출하면 프레임(지역 변수와 돌아갈 위치를 담은 기록)이 호출 스택에 쌓이고, 함수가 끝나면 맨 위 프레임이 빠진다고 했다. 그때 "스택처럼 동작한다"고 미뤄 둔 말을 이제 풀 수 있다. 호출은 push, 반환은 pop이다. 가장 늦게 불린 함수가 가장 먼저 끝난다는 점이 바로 LIFO이고, 그래서 이름이 호출 스택이다. 6장 그림 6-1의 factorial(3)이 f(1)부터 차례로 빠져나오는 모습은 그림 10-1의 pop과 같은 그림이다.

재귀는 이 호출 스택에 일을 맡기는 방식이다. 안쪽 문제를 먼저 풀고 돌아와 바깥 문제를 마무리하므로, "중첩을 안에서 밖으로 처리한다"는 세 번째 신호와 정확히 맞는다. 문제는 호출 스택의 높이에 한도가 있다는 것이다(6장). 중첩 리스트를 평평하게 펴는 재귀 함수로 확인해 보자.


def flatten(nested: list) -> list:
    result = []
    for item in nested:
        if isinstance(item, list):
            result.extend(flatten(item))   # 안쪽 리스트는 재귀로 편다
        else:
            result.append(item)
    return result


print(flatten([1, [2, [3, 4]], 5]))

deep = [1]
for k in range(2, 3001):
    deep = [deep, k]                       # 3000겹으로 싸인 리스트
try:
    print(len(flatten(deep)))
except RecursionError as e:
    print(f'{type(e).__name__}: {e}')

[1, 2, 3, 4, 5]
RecursionError: maximum recursion depth exceeded

리스트가 3000겹이면 프레임도 3000개가 쌓여야 하는데 기본 한도는 1000이다. 한도를 올릴 수도 있지만(6장), 호출 스택이 하던 일을 우리가 만든 리스트가 대신하게 하면 한도 자체가 사라진다. 리스트는 메모리가 허락하는 만큼 커질 수 있기 때문이다. 바꾸는 패턴은 재귀 함수의 모양과 상관없이 늘 같다.

  1. 처음 할 일을 스택에 넣는다.
  2. 스택이 빌 때까지 하나 꺼내 처리한다.
  3. 처리하다 생긴 새 일은 재귀로 부르는 대신 스택에 넣는다.

def flatten_iter(nested: list) -> list:
    result = []
    stack = list(reversed(nested))        # 할 일 더미. 왼쪽 원소가 맨 위에 오도록 거꾸로 넣는다
    while stack:
        item = stack.pop()                # 가장 최근에 쌓인 일부터
        if isinstance(item, list):
            stack.extend(reversed(item))  # 재귀 호출 대신 안쪽 원소들을 할 일로 쌓는다
        else:
            result.append(item)
    return result


print(flatten_iter([1, [2, [3, 4]], 5]))

deep = [1]
for k in range(2, 3001):
    deep = [deep, k]
flat = flatten_iter(deep)
print(len(flat), flat[:3], flat[-3:])

[1, 2, 3, 4, 5]
3000 [1, 2, 3] [2998, 2999, 3000]

재귀 버전에서 프레임이 기억하던 것, 곧 "어느 리스트의 어디까지 처리했는가"를 여기서는 아직 꺼내지 않은 원소들이 스택에 남아 있는 것으로 기억한다. 안쪽 리스트를 만나면 그 원소들을 쌓고 곧바로 그것부터 꺼내니, 안쪽을 먼저 끝내고 바깥으로 돌아오는 순서가 재귀와 같다.

reversed가 붙은 이유는 앞 절에서 본 "넣었다 빼면 뒤집힌다" 때문이다. 왼쪽 원소를 먼저 처리하려면 왼쪽 원소가 맨 위에 있어야 하므로 오른쪽부터 넣는다. 빼먹으면 순서가 거꾸로 나온다.


nested = [1, [2, 3], 4]

stack = list(nested)          # 거꾸로 넣지 않으면
result = []
while stack:
    item = stack.pop()
    if isinstance(item, list):
        stack.extend(item)
    else:
        result.append(item)
print(result)                 # 순서가 뒤집힌다

[4, 3, 2, 1]

순서가 상관없는 문제라면 reversed를 빼도 된다. 그래프를 깊이 우선으로 탐색하는 DFS도 "이웃을 재귀로 부르는 대신 스택에 넣는" 같은 패턴이며, 13장에서 그대로 쓴다.

후위 표기식 계산

우리가 쓰는 3 + 4는 연산자를 가운데 두는 중위 표기다. 연산자를 피연산자 뒤에 두는 후위 표기(postfix)로는 3 4 +라고 쓴다. 후위 표기에는 괄호가 없다. (3 + 4) * 2는 3 4 + 2 *, 3 + 4 * 2는 3 4 2 * +로, 연산자가 나오는 자리 자체가 계산 순서를 정하기 때문이다.

이런 식은 스택으로 왼쪽에서 오른쪽으로 한 번만 읽으면 계산된다. 규칙은 두 줄이다. 숫자는 쌓는다. 연산자를 만나면 둘을 꺼내 계산하고 결과를 다시 쌓는다. 연산자의 피연산자는 언제나 "가장 최근에 나온 두 값"이므로, 여기서도 가장 최근 것이 맨 위에 있다는 성질을 쓴다.


def eval_postfix(expr: str) -> int:
    stack = []
    for token in expr.split():
        if token.isdigit():
            stack.append(int(token))      # 숫자는 쌓는다
            continue
        b = stack.pop()                   # 나중에 쌓인 것이 오른쪽 피연산자
        a = stack.pop()
        if token == '+':
            stack.append(a + b)
        elif token == '-':
            stack.append(a - b)
        elif token == '*':
            stack.append(a * b)
        else:                             # '/'
            stack.append(a // b)
    return stack.pop()                    # 마지막에 하나만 남는다


print(eval_postfix('3 4 + 2 *'))          # (3 + 4) * 2
print(eval_postfix('3 4 2 * +'))          # 3 + 4 * 2
print(eval_postfix('10 3 -'))             # 10 - 3 이지 3 - 10 이 아니다
print(eval_postfix('7 2 /'))

14
11
7
3

꺼내는 순서에 주의한다. 먼저 꺼낸 값이 오른쪽 피연산자다. 10 3 -에서 먼저 나오는 것은 3이므로, 먼저 꺼낸 것을 a라고 부르면 3 - 10을 계산하게 된다. 덧셈과 곱셈은 순서를 바꿔도 결과가 같아서 이 실수가 뺄셈과 나눗셈에서만 드러난다.

식을 다 읽으면 스택에 정확히 하나가 남고, 그것이 답이다. 파이썬도 코드를 바이트코드로 바꾼 뒤 이런 스택 위에서 값을 쌓고 꺼내며 계산한다.

자주 하는 실수

빈 스택에서 꺼내거나 들여다보기

빈 리스트에 pop()을 하면 IndexError가 난다. stack[-1]도 마찬가지다. 꺼내기 전에 if stack:으로 확인하거나, 비어 있을 때 쓸 값을 조건식으로 정해 둔다. 괄호 검사의 if not stack or ...이 바로 이 확인이다.


stack = []
for op in ('pop', 'peek'):
    try:
        if op == 'pop':
            stack.pop()
        else:
            stack[-1]
    except IndexError as e:
        print(f'{type(e).__name__}: {e}')

top = stack[-1] if stack else None   # 안전한 peek
print(top)

IndexError: pop from empty list
IndexError: list index out of range
None
pop(0)으로 큐처럼 쓰기

pop(0)은 맨 앞을 꺼내므로 스택이 아니라 큐처럼 동작하고, 매번 뒤의 원소를 모두 당기느라 O(n)이 걸린다. 먼저 넣은 것을 먼저 꺼내야 한다면 collections.deque의 popleft()를 쓴다. 11장에서 다룬다.

문자열로 스택 흉내 내기

문자열은 바꿀 수 없는 값이라 "맨 뒤 한 글자 빼기"를 s = s[:-1]로 쓰게 되는데, 이 슬라이스는 나머지 글자를 전부 새 문자열로 복사하므로 pop 한 번이 O(n)이다. n번 꺼내면 O(n²)이 된다. s += ch가 빠르게 느껴지는 것은 CPython이 상황에 따라 제자리에서 늘려 주는 최적화 덕분일 뿐 언어가 보장하는 것은 아니다. 스택은 리스트로 만들고, 문자열이 필요하면 마지막에 ''.join(stack)으로 합친다.

peek 하려다 pop 하기

맨 위를 보기만 하려는 자리에 stack.pop()을 쓰면 원소가 사라진다. 흔한 모양이 if stack.pop() == x:처럼 조건식 안에서 꺼내 버리는 것이다. 조건이 거짓이어도 원소는 이미 없다. 보기만 할 때는 stack[-1], 꺼낼 때는 pop()으로 구분하고, 한 번 꺼낸 값을 다시 써야 하면 변수에 받아 둔다.

대표 문제

Problem보통스택단조 스택

다음 큰 수 찾기

정수 리스트 nums가 주어진다. 각 원소에 대해 그 원소보다 오른쪽에 있으면서 처음으로 나오는 더 큰 수를 구하라. 그런 수가 없으면 -1이다. 원소마다의 답을 같은 순서로 담은 리스트를 돌려주는 함수 next_greater(nums)를 작성하라.

  • 같은 수는 더 큰 수가 아니다.
  • nums의 길이는 1 이상 1,000,000 이하다.
입력출력이유
[2, 1, 3, 5, 4][3, 3, 5, -1, -1]2와 1의 오른쪽에서 처음 큰 수는 3, 3의 것은 5. 5와 4의 오른쪽엔 더 큰 수가 없다
[5, 4, 3, 2, 1][-1, -1, -1, -1, -1]계속 작아지므로 아무도 답이 없다
[1, 1, 2][2, 2, -1]첫 1의 답은 옆의 1이 아니라 2다
접근 방법먼저 생각해 보고 펼치세요

먼저 떠오르는 방법은 원소마다 오른쪽을 훑어 처음 큰 수를 찾는 것이다.


def next_greater_slow(nums: list[int]) -> list[int]:
    n = len(nums)
    answer = [-1] * n
    for i in range(n):
        for j in range(i + 1, n):        # 오른쪽을 하나씩 훑는다
            if nums[j] > nums[i]:
                answer[i] = nums[j]
                break
    return answer


print(next_greater_slow([2, 1, 3, 5, 4]))

[3, 3, 5, -1, -1]

내림차순 입력처럼 답이 없는 원소가 많으면 매번 끝까지 훑어 O(n²)이다. n이 100만이면 시간 안에 끝나지 않는다.

질문을 뒤집어 보자. "내 오른쪽의 큰 수는 누구인가"를 묻는 대신, 새 수 x를 읽는 순간 "x가 답이 되어 줄 왼쪽 원소는 누구인가"를 묻는다. 아직 답을 받지 못한 원소들을 스택에 쌓아 두면, x보다 작은 것들이 바로 그 원소들이다. 꺼내서 답을 x로 적어 주고, x도 자기 답을 기다리러 스택에 들어간다.

이때 스택 안의 값을 보면 위로 갈수록 작다. 큰 수가 들어올 때마다 그보다 작은 위쪽을 모두 꺼냈기 때문에, 남아 있는 것은 아래에서 위로 작아지는 수들뿐이다. 그래서 맨 위가 x보다 크거나 같으면 그 아래는 더 크니 더 볼 필요가 없다. 이렇게 크기 순서를 유지하는 스택을 단조 스택(monotonic stack)이라고 한다. 값 대신 인덱스를 쌓는 이유는 답을 answer[i]에 적을 자리가 필요해서다.


nums = [2, 1, 3, 5, 4]
answer = [-1] * len(nums)
stack = []                                # 아직 답을 못 찾은 인덱스들

for i, x in enumerate(nums):
    while stack and nums[stack[-1]] < x:  # 맨 위가 x 보다 작으면 그 답은 x
        answer[stack.pop()] = x
    stack.append(i)
    print(f'{x} 처리 후 스택의 값: {[nums[j] for j in stack]}')

print(answer)

2 처리 후 스택의 값: [2]
1 처리 후 스택의 값: [2, 1]
3 처리 후 스택의 값: [3]
5 처리 후 스택의 값: [5]
4 처리 후 스택의 값: [5, 4]
[3, 3, 5, -1, -1]

3이 들어올 때 2와 1이 한꺼번에 답을 받고 나가는 모습이 보인다. 안쪽에 while이 있어도 전체는 O(n)이다. 각 인덱스는 스택에 한 번 들어가고 많아야 한 번 나오므로, while이 도는 총 횟수는 모든 i를 합쳐도 n을 넘지 않는다. 끝까지 스택에 남은 인덱스는 오른쪽에 더 큰 수가 없었다는 뜻이니 -1 그대로 둔다.

풀이 코드 

def next_greater(nums: list[int]) -> list[int]:
    answer = [-1] * len(nums)
    stack = []                                # 답을 기다리는 인덱스. 값은 위로 갈수록 작다

    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:  # 맨 위가 x 보다 작으면 x 가 그 답
            answer[stack.pop()] = x
        stack.append(i)                       # x 도 자기 답을 기다린다

    return answer                             # 스택에 남은 인덱스는 -1 그대로


print(next_greater([2, 1, 3, 5, 4]))
print(next_greater([5, 4, 3, 2, 1]))
print(next_greater([1, 1, 2]))

[3, 3, 5, -1, -1]
[-1, -1, -1, -1, -1]
[2, 2, -1]

조건이 <라서 같은 수는 꺼내지 않는다. [1, 1, 2]에서 두 번째 1이 들어올 때 첫 1은 그대로 남았다가, 2가 들어올 때 둘이 함께 답을 받는다.

복잡도
시간
O(n) 원소를 한 번씩 읽고, 각 인덱스는 스택에 한 번 들어가고 많아야 한 번 나온다.
공간
O(n) 내림차순 입력이면 아무도 나가지 못해 n개가 모두 스택에 쌓인다.

스스로 확인

리스트로 스택을 만들 때, 리스트의 앞이 아니라 끝을 맨 위로 삼는 이유는?

끝에서 넣고 빼면 다른 원소를 옮기지 않아 O(1)이다. 앞을 맨 위로 삼으면 insert(0, x)와 pop(0)이 매번 나머지 원소를 모두 옮겨 O(n)이 된다.

flatten_iter에서 안쪽 리스트의 원소를 reversed로 거꾸로 쌓는 이유는?

스택은 나중에 넣은 것을 먼저 꺼내므로, 넣은 순서대로 쌓으면 오른쪽 원소가 먼저 나와 결과가 뒤집힌다. 왼쪽 원소를 먼저 처리하려면 왼쪽 원소가 맨 위에 와야 하니 오른쪽부터 넣는다.

next_greater에는 for 안에 while이 있는데 왜 O(n²)이 아니라 O(n)인가?

while이 한 번 돌 때마다 인덱스 하나가 스택에서 나간다. 각 인덱스는 한 번만 들어가므로 나가는 횟수도 전체를 합쳐 n을 넘지 못한다. 반복문이 겹쳐 있어도 일의 총량이 n에 비례하면 O(n)이다.

next_greater의 조건을 nums[stack[-1]] <= x로 바꾸면 [1, 1, 2]의 답은 어떻게 되는가?

[1, 2, -1]이 된다. 두 번째 1이 들어올 때 첫 1을 꺼내 답을 1로 적어 버리므로, 같은 수를 "더 큰 수"로 치는 셈이 된다. 문제가 "크거나 같은 수"를 묻는다면 이렇게 바꾸면 된다.

정리

  1. 스택은 마지막에 넣은 것을 먼저 꺼내는 LIFO 구조다. 가장 최근 것이 언제나 맨 위에 있다.
  2. 파이썬에서는 리스트의 끝을 맨 위로 삼아 append, pop(), [-1]로 쓴다. 셋 다 O(1)이고, pop(0)은 O(n)이니 앞에서 꺼내야 하면 deque를 쓴다.
  3. "가장 최근 것과 짝 맞추기", "되돌리기", "중첩을 안에서 밖으로"가 보이면 스택을 떠올린다. 괄호 검사가 대표다.
  4. 호출 스택은 호출이 push, 반환이 pop인 진짜 스택이다. 재귀가 깊어 한도에 걸리면, 재귀 호출 대신 할 일을 리스트에 쌓는 반복문으로 바꾼다. 순서가 중요하면 거꾸로 넣는다.
  5. 후위 표기식은 숫자는 쌓고 연산자는 둘 꺼내 계산하면 한 번에 계산된다. 먼저 꺼낸 값이 오른쪽 피연산자다.
  6. 단조 스택은 크기 순서를 유지하는 스택이다. 각 원소가 한 번 들어가고 한 번 나오므로 "다음 큰 수" 같은 문제를 O(n)에 푼다.
