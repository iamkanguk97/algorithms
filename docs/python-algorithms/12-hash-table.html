해시 테이블

4장에서 딕셔너리와 집합은 해시 덕분에 거의 한 번에 찾는다고 했습니다. 이 장은 그 "거의"의 속을 들여다봅니다. 키가 칸 번호가 되는 과정, 두 키가 같은 칸을 원할 때의 처리, 표가 찼을 때 파이썬이 하는 일을 작은 해시 테이블을 직접 만들며 확인합니다.

hash()버킷충돌적재율체이닝

이 장에서 배울 것

  • 키가 해시 함수를 거쳐 칸 번호가 되는 과정을 설명할 수 있다
  • 충돌이 왜 피할 수 없는지, 체이닝과 개방 주소법이 충돌을 어떻게 다루는지 안다
  • 적재율이 높아지면 왜 느려지고, 표를 늘리면 왜 평균 O(1)이 지켜지는지 안다
  • 체이닝 해시 테이블을 직접 만들어 넣기·찾기·지우기를 할 수 있다
  • __hash__와 __eq__의 약속을 알고, 1·1.0·True가 한 키인 이유를 설명할 수 있다

해시 테이블이란

핵심

해시 테이블은 키를 해시 함수에 넣어 칸 번호를 얻고, 그 칸에 값을 둔다. 찾을 때도 같은 계산을 하므로 어느 칸을 볼지 바로 안다.

딕셔너리와 집합(4장)의 바닥에 있는 구조가 해시 테이블(hash table)이다. 이 장은 4장이 미뤄 둔 두 질문, "평균"이라는 말이 왜 붙는지와 파이썬이 표를 늘려 충돌을 줄이는 방식을 다룬다.

해시 테이블은 세 조각으로 이루어진다.

  • 칸(bucket, 버킷)이 줄지어 있는 배열. 칸 수를 m이라고 하자.
  • 키를 정수로 바꾸는 해시 함수 hash().
  • 그 정수를 0 이상 m 미만의 칸 번호로 접는 규칙. 가장 단순한 규칙이 hash(key) % m이다.

칸 번호만 알면 배열이니 "시작 위치 + 칸 크기 × 번호"로 한 번에 간다(8장). 키가 백만 개여도 계산은 한 번이다. 그래서 찾기가 O(1)이다.


SIZE = 8                                   # 칸이 8개인 작은 표

for key in (17, 12, 5, 8, 33):
    print(f'{key:>2} -> hash {hash(key):>2} -> {hash(key) % SIZE}번 칸')

17 -> hash 17 -> 1번 칸
12 -> hash 12 -> 4번 칸
 5 -> hash  5 -> 5번 칸
 8 -> hash  8 -> 0번 칸
33 -> hash 33 -> 1번 칸

17과 33이 같은 1번 칸을 원한다. 이 충돌은 해시 함수를 먼저 본 뒤에 다룬다.

해시 함수

해시 함수는 어떤 값이든 받아 정수 하나를 돌려주는 함수다(4장). 해시 테이블의 재료로 쓰려면 세 가지를 갖춰야 한다.

  • 같은 값에는 언제나 같은 해시 값을 준다. 아니면 넣은 칸과 찾는 칸이 어긋난다.
  • 빠르다. 찾을 때마다 부르기 때문이다.
  • 고르게 퍼뜨린다. 키들이 몇 칸에 몰리면 충돌이 늘어난다.

정수의 해시

파이썬에서 정수의 해시 값은 거의 자기 자신이다. 정확히는 261 − 1로 나눈 나머지이고 부호는 그대로 둔다. 하나뿐인 예외가 −1이다.


print(hash(42), hash(0), hash(-7))         # 작은 정수는 해시 값이 자기 자신
print(hash(-1))                            # 예외: -1 은 오류 신호로 쓰여서 -2
print(hash(2**61 - 1), hash(2**61))        # 큰 정수는 2^61 - 1 로 나눈 나머지
print(hash(-7) % 8)                        # 음수 해시도 % 는 0~7 사이를 준다

42 0 -7
-2
0 1
1

−1이 −2가 되는 것은 파이썬의 C 구현이 "해시 계산 실패"를 −1로 알리기 때문이다. 오류와 헷갈리지 않게 −1의 해시만 −2로 바꿨다. 큰 정수를 접는 것은 해시 값이 64비트 정수 한 칸에 들어가야 해서다. 음수 해시라도 파이썬의 %는 0 이상의 나머지를 주므로 칸 번호는 늘 범위 안이다.

문자열의 해시는 실행마다 다르다

문자열과 바이트열, 그리고 그것을 담은 튜플의 해시 값은 프로그램을 시작할 때 뽑은 무작위 시드(seed, 해시 계산에 섞는 비밀 숫자)에 따라 달라진다. 한 번 실행되는 동안은 같으니 찾기에는 문제가 없지만, 다음 실행에서는 다른 값이 나온다(환경 변수 PYTHONHASHSEED로 고정할 수는 있다). 일부러 이렇게 만든 것은 공격을 막기 위해서다. 규칙이 고정돼 있으면 누군가 같은 칸에 몰리는 문자열을 수만 개 만들어 보내, 서버의 딕셔너리를 최악인 O(n)으로 떨어뜨릴 수 있다. 시드를 숨기면 그런 문자열을 미리 만들 수 없다. 이 책이 문자열의 해시 값을 출력하지 않는 이유다.

충돌과 처리법

서로 다른 키가 같은 칸 번호를 받는 것이 충돌(collision)이다. 충돌은 피할 수 없다. 비둘기 9마리를 집 8개에 넣으면 어느 집엔가는 두 마리가 들어가듯(비둘기집 원리), 칸은 유한하고 키는 끝이 없으니 어떤 두 키는 반드시 같은 칸을 원한다. 좋은 해시 함수도 충돌을 드물게 만들 뿐이라서 충돌을 처리하는 규칙이 따로 있어야 한다. 방법은 크게 둘이다.

체이닝: 한 칸에 줄을 세운다

체이닝(chaining)은 칸마다 리스트를 두고, 같은 칸에 온 키를 그 리스트에 이어 붙인다. 찾을 때는 칸 번호를 계산한 뒤 그 리스트만 앞에서부터 비교한다. 리스트가 짧으면 거의 한 번에 끝나고, 길면 그만큼 느려진다.

개방 주소법: 빈 칸을 찾아 옮긴다

개방 주소법(open addressing)은 한 칸에 키 하나만 둔다. 원하는 칸이 차 있으면 정해진 순서로 다른 칸을 살펴 빈 칸을 찾는다. 이 살피기를 탐사(probing)라고 한다. 가장 단순한 규칙은 바로 옆 칸으로 가는 선형 탐사다.


table = [None] * 8                        # 한 칸에 키 하나만 둔다


def put(key):
    start = hash(key) % 8
    i = start
    while table[i] is not None:           # 차 있으면 다음 칸을 본다
        i = (i + 1) % 8
    table[i] = key
    print(f'{key}: {start}번 칸을 원했고 {i}번 칸에 넣었다')


for key in (17, 12, 33, 25):
    put(key)
print(table)

17: 1번 칸을 원했고 1번 칸에 넣었다
12: 4번 칸을 원했고 4번 칸에 넣었다
33: 1번 칸을 원했고 2번 칸에 넣었다
25: 1번 칸을 원했고 3번 칸에 넣었다
[None, 17, 33, 25, 12, None, None, None]

33은 1번 칸이 차 있어서 2번으로, 25는 1번과 2번이 차 있어서 3번으로 밀렸다. 찾을 때도 같은 길을 따라가며 키를 비교하고, 빈 칸을 만나면 "없다"로 끝낸다. 그래서 지우기가 까다롭다. 17을 그냥 빈 칸으로 만들면 33을 찾을 때 1번 칸에서 빈 칸을 만나 길이 끊긴다. 개방 주소법은 지운 자리에 "지워졌음" 표시를 남겨 탐사가 그 칸을 건너뛰게 한다.

파이썬의 dict와 set은 개방 주소법을 쓴다. 체인용 리스트를 따로 만들지 않아 메모리가 적게 들고, 칸이 연속 메모리라 빠르기 때문이다. 다만 바로 옆 칸만 보면 찬 칸이 한 덩어리로 뭉치므로, 파이썬은 해시 값의 윗자리 비트를 섞어 다음 칸을 띄엄띄엄 고른다. 빈 칸을 찾을 때까지 다른 칸을 본다는 뼈대는 같다.

적재율과 리사이즈

어느 방법이든 충돌이 잦아지면 느려진다. 표가 얼마나 찼는지를 나타내는 수가 적재율(load factor), 곧 항목 수 ÷ 칸 수다. 체이닝에서 적재율이 α면 줄의 평균 길이가 α이므로, 없는 키를 찾을 때 평균 α번쯤 비교한다. 개방 주소법은 적재율이 1에 가까워질수록 빈 칸이 드물어 탐사가 급격히 길어지고, 1을 넘으면 넣을 곳 자체가 없다.

해결책은 단순하다. 표가 어느 정도 차면 더 큰 표를 만들고 모든 키를 새 칸 번호로 옮겨 담는다. 이것이 리사이즈(resize)다. 파이썬 dict는 칸 8개로 시작하고, 쓸 수 있는 칸(칸 수의 2/3)을 다 쓰면 더 큰 2의 거듭제곱 크기로 옮긴다. sys.getsizeof로 그 순간을 볼 수 있다.


import sys

d = {}
last = sys.getsizeof(d)
print(f'빈 딕셔너리: {last}바이트')

for n in range(1, 30):
    d[n] = n
    now = sys.getsizeof(d)
    if now != last:                       # 크기가 바뀐 순간만 찍는다
        print(f'{n}번째 키를 넣자 {last} -> {now}바이트')
        last = now

빈 딕셔너리: 64바이트
1번째 키를 넣자 64 -> 224바이트
6번째 키를 넣자 224 -> 352바이트
11번째 키를 넣자 352 -> 632바이트
22번째 키를 넣자 632 -> 1168바이트

8칸짜리 표는 쓸 수 있는 칸이 5개라 6번째 키에서 16칸으로, 16칸은 11번째 키에서 32칸으로 늘어난다. 바이트 수는 환경(파이썬 버전과 운영체제)에 따라 다를 수 있다.

그래서 "평균" O(1)이다

이제 4장의 "평균"을 설명할 수 있다. 한 번의 찾기는 칸 번호 계산 한 번에 충돌한 만큼의 비교가 더해진다. 리사이즈가 적재율을 늘 2/3 아래로 눌러 두므로 충돌은 드물고, 비교 횟수는 데이터 크기와 상관없이 작은 상수에 머문다. 이것이 평균 O(1)이다. 그래도 키가 한 칸에 몰리면 n개를 비교하는 최악 O(n)이 된다. 앞 절의 해시 시드가 이 최악을 막는 장치다.

리사이즈 자체는 키 n개를 모두 옮기므로 O(n)이다. 그런데도 넣기를 O(1)이라 부르는 것은 8장의 append와 같은 논리다. 표를 두 배로 키우면 다음 리사이즈까지 그만큼 많은 넣기가 공짜로 들어가므로, 여러 번을 평균 내면 넣기 한 번에 O(1)이다(분할 상환, 8장).

직접 만들어 보기

작은 체이닝 해시 테이블을 만들어 보자. 칸마다 (키, 값) 튜플의 리스트를 두고 넣기·찾기·지우기와 리사이즈를 갖춘다. 출력이 실행마다 같도록 키는 정수만 쓴다. 이 클래스는 hash_table.py에 한 번 정의하고 뒤의 코드가 가져다 쓴다.


class HashTable:
    def __init__(self, capacity=8):
        self.buckets = [[] for _ in range(capacity)]
        self.size = 0

    def _index(self, key):
        return hash(key) % len(self.buckets)        # 해시 값 -> 칸 번호

    def put(self, key, value):
        bucket = self.buckets[self._index(key)]
        for i, (k, _) in enumerate(bucket):
            if k == key:                            # 이미 있는 키면 값만 바꾼다
                bucket[i] = (key, value)
                return
        bucket.append((key, value))
        self.size += 1
        if self.size > len(self.buckets) * 2 // 3:  # 적재율이 2/3 를 넘으면
            self._resize(len(self.buckets) * 2)     # 칸을 두 배로 늘린다

    def get(self, key, default=None):
        for k, v in self.buckets[self._index(key)]:   # 그 칸의 체인만 훑는다
            if k == key:
                return v
        return default

    def remove(self, key):
        bucket = self.buckets[self._index(key)]
        for i, (k, _) in enumerate(bucket):
            if k == key:
                del bucket[i]
                self.size -= 1
                return True
        return False

    def _resize(self, capacity):
        old = [pair for bucket in self.buckets for pair in bucket]
        self.buckets = [[] for _ in range(capacity)]
        self.size = 0
        for key, value in old:                      # 새 칸 번호로 다시 넣는다
            self.put(key, value)

    def show(self):
        for i, bucket in enumerate(self.buckets):
            chain = ' -> '.join(f'{k}:{v}' for k, v in bucket)
            print(f'{i}: {chain or "비어 있음"}')



        
put은 먼저 체인에 같은 키가 있는지 보고, 있으면 값만 바꾼다. 없으면 체인 끝에 붙이고 개수를 센 뒤, 적재율이 2/3를 넘는 순간 칸을 두 배로 늘린다. _resize는 모든 쌍을 꺼내 새 표에 put으로 다시 넣는다. 칸 수가 달라졌으니 _index가 새 번호를 준다. 일부러 작은 표에 넣어 충돌을 눈으로 보자.




from hash_table import HashTable

t = HashTable(capacity=8)
for key, value in [(17, 'a'), (12, 'b'), (33, 'c'), (25, 'd')]:
    t.put(key, value)
t.show()

print(t.get(33))                  # 1번 칸의 체인을 훑어 33 을 찾는다
print(t.get(41, '없음'))           # 1번 칸 체인에 없으니 기본값
t.put(33, 'C')                    # 있는 키는 값만 바뀐다
print(t.get(33), t.size)
print(t.remove(17), t.remove(99)) # 있는 키는 True, 없는 키는 False
print(t.get(33), t.size)          # 앞 쌍을 지워도 체인의 나머지는 그대로

딕셔너리가 순서를 기억하는 방법

        
4장에서 딕셔너리는 넣은 순서대로 순회된다고 했다. 해시 테이블은 키를 칸 번호 순서로 흩어 놓는데 어떻게 넣은 순서를 알까. 3.5까지의 dict는 칸에 키와 값을 직접 두고 칸 번호 순서로 훑었으니 순서가 뒤죽박죽이었다. 3.6부터 구조가 바뀌었다.

        
새 구조는 표를 둘로 나눈다. 해시로 찾는 인덱스 표(indices)에는 "몇 번째 항목인가"라는 작은 번호만 두고, 실제 키와 값은 항목 배열(entries)에 넣은 순서대로 쌓는다. 찾기는 인덱스 표 → 항목 번호 → 항목 배열의 두 단계이고, 순회는 항목 배열을 앞에서부터 읽기만 하면 된다.


        


이 구조는 메모리도 아낀다. 인덱스 표는 칸이 적을 때 칸마다 1바이트짜리 번호만 담고, 무거운 항목은 실제 개수만큼만 쌓이기 때문이다. 3.6에서는 CPython의 구현 사정이었고, 3.7부터 언어 규칙이 되어 어떤 파이썬에서도 보장된다.




d = {'b': 1, 'a': 2, 'c': 3}
del d['a']
d['a'] = 9                 # 지웠다 다시 넣으면 맨 뒤로 간다
d['b'] = 0                 # 값만 바꾸면 자리는 그대로
print(d)
print(d.popitem())         # 마지막에 넣은 항목부터 꺼낸다
print(list(d))

지운 항목은 항목 배열에 빈 자리로 남아 순회 때 건너뛰고, 다음 리사이즈 때 정리된다. 그래서 다시 넣은 'a'는 맨 뒤로 가고, 값만 바꾼 'b'는 자리를 지킨다. popitem()은 배열의 끝을 떼어 낸다. 집합은 이 구조를 쓰지 않고 칸에 원소를 직접 두므로 순서가 없다.

      


      

        
키의 조건: __hash__와 __eq__

        
4장의 "불변이면 키가 된다"를 원리로 다시 보자. 찾기는 두 단계다. hash(key)로 칸 번호를 정하고, 그 칸(또는 체인)에서 ==로 키를 비교한다. 두 단계가 서로 맞아야 하므로 파이썬은 이런 약속을 요구한다. a == b이면 hash(a) == hash(b)여야 한다. 반대는 필요 없다. 해시가 같아도 다른 값일 수 있고, 그것이 바로 충돌이다.

        
이 약속 때문에 1, 1.0, True는 한 키다. 세 값은 ==로 같으므로 해시도 같아야 하고, 그래서 파이썬의 숫자 해시는 타입이 아니라 수학적인 값으로 계산한다.




print(1 == 1.0 == True)
print(hash(1), hash(1.0), hash(True))   # 같은 값이면 해시도 같다

d = {1: 'int'}
d[1.0] = 'float'                        # 같은 키로 취급해 값만 덮어쓴다
d[True] = 'bool'
print(d)                                # 키는 처음 넣은 1 이 그대로 남는다
print(len({1, 1.0, True}))



True

직접 만든 클래스도 이 약속을 지켜야 한다. __eq__만 정의하면 파이썬은 __hash__를 None으로 바꾼다. "같다"의 기준은 바뀌었는데 해시가 옛 기준(객체의 주소)으로 계산되면 약속이 깨지기 때문이다. __eq__가 비교하는 재료로 __hash__를 정의하면 된다.




class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)


print(Point.__hash__)                   # __eq__ 만 정의하면 __hash__ 는 None
try:
    {Point(1, 2)}
except TypeError as e:
    print(f'{type(e).__name__}: {e}')


class HashablePoint(Point):
    def __hash__(self):
        return hash((self.x, self.y))   # 같은 좌표면 같은 해시


visited = {HashablePoint(1, 2)}
print(HashablePoint(1, 2) in visited)   # 다른 객체지만 같은 키다



None
TypeError: unhashable type: 'Point'
True



        
@dataclass(frozen=True)를 쓰면 __eq__와 __hash__를 필드 기준으로 한꺼번에 만들어 준다. 좌표처럼 값 몇 개를 묶은 키는 그냥 튜플을 쓰는 것이 가장 간단하다(4장).

      


      

        
자주 하는 실수

        

          해시 값을 저장하거나 실행 사이에 비교하기
          
문자열의 hash()는 실행마다 바뀐다. 파일이나 데이터베이스에 적어 두거나, 두 프로그램이 주고받아 비교하면 다음 실행에서 모두 어긋난다. 어디서나 같은 값이 필요하면 hashlib.sha256처럼 시드가 없는 해시 함수를 쓴다.

        

        

          실수(float)를 키로 쓰기
          
실수는 불변이라 키가 되지만, 계산 결과가 미세하게 어긋나면 값도 해시도 달라져 찾지 못한다. 0.1 + 0.2를 키로 넣고 0.3으로 찾으면 False다. 돈이나 좌표처럼 자릿수가 정해진 값은 정수로 바꿔 키를 만든다.

        



        

          키로 넣은 객체의 내용 바꾸기
          
리스트는 애초에 거부되지만(4장), __hash__를 직접 붙인 객체는 넣은 뒤 필드를 바꿔도 막지 않는다. 해시 값이 바뀌어 다른 칸을 보게 되므로 분명히 넣었는데 in이 False를 돌려준다. 키로 쓰는 객체는 불변으로 만든다.

        

        

          순회하면서 넣거나 지우기
          
4장에서 본 RuntimeError의 이유가 여기에 있다. 넣다가 리사이즈가 일어나면 항목 배열이 새로 만들어져 순회 위치가 의미를 잃으므로, 파이썬은 순회 중 크기가 바뀌면 멈춘다. list(d)로 복사한 키 목록을 돌며 지운다.

애너그램끼리 묶기

          

          

            
소문자 알파벳으로만 이루어진 단어 목록 words가 주어진다. 글자의 종류와 개수가 같아 순서만 바꾸면 서로 같아지는 두 단어를 애너그램(anagram)이라고 한다. 애너그램끼리 묶은 리스트를 돌려주는 함수 group_anagrams(words)를 작성하라.

            
    
              
  • 묶음의 순서는 각 묶음의 첫 단어가 입력에 나온 순서를 따르고, 묶음 안의 순서도 입력 순서를 따른다.
    • 
              
  • 단어는 최대 10,000개이고, 한 단어의 길이는 100 이하다.
    • 
            

            

              

                
입력출력이유

                
                  
['race', 'care', 'note', 'acre', 'tone', 'cat'][['race', 'care', 'acre'], ['note', 'tone'], ['cat']]race·care·acre는 a, c, e, r이 하나씩이다

                  
['stop', 'pots', 'tops'][['stop', 'pots', 'tops']]모두 같은 글자로 되어 있다

                  
['a'][['a']]혼자인 단어도 한 묶음이다

                
              

            

          


          

            접근 방법먼저 생각해 보고 펼치세요
            

              
단어를 두 개씩 짝지어 확인하면 쌍만 n(n−1)/2개, 단어가 만 개면 5천만 쌍이다.

              
관점을 바꾸자. 애너그램은 글자의 구성이 같은 단어들이다. 그러니 구성이 같으면 같은 값이 나오는 "이름표"를 만들어 그 이름표를 키로 모으면 된다. 가장 쉬운 이름표는 글자를 정렬한 문자열이다. 'race', 'care', 'acre'는 모두 'acer'가 된다.

              
    
                
  1. 단어마다 ''.join(sorted(w))로 이름표를 만든다.
    2. 
                
  2. 이름표를 키로, 단어 목록을 값으로 딕셔너리에 모은다. 4장의 defaultdict(list)가 꼭 맞는다.
    3. 
                
  3. 딕셔너리는 넣은 순서를 지키므로 값들을 차례로 꺼내면 묶음 순서가 저절로 입력 순서가 된다.
    4. 
              

            

          


          

            풀이 코드
            



from collections import defaultdict


def group_anagrams(words: list[str]) -> list[list[str]]:
    groups = defaultdict(list)            # 정렬한 글자열 -> 단어 목록
    for w in words:
        key = ''.join(sorted(w))          # 'race', 'care', 'acre' -> 'acer'
        groups[key].append(w)
    return list(groups.values())          # 딕셔너리는 넣은 순서를 지킨다


print(group_anagrams(['race', 'care', 'note', 'acre', 'tone', 'cat']))
print(group_anagrams(['stop', 'pots', 'tops']))
print(group_anagrams(['a']))



[['race', 'care', 'acre'], ['note', 'tone'], ['cat']]
[['stop', 'pots', 'tops']]
[['a']]


              
정렬 대신 글자별 개수를 이름표로 써도 된다. 알파벳 26칸을 센 리스트 counts를 tuple(counts)로 바꿔 키로 쓰면 정렬이 필요 없다. 리스트는 키가 될 수 없으니 반드시 튜플로 바꾼다(4장).

            

          


          

            복잡도
            

              

                
시간
O(n · k log k) 단어 n개를 한 번씩 보고, 길이 k인 단어를 정렬한다. 딕셔너리 넣기는 평균 O(1)이다. 개수 튜플을 쓰면 O(n · k)다.

                
공간
O(n · k) 모든 단어와 그 이름표를 딕셔너리에 담는다.

              

            

          

        

      


      

        
스스로 확인

        

          

            딕셔너리 찾기에 "평균 O(1)"이라고 "평균"을 붙이는 이유는? 최악은 얼마인가?
            
충돌한 만큼 비교가 늘어나기 때문이다. 리사이즈가 적재율을 2/3 아래로 눌러 두어 평균 비교 횟수는 작은 상수다. 모든 키가 한 칸에 몰리면 최악 O(n)이다.

          

          

            개방 주소법에서 키를 지울 때 그 칸을 그냥 빈 칸으로 돌려놓으면 왜 안 되는가?
            
찾기는 빈 칸을 만나면 "없다"로 끝난다. 지운 칸 뒤로 밀려났던 키는 그 빈 칸에서 길이 끊겨 찾지 못한다. 그래서 "지워졌음" 표시를 남긴다.

          

          

            {1: 'a', 1.0: 'b', True: 'c'}는 무엇이 되고, 왜 그런가?
            
{1: 'c'}가 된다. 세 값은 ==로 같으므로 약속에 따라 해시도 같고, 딕셔너리는 같은 키로 취급해 값만 덮어쓴다. 키는 처음 넣은 1이 남고 값은 마지막 'c'가 남는다.

          

          

            __eq__만 정의한 클래스의 객체를 집합에 넣으면 어떻게 되는가?
            
TypeError: unhashable type이 난다. __eq__를 정의하면 __hash__가 None이 되기 때문이다. 같은 재료로 __hash__를 정의하거나 @dataclass(frozen=True)를 쓴다.

          

        

      


      

        
정리

        
    
          
  1. 해시 테이블은 hash(key) % 칸 수로 칸 번호를 정해 배열처럼 바로 간다. 딕셔너리와 집합의 바닥 구조다.
    2. 
          
  2. 정수의 해시는 어디서나 같지만 문자열의 해시는 실행마다 바뀐다(시드). 출력하거나 저장하거나 실행 사이에 비교하지 않는다.
    3. 
          
  3. 충돌은 피할 수 없다. 체이닝은 칸마다 줄을 세우고, 개방 주소법은 빈 칸을 찾아 옮긴다. 파이썬 dict와 set은 개방 주소법이다.
    4. 
          
  4. 적재율이 2/3를 넘으면 표를 늘려 모두 다시 넣는다. 그래서 찾기는 평균 O(1), 최악 O(n)이고 넣기는 분할 상환 O(1)이다.
    5. 
          
  5. 딕셔너리는 인덱스 표와 항목 배열을 나눠 넣은 순서를 기억한다. 집합은 그렇지 않다.
    6. 
          
  6. a == b이면 hash(a) == hash(b)여야 한다. 그래서 1, 1.0, True는 한 키이고, __eq__를 정의하면 __hash__도 정의해야 한다.
