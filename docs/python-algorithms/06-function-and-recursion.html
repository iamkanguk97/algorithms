함수와 재귀

함수는 코드 묶음에 이름을 붙여 몇 번이고 다시 쓰게 해 주는 도구입니다. 이 장에서는 함수의 규칙을 정리한 뒤, 함수가 자기 자신을 부르는 재귀까지 다룹니다.

def · returnlambda스코프재귀호출 스택

이 장에서 배울 것

  • 함수를 정의하고 기본값, 키워드 인자, 가변 인자를 쓸 수 있다
  • 가변 기본값 함정과 스코프 규칙(global, nonlocal)을 설명할 수 있다
  • 함수를 값처럼 넘기고, lambda를 정렬 기준으로 쓸 수 있다
  • 재귀 함수를 기저 조건과 재귀 단계로 나눠 짤 수 있다
  • 재귀 깊이 제한과 메모이제이션이 왜 필요한지 안다

함수 정의와 호출

핵심

함수는 입력(인자)을 받아 일을 하고 결과 하나를 돌려주는 이름 붙은 코드 묶음이다.

def로 함수를 만들고, return으로 결과를 돌려준다. 함수를 정의할 때 괄호 안에 적는 이름을 매개변수, 호출할 때 실제로 넘기는 값을 인자라고 한다.


def add(a, b):
    return a + b


def greet(name):
    print(f'안녕, {name}')     # return 이 없다


def min_max(numbers):
    return min(numbers), max(numbers)   # 튜플 하나를 돌려준다


print(add(2, 3))
result = greet('파이썬')
print(result)

pair = min_max([4, 1, 7])
print(pair)
low, high = min_max([4, 1, 7])     # 받자마자 풀어 담는다
print(low, high)

5
안녕, 파이썬
None
(1, 7)
1 7

return이 없는 함수도 None이라는 값을 돌려준다. 여러 값을 돌려주는 것처럼 보이는 return a, b는 사실 튜플 하나를 돌려주는 것이고, 받는 쪽에서 low, high = ...로 풀어 담는다(언패킹, 3장).

기본값과 키워드 인자

매개변수에 =값을 붙이면 기본값이 된다. def power(base, exp=2):라면 power(3)은 exp를 2로 계산해 9를 돌려준다. 인자를 이름=값 꼴로 넘기는 것을 키워드 인자라고 하는데, power(exp=3, base=2)처럼 순서를 바꿔 넘겨도 된다.

기본값이 있는 매개변수는 기본값이 없는 매개변수보다 뒤에 와야 한다. def f(x, y=1, z):처럼 쓰면 SyntaxError가 난다. 어떤 값이 어느 매개변수로 갈지 정할 수 없기 때문이다.

인자를 몇 개든 받기: *args와 **kwargs

매개변수 이름 앞에 *를 붙이면 남은 위치 인자를 모두 튜플로 묶어 받는다. **를 붙이면 남은 키워드 인자를 딕셔너리로 묶어 받는다. 이름은 관례상 args, kwargs를 많이 쓴다.


def total(*numbers):
    print(numbers)          # 위치 인자들이 튜플 하나로 묶인다
    return sum(numbers)


print(total(1, 2, 3))
nums = [4, 5, 6]
print(total(*nums))         # 호출할 때 * 는 리스트를 풀어서 넘긴다

(1, 2, 3)
6
(4, 5, 6)
15

타입 힌트는 검사하지 않는다

def double(x: int) -> int:처럼 매개변수와 반환값에 자료형을 적을 수 있다. 이것을 타입 힌트라고 한다. 다만 파이썬은 실행할 때 힌트를 확인하지 않는다. 이 함수에 'ab'를 넘겨도 에러 없이 'abab'를 돌려준다. 힌트는 읽는 사람과 편집기, mypy 같은 검사 도구를 위한 표시다.

기본값 함정

기본값에 리스트나 딕셔너리처럼 바뀔 수 있는(가변) 객체를 쓰면 예상과 다르게 동작한다. 아래 함수는 호출할 때마다 빈 리스트에서 시작할 것처럼 보이지만 그렇지 않다.


def add_item(item, items=[]):
    items.append(item)
    return items


print(add_item('a'))
print(add_item('b'))         # ['b'] 를 기대했지만…
print(add_item('c', []))     # 리스트를 직접 넘기면 괜찮다
print(add_item('d'))
print(add_item.__defaults__) # 기본값은 함수에 붙어 있다

['a']
['a', 'b']
['c']
['a', 'b', 'd']
(['a', 'b', 'd'],)

이유는 기본값이 만들어지는 시점에 있다. 기본값은 def 문이 실행될 때 딱 한 번 만들어져 함수에 저장된다. 호출할 때마다 새로 만드는 것이 아니다. 그래서 기본값을 쓰는 호출은 모두 같은 리스트 하나를 함께 쓰고, 앞선 호출에서 넣은 값이 다음 호출에 남는다. 마지막 줄의 __defaults__가 함수에 붙어 있는 바로 그 리스트다.

해결책은 기본값을 None으로 두고, 함수 안에서 새 리스트를 만드는 것이다. 함수 본문은 호출할 때마다 실행되므로 매번 새 리스트가 생긴다.


def add_item(item, items=None):
    if items is None:        # 호출할 때마다 새 리스트를 만든다
        items = []
    items.append(item)
    return items


print(add_item('a'))
print(add_item('b'))

['a']
['b']
팁

숫자, 문자열, 튜플, None처럼 바뀌지 않는(불변) 값은 기본값으로 써도 안전하다(가변과 불변은 2장).

함수도 값이다: 람다

파이썬에서 함수는 숫자나 리스트와 똑같은 값이다. 변수에 담을 수 있고, 다른 함수의 인자로 넘길 수 있고, 함수의 결과로 돌려줄 수도 있다. 이런 성질을 일급 객체라고 부른다.


def square(x):
    return x * x


f = square            # 괄호가 없으면 호출하지 않고 함수 자체를 담는다
print(f(5))
print(list(map(square, [1, 2, 3])))   # 모든 원소에 square 를 적용

25
[1, 4, 9]

square와 square()의 차이가 중요하다. 괄호를 붙이면 함수를 실행해서 그 결과를 쓰고, 괄호가 없으면 함수 그 자체를 가리킨다. map, sorted, max처럼 함수를 받는 함수에는 괄호 없이 넘긴다.

lambda: 이름 없는 한 줄 함수

정렬 기준처럼 한 번만 쓰고 버릴 짧은 함수를 위해 def로 이름까지 붙이기는 번거롭다. 이럴 때 lambda 매개변수: 식으로 그 자리에서 함수를 만든다. lambda x: x * x는 def로 만든 square와 같은 일을 한다. 콜론 뒤의 식을 계산한 값이 곧 반환값이라 return을 쓰지 않는다.


words = ['pear', 'kiwi', 'apple', 'fig']
print(sorted(words, key=len))                     # 길이 순
print(sorted(words, key=lambda w: (len(w), w)))   # 길이, 같으면 사전 순

points = [(1, 3), (2, 1), (0, 2)]
print(max(points, key=lambda p: p[1]))     # 두 번째 값이 가장 큰 점
print(list(map(lambda x: x * 10, [1, 2, 3])))

['fig', 'pear', 'kiwi', 'apple']
['fig', 'kiwi', 'pear', 'apple']
(1, 3)
[10, 20, 30]

key에 넘긴 함수는 원소마다 한 번씩 불려 "비교에 쓸 값"을 만든다. 두 번째 정렬은 (길이, 단어) 튜플을 비교하므로 길이가 같은 pear와 kiwi를 사전 순으로 정한다. 정렬 기준은 3장에서 더 다룬다.

lambda에는 식 하나만 쓸 수 있다. 대입이나 for, 여러 줄짜리 if 문은 넣을 수 없다(a if 조건 else b 같은 조건식은 식이라서 된다). 로직이 한 줄을 넘거나, 여러 곳에서 다시 쓰거나, 이름을 붙여야 읽기 쉬워진다면 def로 만든다.

스코프: 이름이 보이는 범위

변수 이름이 통하는 범위를 스코프라고 한다. 함수 안에서 만든 변수는 지역 변수로, 그 함수 안에서만 보인다. 함수 밖, 파일 맨 바깥에서 만든 변수는 전역 변수다.

파이썬은 이름을 지역 → 감싸는 함수 → 전역 → 내장(print, len 같은 기본 이름) 순서로 찾는다. 그래서 전역 변수를 읽기만 하는 것은 문제가 없다. 문제는 대입할 때 생긴다.


count = 0


def show():
    print(count)          # 읽기만 하면 바깥 변수를 그대로 쓴다


def increase():
    count += 1            # 대입이 있으면 count 는 지역 변수가 된다


show()
try:
    increase()
except UnboundLocalError as e:
    print(f'{type(e).__name__}: {e}')

0
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value

함수 안 어디에서든 어떤 이름에 대입하면, 그 이름은 함수 전체에서 지역 변수로 취급된다. 파이썬은 함수를 실행하기 전에 이것을 정해 둔다. count += 1은 count = count + 1이므로 count는 지역 변수가 되고, 오른쪽에서 아직 값이 없는 지역 변수 count를 읽으려다 에러가 난다.

global과 nonlocal

바깥 변수에 정말로 대입하고 싶다면 그 사실을 밝혀야 한다. 함수 첫머리에 전역 변수라면 global count, 한 단계 바깥 함수의 변수라면 nonlocal count라고 쓴다. 위 increase에 global count 한 줄을 넣으면 에러 없이 1이 늘어난다.

코딩 테스트에서는 nonlocal을 더 자주 만난다. 함수 안에 보조 함수를 두고, 보조 함수가 바깥의 결과 변수를 고치는 코드를 자주 쓰기 때문이다. 13장의 깊이 우선 탐색(DFS)이 대표적이다. 이때 무엇에 nonlocal이 필요한지 헷갈리기 쉽다.


def summarize(numbers: list[int]) -> tuple[list[int], int]:
    evens = []
    total = 0

    def visit(x: int) -> None:
        nonlocal total        # total 에는 새 값을 대입하므로 필요하다
        if x % 2 == 0:
            evens.append(x)   # 리스트 내용만 바꾸므로 필요 없다
            total += x

    for x in numbers:
        visit(x)
    return evens, total


print(summarize([3, 8, 5, 2, 6]))

([8, 2, 6], 16)

기준은 하나다. 이름에 대입하느냐를 본다. total += x는 이름 total에 새 숫자를 대입하므로 nonlocal이 필요하다. evens.append(x)는 이름 evens가 가리키는 리스트의 내용을 바꿀 뿐, 이름에 대입하지 않으므로 필요 없다.

재귀의 두 요소

함수가 자기 자신을 호출하는 것을 재귀라고 한다. 처음 보면 끝없이 돌 것 같지만, 두 가지만 갖추면 반드시 멈춘다.

  • 기저 조건 — 더 쪼개지 않고 바로 답을 돌려주는 가장 작은 경우
  • 재귀 단계 — 문제를 한 단계 더 작은 같은 문제로 바꿔 자기 자신에게 맡기는 부분

팩토리얼이 가장 흔한 예다. 5! = 5 × 4!이고, 4! = 4 × 3!이다. 큰 문제의 답이 한 단계 작은 같은 문제의 답으로 표현된다.


def factorial(n: int) -> int:
    if n <= 1:                    # 기저 조건: 바로 답한다
        return 1
    return n * factorial(n - 1)   # 재귀 단계: 작은 문제에 맡긴다


print(factorial(5))
print(factorial(20))

120
2432902008176640000

재귀 함수를 짤 때는 호출이 어떻게 이어지는지 끝까지 따라가지 않는 편이 낫다. 대신 "한 단계 작은 호출은 이미 정답을 돌려준다"고 믿고, 그 답으로 지금 단계의 답을 만드는 것만 생각한다. factorial(n - 1)이 (n-1)!을 정확히 돌려준다고 믿으면, 남은 일은 거기에 n을 곱하는 것뿐이다. 기저 조건이 맞고 매 단계 문제가 작아진다면 이 믿음은 실제로 성립한다. 수학적 귀납법과 같은 구조다.

재귀로 짤 수 있는 것은 모두 반복문으로도 짤 수 있다. 그래도 재귀를 배우는 이유는 트리(15장)나 분할 정복(25장)처럼 문제 안에 같은 모양의 작은 문제가 들어 있는 경우에 재귀가 훨씬 자연스럽게 읽히기 때문이다.

호출 스택

함수를 호출하면 파이썬은 그 호출의 지역 변수와 "끝나면 돌아갈 위치"를 담은 기록을 하나 만든다. 이 기록을 프레임이라고 하고, 프레임이 쌓이는 곳을 호출 스택이라고 한다. 이름 그대로 스택(10장)처럼 동작한다. 새 호출은 맨 위에 쌓이고, 함수가 끝나면 맨 위 프레임이 빠진다.

factorial(3)은 3 * factorial(2)를 계산하다가 멈추고 기다린다. factorial(2)도 factorial(1)을 기다린다. 기저 조건인 factorial(1)이 1을 돌려주면, 그제야 기다리던 프레임이 차례로 깨어나 곱셈을 마친다. 들여쓰기로 깊이를 표시해 직접 확인해 보자.


def factorial(n: int, depth: int = 0) -> int:
    indent = '  ' * depth
    print(f'{indent}factorial({n}) 호출')
    if n <= 1:
        result = 1
    else:
        result = n * factorial(n - 1, depth + 1)
    print(f'{indent}factorial({n}) = {result} 반환')
    return result


factorial(3)

factorial(3) 호출
  factorial(2) 호출
    factorial(1) 호출
    factorial(1) = 1 반환
  factorial(2) = 2 반환
factorial(3) = 6 반환

각 프레임은 자기만의 n과 indent를 따로 가진다. 그래서 같은 이름의 변수가 여러 단계에 동시에 있어도 섞이지 않는다.

재귀 깊이 제한

프레임은 메모리를 차지한다. 기저 조건을 잘못 써서 재귀가 끝나지 않으면 프레임이 한없이 쌓인다. 파이썬은 이를 막으려고 재귀 깊이, 즉 동시에 쌓일 수 있는 파이썬 함수 호출 수에 한도를 둔다. 기본값은 1000이고, 넘으면 RecursionError가 난다.


import sys


def depth(n: int) -> int:
    if n == 0:
        return 0
    return depth(n - 1) + 1


print(sys.getrecursionlimit())
print(depth(900))
try:
    depth(5000)
except RecursionError as e:
    print(f'{type(e).__name__}: {e}')

1000
900
RecursionError: maximum recursion depth exceeded

코드가 틀리지 않았는데도 입력이 크면 한도에 걸린다. 예를 들어 노드가 10만 개인 일자 모양 그래프를 재귀 DFS로 돌면 깊이도 10만이 된다. 그래서 코딩 테스트 풀이에서는 파일 맨 위에 한도를 올리는 한 줄을 넣는 경우가 많다.


import sys

sys.setrecursionlimit(10**6)   # 한도를 100만으로 올린다


def depth(n: int) -> int:
    if n == 0:
        return 0
    return depth(n - 1) + 1


print(depth(100_000))

100000

한도를 올린다고 문제가 모두 사라지지는 않는다. 이 노트를 쓴 환경(Python 3.13)에서 실험한 결과는 이렇다.

  • 단순한 재귀는 한도를 충분히 올리면 깊이 100만까지 돌았다. 다만 깊이 100만에서 메모리를 100MB 넘게 썼다.
  • 뒤에서 볼 @cache를 붙인 재귀는 한도를 100만으로 올려도 깊이 몇천에서 RecursionError가 났다. cache는 C로 만들어져 있고, C 코드를 거치는 호출에는 setrecursionlimit과 상관없는 별도 한도가 걸린다.

파이썬 3.10 이하는 파이썬 함수끼리의 호출에도 C 스택을 써서, 한도만 크게 올리고 깊이 들어가면 에러 메시지 없이 프로그램이 죽기도 했다. 채점 환경의 버전에 따라 결과가 다를 수 있다.

깊이가 수만을 넘을 수 있다면

재귀 대신 반복문과 직접 만든 스택(리스트)으로 바꾸는 편이 안전하다. 호출 스택이 하던 일을 리스트가 대신하므로 재귀 한도에 걸리지 않는다. 13장에서 DFS를 이렇게 바꾸는 방법을 다룬다.

같은 계산 다시 하지 않기

피보나치 수열은 앞의 두 수를 더해 다음 수를 만든다(0, 1, 1, 2, 3, 5, 8, …). 정의를 그대로 재귀로 옮기면 짧고 읽기 쉽지만, 아주 느리다. 함수가 몇 번 불리는지 세어 보자.


calls = 0


def fib(n: int) -> int:
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)


print(fib(20), calls)

6765 21891

21번이면 될 계산을 21,891번 한다. fib(20)은 fib(19)와 fib(18)을 부르는데, fib(19)도 다시 fib(18)을 부른다. 같은 인자의 호출이 가지를 칠 때마다 겹치고, 그 겹침이 아래로 갈수록 불어난다.

n단순 재귀의 호출 수답을 저장해 두면
1017711
2021,89121
302,692,53731
시간O(1.62ⁿ) 지수 시간O(n)

해결책은 간단하다. 한 번 구한 답을 저장해 두고, 같은 인자로 다시 불리면 저장한 답을 돌려준다. 이것을 메모이제이션이라고 한다. 파이썬에서는 functools.cache를 함수 위에 붙이기만 하면 된다. 함수 위에 @이름을 적어 함수에 기능을 덧씌우는 문법을 데코레이터라고 한다.


from functools import cache

calls = 0


@cache
def fib(n: int) -> int:
    global calls
    calls += 1            # 저장된 답이 없을 때만 본문이 실행된다
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)


print(fib(20), calls)
print(fib(90))

6765 21
2880067194370816120

본문은 n마다 한 번씩, 모두 21번만 실행된다. 단순 재귀로는 엄두도 못 낼 fib(90)도 바로 나온다. 이 "겹치는 작은 문제의 답을 저장해 다시 쓰는" 생각이 26장 다이나믹 프로그래밍의 출발점이다.

@cache는 인자를 딕셔너리의 키로 써서 답을 저장한다. 그래서 인자가 리스트면 TypeError: unhashable type: 'list'가 난다(4장). 리스트 대신 튜플을 넘긴다. 깊이가 몇천을 넘는 문제라면 앞 절의 한도 문제 때문에 반복문으로 표를 채우는 방식(26장)을 쓴다.

자주 하는 실수

재귀 호출의 결과를 return 하지 않기

재귀 단계에서 호출만 하고 return을 빠뜨리면, 깊은 곳에서 찾은 답이 위로 전달되지 않고 버려진다. 함수 끝까지 return 없이 내려오므로 결과는 None이다.


def find(numbers: list[int], target: int, i: int = 0) -> int:
    if i == len(numbers):
        return -1
    if numbers[i] == target:
        return i
    find(numbers, target, i + 1)       # return 이 빠졌다


print(find([5, 3, 8], 8))   # 2 를 기대했다

None

마지막 줄을 return find(numbers, target, i + 1)로 고치면 2가 나온다. 재귀 호출의 결과를 그대로 위로 넘겨야 하는 자리라면 return이 빠지지 않았는지 먼저 확인한다.

기저 조건에 닿지 않기

기저 조건이 있어도 재귀 단계가 그 조건을 건너뛰면 소용없다. n == 0에서 멈추는 함수가 n - 2로 내려가면, 홀수에서 시작했을 때 0을 지나쳐 음수로 끝없이 내려가다 RecursionError가 난다. 조건을 n <= 0처럼 넓게 잡는다.

가변 객체를 기본값으로 쓰기

def f(x, memo={})나 def f(x, path=[])는 호출 사이에 값이 남는다. 재귀 함수에 경로나 메모를 넘길 때 특히 자주 실수한다.

함수 안에서 바깥 변수에 대입하기

보조 함수 안의 answer += 1이나 best = max(best, x)는 UnboundLocalError를 낸다. nonlocal이나 global을 선언한다.

입력이 커지면 재귀 한도에 걸린다

예제에서 잘 돌던 재귀가 큰 입력에서 RecursionError를 낸다면 깊이를 의심한다. sys.setrecursionlimit으로 한도를 올리고, 그래도 깊이가 수만을 넘을 수 있으면 반복문과 스택으로 바꾼다.

대표 문제

Problem보통재귀

하노이 탑

기둥 세 개에 1, 2, 3번이 붙어 있다. 1번 기둥에는 크기가 모두 다른 원판 n개가 큰 것이 아래로 가도록 쌓여 있다. 다음 규칙을 지키며 모든 원판을 3번 기둥으로 옮기려 한다.

  • 한 번에 원판 하나만 옮긴다.
  • 각 기둥의 맨 위 원판만 옮길 수 있다.
  • 작은 원판 위에 큰 원판을 올릴 수 없다.

가장 적게 옮기는 방법을 출력하라. 첫 줄에는 옮긴 횟수를, 다음 줄부터는 한 번 옮길 때마다 "출발 기둥 도착 기둥"을 한 줄씩 쓴다. n은 1 이상 20 이하이다.

입력출력설명
11
1 3		원판 하나는 바로 옮긴다
23
1 2
1 3
2 3		작은 원판을 2번에 비켜 두고, 큰 원판을 옮긴 뒤, 작은 원판을 다시 올린다
접근 방법먼저 생각해 보고 펼치세요

가장 큰 원판에 집중한다. 가장 큰 원판을 3번으로 옮기려면 그 순간 1번에는 그 원판만 있고, 3번은 비어 있어야 한다. 즉 나머지 n-1개는 모두 2번에 가 있어야 한다. 그러면 할 일은 세 단계로 정리된다.

  1. 위의 n-1개를 1번에서 2번으로 옮긴다. 3번을 거쳐 가는 기둥으로 쓴다.
  2. 가장 큰 원판을 1번에서 3번으로 옮긴다.
  3. 2번에 있는 n-1개를 3번으로 옮긴다. 이번에는 1번을 거쳐 간다.

1단계와 3단계는 "원판 n-1개를 한 기둥에서 다른 기둥으로 옮기기"로, 원래 문제와 모양은 같고 크기만 하나 작다. 작은 호출이 n-1개를 알아서 옮겨 준다고 믿으면, 지금 단계에서는 가장 큰 원판 하나만 옮기면 된다. 원판이 0개면 할 일이 없으니 그것을 기저 조건으로 삼는다.

옮기는 횟수를 T(n)이라 하면 T(n) = 2·T(n-1) + 1, T(0) = 0이다. 풀면 T(n) = 2ⁿ - 1이다.

풀이 코드 

import sys

input = sys.stdin.readline


def hanoi(n: int, start: int, goal: int, via: int,
          moves: list[str]) -> None:
    if n == 0:                               # 옮길 원판이 없다
        return
    hanoi(n - 1, start, via, goal, moves)    # n-1개를 비켜 둔다
    moves.append(f'{start} {goal}')          # 가장 큰 원판
    hanoi(n - 1, via, goal, start, moves)    # n-1개를 다시 올린다


n = int(input())
moves = []
hanoi(n, 1, 3, 2, moves)
print(len(moves))
print('\n'.join(moves))     # 한 번에 모아 출력해야 빠르다

start, goal, via(출발, 도착, 거쳐 가는 기둥)의 자리만 바꿔 넘기는 것이 핵심이다. n이 20이면 이동이 100만 줄을 넘으므로 리스트에 모아 한 번에 출력한다(1장).

복잡도
시간
O(2ⁿ) 이동이 정확히 2ⁿ - 1번 일어난다. 출력해야 할 줄 수 자체가 그만큼이라 이보다 빠를 수 없다.
공간
O(2ⁿ) 이동 기록을 모두 모아 두기 때문이다. 재귀 깊이는 n + 1단계를 넘지 않아 호출 스택은 O(n)만 쓴다.

스스로 확인

def f(x, items=[])로 만든 함수를 여러 번 호출하면 왜 앞선 호출의 값이 남는가?

기본값은 def 문이 실행될 때 한 번만 만들어져 함수에 저장되고, 기본값을 쓰는 호출은 모두 그 리스트 하나를 함께 쓴다. 기본값을 None으로 두고 함수 안에서 새 리스트를 만든다.

보조 함수 안에서 바깥 리스트에 append할 때는 괜찮은데, 바깥 정수에 += 1을 하면 에러가 나는 이유는?

+= 1은 이름에 대입하므로 그 이름이 보조 함수의 지역 변수가 되고, 값이 없는 지역 변수를 읽다가 UnboundLocalError가 난다. append는 이름에 대입하지 않고 리스트 내용만 바꾼다. 정수 쪽은 nonlocal을 선언한다.

@cache를 붙이면 fib(20)의 본문이 21,891번에서 21번으로 줄어드는 이유는?

단순 재귀는 같은 인자의 호출을 가지마다 다시 계산한다. @cache는 인자별로 답을 저장해 두고 두 번째부터는 저장한 답을 돌려주므로, 본문은 fib(0)부터 fib(20)까지 인자마다 한 번씩, 모두 21번만 실행된다.

원판이 4개인 하노이 탑은 최소 몇 번 옮겨야 하는가?

15번이다. T(n) = 2·T(n-1) + 1이므로 T(1) = 1, T(2) = 3, T(3) = 7, T(4) = 15이고, 일반식 2ⁿ - 1에 넣어도 2⁴ - 1 = 15다.

정리

  1. return이 없는 함수는 None을 돌려주고, return a, b는 튜플 하나를 돌려준다.
  2. 기본값은 def 때 한 번만 만들어진다. 리스트나 딕셔너리 대신 None을 기본값으로 쓴다.
  3. 함수도 값이라 변수에 담고 인자로 넘길 수 있다. 한 번 쓰고 버릴 짧은 함수는 lambda로 그 자리에서 만든다.
  4. 함수 안에서 이름에 대입하면 그 이름은 지역 변수가 된다. 바깥 변수에 대입하려면 global이나 nonlocal을 선언한다.
  5. 재귀는 기저 조건과, 문제를 한 단계 작게 만드는 재귀 단계로 이루어진다. 작은 호출이 정답을 준다고 믿고 지금 단계만 생각한다.
  6. 호출마다 프레임이 호출 스택에 쌓인다. 기본 한도는 1000이고, 깊으면 sys.setrecursionlimit으로 올리되 수만을 넘으면 반복문과 스택으로 바꾼다.
  7. 같은 인자로 반복해서 불리는 재귀는 @cache로 답을 저장해 중복 계산을 없앤다. 피보나치는 지수 시간이 선형 시간으로 줄어든다.
