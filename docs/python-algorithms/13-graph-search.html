본문으로 건너뛰기

그래프와 탐색

지하철 노선도나 친구 관계처럼 점과 선으로 이어진 데이터를 그래프라고 부릅니다. 그래프를 코드로 옮기는 법과, 그 위를 빠짐없이 돌아보는 두 가지 탐색인 DFS와 BFS를 다룹니다.

정점 · 간선인접 리스트DFSBFS격자

이 장에서 배울 것

  • 정점, 간선, 차수, 경로, 사이클, 연결 요소가 무엇인지 설명할 수 있다
  • 간선 목록을 받아 인접 리스트를 만들고, 인접 행렬과 비교해 고를 수 있다
  • DFS를 재귀와 스택 두 가지로 짤 수 있고, 방문 순서가 왜 다를 수 있는지 안다
  • BFS로 간선 수 기준 최단 거리를 구하고, 그것이 왜 최단인지 설명할 수 있다
  • 격자를 그래프로 보고 네 방향 탐색과 경계 검사를 할 수 있다

그래프란

핵심

그래프는 무엇이 무엇과 이어져 있는가만 담는 구조다. 위치나 모양은 상관없고, 연결 관계만 중요하다.

지하철 노선도를 떠올리면 쉽다. 노선도의 역 위치는 실제 지도와 다르지만, 어느 역에서 어느 역으로 가는지는 정확하다. 그래프가 담는 정보가 바로 그것이다.

점을 정점(vertex), 선을 간선(edge)이라 하고, 개수를 V와 E로 적는다.

용어뜻예
무방향 그래프간선 u–v로 양쪽 다 간다친구 관계
방향 그래프u→v가 있어도 v→u는 따로 있어야 한다일방통행, 팔로우
가중치간선에 붙은 비용이나 거리역 사이 소요 시간
차수(degree)한 정점에 붙은 간선 수친구 수
경로(path)간선을 따라 정점을 차례로 지나는 길0 → 1 → 3
사이클(cycle)출발한 정점으로 되돌아오는 경로0 → 1 → 3 → 2 → 0
연결 요소서로 오갈 수 있는 정점끼리 묶은 덩어리아래 그림의 두 덩어리

간선 하나는 양 끝 정점의 차수를 하나씩 올린다. 그래서 무방향 그래프에서 차수의 합은 간선 수의 두 배다(합 10, 간선 5개).

사이클이 있으면 같은 정점에 여러 길로 닿는다. 이미 간 정점을 기억하지 않으면 사이클을 따라 끝없이 돈다. 모든 탐색 코드에 visited가 붙는 이유다.

그래프를 코드로 표현하기

인접 행렬: V × V 표

인접 행렬은 V행 V열짜리 2차원 리스트다. u와 v가 이어져 있으면 matrix[u][v]를 1로 둔다.


n = 6
edges = [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4)]

matrix = [[0] * n for _ in range(n)]
for u, v in edges:
    matrix[u][v] = 1
    matrix[v][u] = 1                  # 무방향이라 양쪽에 표시한다

for row in matrix:
    print(row)
print(matrix[1][3], matrix[1][4])     # 1-3 간선은 있고, 1-4 는 없다

인접 리스트: 정점마다 이웃 목록

인접 리스트는 정점마다 이웃 목록을 둔다. 있는 간선만 적으니 메모리가 V + E에 비례한다.


n = 6
edges = [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4)]

adj = [[] for _ in range(n)]          # [[]] * n 은 같은 리스트를 공유한다 (3장)
for u, v in edges:
    adj[u].append(v)
    adj[v].append(u)                  # 무방향이라 두 번 넣는다

for v in range(n):
    print(v, adj[v], '차수', len(adj[v]))
print(3 in adj[1])                    # 1-3 간선이 있나: 이웃 목록을 훑는다

탐색은 정점마다 이웃을 훑고, 시험의 그래프는 대개 정점이 많고 간선은 그 몇 배뿐이다. 그래서 코딩 테스트에서는 거의 언제나 인접 리스트를 쓴다. 인접 행렬은 V가 수백 이하일 때(14장의 플로이드-워셜) 꺼낸다.

방향과 가중치가 있을 때

방향 그래프는 adj[u].append(v) 한 번만 한다. 가중치가 있으면 adj[u].append((v, w))처럼 튜플을 넣는다(14장). 정점이 이름이면 defaultdict(list)(4장)에 이름을 키로 담는다.

입력에서 그래프 만들기

정점 번호가 1부터면 리스트를 n + 1칸으로 만들고 0번 칸은 비워 둔다.

DFS: 한 길로 끝까지

DFS(깊이 우선 탐색, depth-first search)는 갈 수 있는 데까지 깊이 들어가고, 막히면 바로 전 갈림길로 돌아온다. 미로에서 한 통로를 끝까지 가 보고, 막히면 마지막 갈림길로 돌아가는 것과 같다.

"이웃으로 들어가 같은 일을 반복한다"가 그대로 재귀가 된다(6장). 들어오자마자 방문을 표시해야 사이클을 다시 돌지 않는다.


n = 6
edges = [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4)]
adj = [[] for _ in range(n)]
for u, v in edges:
    adj[u].append(v)
    adj[v].append(u)

visited = [False] * n
order = []


def dfs(v: int) -> None:
    visited[v] = True
    order.append(v)
    for nxt in adj[v]:
        if not visited[nxt]:
            dfs(nxt)                  # 더 깊이 들어간다


dfs(0)
print(order)

[0, 1, 3, 2, 4]

2의 이웃은 모두 방문했으므로 dfs(2)가 끝나고, dfs(3)의 반복문으로 돌아와 4로 간다. "막히면 돌아온다"는 함수가 끝나 호출한 쪽으로 돌아가는 일이다.

스택으로 바꾼 DFS

재귀는 깊이만큼 프레임이 쌓여, 정점이 한 줄로 수천 개 이어지면 RecursionError가 난다(6장). 그럴 때는 호출 스택이 하던 일을 리스트 스택(10장)에 맡긴다.


n = 6
edges = [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4)]
adj = [[] for _ in range(n)]
for u, v in edges:
    adj[u].append(v)
    adj[v].append(u)


def dfs_stack(start: int) -> list[int]:
    visited = [False] * n
    order = []
    stack = [start]
    while stack:
        v = stack.pop()
        if visited[v]:
            continue                  # 같은 정점이 두 번 들어올 수 있다
        visited[v] = True
        order.append(v)
        for nxt in adj[v]:
            if not visited[nxt]:
                stack.append(nxt)
        print(f'방문 {v}, 스택 {stack}')
    return order


print(dfs_stack(0))

방문 3, 스택 [1, 1, 4]
방문 4, 스택 [1, 1]
방문 1, 스택 [1]

순서가 바뀌었다. 스택은 0의 이웃 1, 2 중 나중에 넣은 2를 먼저 꺼내기 때문이다. 둘 다 올바른 DFS다. 재귀와 순서를 맞추려면 reversed(adj[v]) 순서로 넣는다. 그러면 [0, 1, 3, 2, 4]가 나온다.

스택 버전은 꺼낼 때 방문을 표시해서 1이 두 번 들어 있다. 넣을 때 표시하면 "가장 최근 갈림길로 돌아간다"는 순서가 깨질 수 있다. 중복은 많아야 간선 수만큼이라 시간은 그대로 O(V+E)다.

방문하지 않은 정점마다 새 탐색을 시작하면, 시작한 횟수가 연결 요소 수다. 대표 문제가 이 방법을 쓴다.

방향 그래프의 사이클도 재귀 DFS로 찾는다. 정점을 "아직 안 감", "탐색 중(호출이 아직 안 끝남)", "끝남" 세 상태로 나눈다. 이웃을 따라가다 탐색 중인 정점을 다시 만나면, 그 정점에서 나온 길이 자기에게 돌아온 것이라 사이클이다. 끝난 정점을 만나는 것은 다른 길로 먼저 다녀간 것일 뿐이라 사이클이 아니다.

BFS: 가까운 곳부터

BFS(너비 우선 탐색, breadth-first search)는 출발점에서 가까운 정점부터 방문한다. 물에 돌을 던지면 물결이 한 겹씩 퍼지는 것과 같다. 먼저 발견한 정점을 먼저 처리하므로 큐(deque, 7장·11장)를 쓴다.


from collections import deque

n = 6
edges = [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4)]
adj = [[] for _ in range(n)]
for u, v in edges:
    adj[u].append(v)
    adj[v].append(u)


def bfs(start: int) -> list[int]:
    visited = [False] * n
    visited[start] = True
    queue = deque([start])
    order = []
    while queue:
        v = queue.popleft()
        order.append(v)
        for nxt in adj[v]:
            if not visited[nxt]:
                visited[nxt] = True   # 넣는 순간 표시
                queue.append(nxt)
        print(f'방문 {v}, 큐 {list(queue)}')
    return order


print(bfs(0))

방문 0, 큐 [1, 2]
방문 1, 큐 [2, 3]
방문 2, 큐 [3]
방문 3, 큐 [4]
방문 4, 큐 []
[0, 1, 2, 3, 4]

2를 꺼냈을 때 3은 이미 큐에 있고, 넣을 때 표시해 두었으니 다시 넣지 않는다. 이것이 BFS의 가장 중요한 규칙이다. visited는 큐에 넣을 때 표시한다.

dist 배열로 최단 거리 구하기

visited 대신 dist를 쓰면 거리가 함께 나온다. 못 간 정점은 -1로 두고, 넣을 때 "지금 거리 + 1"을 적는다. -1인지 보는 것이 visited 확인이다.


from collections import deque

n = 6
edges = [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4)]
adj = [[] for _ in range(n)]
for u, v in edges:
    adj[u].append(v)
    adj[v].append(u)

start = 0
dist = [-1] * n                       # -1 = 아직 못 감
dist[start] = 0
queue = deque([start])
while queue:
    v = queue.popleft()
    for nxt in adj[v]:
        if dist[nxt] == -1:
            dist[nxt] = dist[v] + 1
            queue.append(nxt)

print(dist)
for d in range(max(dist) + 1):
    print(f'거리 {d}:', [v for v in range(n) if dist[v] == d])

처음 닿은 거리가 왜 최단인가

큐에는 언제나 거리 d인 정점들 뒤에 d + 1인 정점들이 줄 서 있다. 거리 d인 정점이 넣는 이웃은 모두 d + 1이고 줄 맨 뒤에 붙는다. 그래서 층이 한 겹씩 처리된다. 어떤 정점에 d + 1층에서 처음 닿았다면, 더 가까운 층에는 그리 가는 간선이 없었다는 뜻이다. 그래서 BFS는 가까운 층부터 퍼지므로, 처음 닿은 순간의 거리가 간선 수 기준 최단 거리다. 단, 간선 비용이 모두 같을 때만 그렇다. 비용이 다르면 14장의 다익스트라를 쓴다.

격자도 그래프다

미로나 지도 같은 격자 문제도 그래프 문제다. 칸이 정점이고, 상하좌우로 맞닿은 칸 사이가 간선이다. 이웃은 좌표에 네 방향을 더하면 나오므로 인접 리스트는 만들지 않는다.

네 방향은 행 변화량 dr = [-1, 1, 0, 0]과 열 변화량 dc = [0, 0, -1, 1]로 적어 두고 반복문으로 돈다. 새 좌표가 격자 밖이면 버린다. 이것이 경계 검사다. 그래서 모서리 칸은 이웃이 둘, 가장자리 칸은 셋이다.

격자 BFS로 거리 구하기

앞 절의 BFS에서 정점을 좌표 튜플로, dist를 2차원 리스트로 바꾸면 된다. 왼쪽 위 칸에서 각 칸까지의 이동 횟수를 적는다. #은 벽이다.


import sys
from collections import deque

input = sys.stdin.readline

rows, cols = map(int, input().split())
grid = [input().rstrip() for _ in range(rows)]

dr = [-1, 1, 0, 0]
dc = [0, 0, -1, 1]
dist = [[-1] * cols for _ in range(rows)]      # 2차원 visited 겸 거리표
dist[0][0] = 0
queue = deque([(0, 0)])                        # 칸의 좌표가 정점이다

while queue:
    r, c = queue.popleft()
    for k in range(4):
        nr, nc = r + dr[k], c + dc[k]
        if not (0 <= nr < rows and 0 <= nc < cols):
            continue                           # 격자 밖
        if grid[nr][nc] == '#' or dist[nr][nc] != -1:
            continue                           # 벽이거나 이미 본 칸
        dist[nr][nc] = dist[r][c] + 1
        queue.append((nr, nc))

for r in range(rows):
    cells = ['#' if grid[r][c] == '#' else str(dist[r][c])
             for c in range(cols)]
    print(' '.join(f'{cell:>2}' for cell in cells))

오른쪽 위 칸은 벽에 막혀 -1로 남는다. 2차원 리스트를 [[-1] * cols] * rows로 만들면 모든 행이 같은 리스트를 가리키니 컴프리헨션으로 만든다(3장).

방문 표시는 4장처럼 좌표 튜플을 집합에 넣고 (nr, nc) in visited로 확인해도 된다. 크기가 정해진 격자는 2차원 리스트가 더 빠르고, 크기를 모르는 판이라면 집합이 편하다.

DFS와 BFS 고르기

두 탐색은 순서만 다르다. 차이는 순서가 의미를 가질 때 생긴다.

문제가 묻는 것고를 것이유
최단 거리(간선 수, 이동 횟수)BFS가까운 층부터 처리해 처음 닿은 거리가 최단이다
모든 경로, 모든 경우 따지기DFS한 경로를 끝까지 만들고 되돌아온다. 백트래킹(22장)의 뼈대다
연결 요소 세기, 덩어리 크기둘 다이어진 정점을 빠짐없이 보기만 하면 된다
깊이가 수만을 넘을 수 있다BFS 또는 스택 DFS재귀 한도와 호출 스택 메모리를 피한다

둘 다 O(V+E)인 이유

visited 덕분에 정점마다 처리는 한 번이고, 그때 이웃 목록을 한 번 훑는다. 이웃 목록 길이의 합은 무방향이면 2E, 방향이면 E다. 그래서 둘 다 모든 정점과 간선을 한 번씩만 보므로 O(V+E)다.

표현탐색 시간이유
인접 리스트O(V+E)정점 V개와 이웃 목록 총길이 2E
인접 행렬O(V²)정점마다 한 행 V칸을 모두 본다
R × C 격자O(RC)칸이 RC개이고, 칸마다 이웃이 많아야 4개다

공간은 visited와 큐(또는 스택)라서 O(V)다. 꺼낼 때 표시하는 스택 DFS는 스택이 O(E)까지, 재귀 DFS는 호출 스택이 깊이만큼 쌓인다.

자주 하는 실수

BFS에서 꺼낼 때 visited를 표시하기

꺼낼 때 표시하면 큐에서 기다리는 정점을 다른 정점이 또 넣는다. 정점 100개가 모두 이어진 그래프에서 넣은 횟수를 센다.


from collections import deque

n = 100
# 모두가 서로 이어진 그래프
adj = [[v for v in range(n) if v != u] for u in range(n)]


def count_pushes(mark_on_push: bool) -> int:
    visited = [False] * n
    visited[0] = mark_on_push
    queue, pushes = deque([0]), 1
    while queue:
        v = queue.popleft()
        if not mark_on_push:
            if visited[v]:
                continue
            visited[v] = True         # 꺼낼 때 표시
        for nxt in adj[v]:
            if not visited[nxt]:
                visited[nxt] = mark_on_push   # True 면 넣을 때 표시
                queue.append(nxt)
                pushes += 1
    return pushes


print(count_pushes(True))
print(count_pushes(False))

100
4951

정점 수인 100번과 간선 수에 가까운 4951번이다. 큐가 불어 시간과 메모리를 잡아먹고, continue 검사까지 빠뜨리면 중복마다 이웃을 다시 훑어 시간 초과가 난다.

무방향 그래프인데 한쪽만 append

adj[u].append(v)만 하면 방향 그래프 u→v가 되고, 에러는 나지 않는다. 사슬 0–1–2–3에서 0에서 출발하면 맞는 듯 보이지만, 3에서는 아무 데도 못 간다.

재귀 DFS의 깊이 한도

한 줄로 이어진 그래프는 DFS 깊이가 정점 수와 같다. 기본 한도 1000을 넘으면 에러가 난다.


n = 5000
adj = [[] for _ in range(n)]
for v in range(n - 1):                # 0-1-2-…-4999 사슬
    adj[v].append(v + 1)
    adj[v + 1].append(v)

visited = [False] * n


def dfs(v: int) -> None:
    visited[v] = True
    for nxt in adj[v]:
        if not visited[nxt]:
            dfs(nxt)


try:
    dfs(0)
except RecursionError as e:
    print(f'{type(e).__name__}: {e}')

RecursionError: maximum recursion depth exceeded

재귀를 쓴다면 맨 위에 sys.setrecursionlimit(10**6)을 넣는다. 깊이가 수십만까지 갈 수 있으면 BFS나 스택 DFS가 안전하다(6장).

경계 검사 없이 음수 인덱스 쓰기

(0, 0)에서 위로 가면 행이 -1이 되고, 파이썬은 이를 뒤에서부터 센다(3장). 에러 없이 마지막 행을 읽는다.

r, c = 0, 0

접근 방법먼저 생각해 보고 펼치세요

"상하좌우로 맞닿은 칸끼리 하나로 묶는다"는 격자를 그래프로 본 것이다. 땅 칸이 정점, 맞닿은 땅 사이가 간선이다. 그러면 섬 하나는 연결 요소 하나이고, 문제는 연결 요소 세기가 된다.

  1. 지도를 왼쪽 위부터 한 칸씩 훑는다.
  2. 아직 방문하지 않은 땅을 만나면 새 섬을 찾은 것이다. 개수를 하나 늘린다.
  3. 그 칸에서 BFS로 이어진 땅을 모두 표시한다. 같은 섬을 다시 세지 않기 위해서다.
  4. 끝까지 훑은 뒤 개수를 출력한다.

재귀 DFS로도 풀리지만, 지도 전체가 구불구불한 섬 하나면 깊이가 25만까지 간다. 재귀 한도를 피하려고 BFS로 푼다.

풀이 코드 

import sys
from collections import deque

input = sys.stdin.readline


def count_islands(grid: list[str]) -> int:
    rows, cols = len(grid), len(grid[0])
    visited = [[False] * cols for _ in range(rows)]
    dr = [-1, 1, 0, 0]
    dc = [0, 0, -1, 1]

    def flood(sr: int, sc: int) -> None:
        """한 섬에 속한 땅을 모두 표시한다."""
        visited[sr][sc] = True
        queue = deque([(sr, sc)])
        while queue:
            r, c = queue.popleft()
            for k in range(4):
                nr, nc = r + dr[k], c + dc[k]
                if not (0 <= nr < rows and 0 <= nc < cols):
                    continue
                if grid[nr][nc] == '0' or visited[nr][nc]:
                    continue
                visited[nr][nc] = True
                queue.append((nr, nc))

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1' and not visited[r][c]:
                flood(r, c)                     # 처음 보는 땅 = 새 섬
                count += 1
    return count


n, m = map(int, input().split())
grid = [input().rstrip() for _ in range(n)]
print(count_islands(grid))

복잡도
시간
O(NM) 바깥 반복문이 칸마다 한 번, BFS가 땅 칸마다 한 번씩 꺼내 이웃 4칸을 본다. 칸 하나가 두 번 이상 큐에 들어가지 않는다.
공간
O(NM) 지도와 visited가 칸 수만큼이고, 큐도 많아야 칸 수만큼 쌓인다.

격자가 수천 × 수천으로 커지면 칸마다 튜플을 만드는 비용이 먼저 막힌다. 그때는 좌표를 정수 r * cols + c로 담는다.

스스로 확인

정점 10만 개, 간선 20만 개인 그래프를 인접 행렬로 담으면 왜 안 되는가?

인접 행렬은 간선 수와 상관없이 V² = 100억 칸이 필요하다. 인접 리스트는 V + 2E, 약 50만 칸이면 되고 탐색도 O(V+E)다.

같은 그래프에서 재귀 DFS와 스택 DFS의 방문 순서가 다르게 나온 이유는?

재귀는 이웃 목록의 첫 이웃부터 들어가지만, 스택은 마지막에 넣은 이웃을 먼저 꺼내기 때문이다. 둘 다 올바른 DFS이고, 순서를 맞춰야 하면 이웃을 거꾸로(reversed) 넣는다.

BFS에서 어떤 정점에 처음 닿았을 때의 거리가 간선 수 기준 최단 거리인 이유는?

큐 덕분에 거리 d인 정점이 모두 처리된 뒤에야 d + 1인 정점이 처리된다. 더 짧은 길이 있었다면 앞선 층에서 먼저 발견했을 것이다.

격자에서 (0, 3) 칸의 위쪽 이웃을 경계 검사 없이 읽으면 어떻게 되는가?

행이 -1이 되어 에러 없이 마지막 행의 3열 칸을 읽고, 틀린 답이 나온다. 칸을 읽기 전에 0 <= nr < rows를 검사한다.

정리

  1. 그래프는 무엇이 무엇과 이어져 있는가만 담는 구조다. 정점, 간선, 차수, 경로, 사이클, 연결 요소로 말한다.
  2. 코딩 테스트에서는 거의 언제나 인접 리스트를 쓴다. 메모리 O(V+E)이고, 무방향 간선은 양쪽에 두 번 넣는다.
  3. DFS는 갈 수 있는 데까지 깊이 들어가고, 막히면 바로 전 갈림길로 돌아온다. 재귀로 짜되, 깊으면 스택으로 바꾼다.
  4. BFS는 deque로 가까운 곳부터 돈다. visited는 큐에 넣을 때 표시한다.
  5. BFS는 가까운 층부터 퍼지므로, 처음 닿은 순간의 거리가 간선 수 기준 최단 거리다.
  6. 격자는 칸이 정점이고, 상하좌우로 맞닿은 칸 사이가 간선이다. dr, dc로 네 방향을 돌고, 읽기 전에 경계를 검사한다.
  7. DFS와 BFS 둘 다 모든 정점과 간선을 한 번씩만 보므로 O(V+E)다. 최단 거리면 BFS, 모든 경우를 따지면 DFS를 고른다.
