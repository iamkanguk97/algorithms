트라이

사전에서 "ca"로 시작하는 단어를 찾을 때 우리는 c 칸을 펼치고, 그 안에서 다시 a 칸으로 내려갑니다. 트라이는 그 사전을 글자 단위의 트리로 만든 것이라, 접두사에 관한 질문에 단어 길이만큼의 시간으로 답합니다.

접두사노드 = 딕셔너리O(L)is_end자동완성

이 장에서 배울 것

  • 트라이가 글자를 간선으로, 접두사를 루트에서 내려온 길로 담는 구조임을 설명할 수 있다
  • 딕셔너리 자식과 is_end 표시를 가진 노드로 넣기, 찾기, 접두사 확인을 짤 수 있다
  • 트라이 연산이 단어 수와 상관없이 단어 길이 L에 비례하는 이유를 안다
  • set으로 충분한 경우와 트라이가 필요한 경우를 가를 수 있다
  • 접두사 세기, 지우기, 자동완성을 트라이 위에서 구현할 수 있다

트라이란

핵심

트라이는 글자 하나를 간선 하나로 삼아, 같은 접두사를 가진 단어들이 같은 길을 함께 쓰는 트리다.

접두사(prefix)는 단어의 앞부분이다. cart의 접두사는 c, ca, car, cart다. 트라이(trie)는 단어들을 접두사 단위로 쪼개 트리(15장)에 담는다. 이름은 찾기(retrieval)에서 왔고, 트리와 구분하려고 "트라이"로 읽는다.

  • 루트는 빈 문자열이다. 아무 글자도 읽지 않은 상태다.
  • 부모에서 자식으로 내려가는 간선 하나가 글자 하나다.
  • 루트에서 어떤 노드까지 내려온 글자를 이어 붙이면 그 노드가 나타내는 접두사가 된다.

그림 18-1에서 ca로 시작하는 세 단어는 세 번째 글자에서야 갈라진다.

r 노드는 car가 끝나는 곳이면서 cart로 가는 길목이다. 그래서 "여기서 끝나는 단어가 있는가"를 따로 적는다. 이것이 다음 절의 is_end다.

구조만 보면 트라이는 "글자를 키로 하는 딕셔너리 안에 또 딕셔너리"다. 단어 끝은 키 '$'로 표시했다. d.setdefault(k, v)는 키 k가 없으면 v를 넣고, 어느 쪽이든 d[k]를 돌려준다.


def build(words: list[str]) -> dict:
    root: dict = {}
    for word in words:
        node = root
        for ch in word:
            node = node.setdefault(ch, {})
        node['$'] = True
    return root


print(build(['car', 'cart', 'cat', 'dog']))

자식을 딕셔너리로 두는 이유

다른 방법은 알파벳 26칸짜리 리스트다. 칸 번호는 ord(ch) - ord('a')로 구한다(5장). 그런데 트라이의 노드는 아래로 갈수록 자식이 한두 개뿐이라 칸 대부분이 빈다. sys.getsizeof로 재면 26칸 리스트는 264바이트, 키 하나짜리 딕셔너리는 184바이트다.

넣기, 찾기, 접두사 확인

세 연산은 모두 루트에서 글자마다 자식 하나로 내려간다. insert는 길이 끊긴 곳에 새 노드를 만들고 마지막에 is_end를 켠다. search는 끝 노드의 is_end가 답이고, starts_with는 끝까지 내려가기만 하면 True다.


class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_end = False


class Trie:
    def __init__(self) -> None:
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            if ch not in node.children:          # 길이 없으면 새로 낸다
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def _walk(self, text: str) -> TrieNode | None:
        node = self.root
        for ch in text:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node.is_end

    def starts_with(self, prefix: str) -> bool:
        return self._walk(prefix) is not None


trie = Trie()
for word in ['car', 'cart', 'cat', 'dog']:
    trie.insert(word)

print(trie.search('car'), trie.search('ca'), trie.search('cow'))
print(trie.starts_with('ca'), trie.starts_with('do'),
      trie.starts_with('dot'))

True True False

search('ca')는 a 노드에 닿지만 is_end가 꺼져 있어 False다. 두 함수의 차이가 이 확인 하나라서 내려가는 부분을 _walk로 묶었다.

단어 수와 상관없는 이유

길이 L인 단어를 넣거나 찾으면 반복문이 L번 돌고, 한 번에 자식 하나를 찾을 뿐이다(평균 O(1)). 노드에서 다른 단어와 비교하지 않으므로 단어가 10개든 100만 개든 횟수는 그대로다. 트라이 연산은 단어 수가 아니라 단어 길이 L만큼만 걸린다.

접두사로 시작하는 단어 세기

"do로 시작하는 단어가 몇 개인가"는 do 노드 아래를 훑어 세도 되지만, 질문이 많으면 그 비용이 쌓인다. 대신 노드마다 count를 두고, 단어를 넣으며 지나가는 노드마다 1씩 늘린다. 어떤 노드를 지나간 단어는 정확히 그 노드의 접두사로 시작하는 단어다. 그래서 노드마다 지나간 단어 수를 적어 두면, 접두사로 시작하는 단어 수는 접두사 노드에 이미 적혀 있다.


class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_end = False
        self.count = 0              # 이 노드를 지나간 단어 수


def insert(root: TrieNode, word: str) -> None:
    node = root
    for ch in word:
        node = node.children.setdefault(ch, TrieNode())
        node.count += 1
    node.is_end = True


def count_prefix(root: TrieNode, prefix: str) -> int:
    node = root
    for ch in prefix:
        if ch not in node.children:
            return 0
        node = node.children[ch]
    return node.count


root = TrieNode()
for word in ['car', 'cart', 'cat', 'dog', 'door', 'dot']:
    insert(root, word)
print([count_prefix(root, p) for p in ['ca', 'car', 'do', 'doo', 'x']])

[3, 2, 3, 1, 0]

질문 하나는 접두사만큼 내려가 숫자를 읽으면 끝나므로 O(L)이다. 같은 단어를 두 번 넣으면 두 번 세는 점은 주의한다.

set·dict와 비교

"단어가 있나"는 set도 O(L)이다

word in words는 흔히 O(1)이라고 하지만, 해시값 계산과 글자 비교에 글자 수만큼 걸린다(12장). 그러니 "이 단어가 있나"는 둘 다 O(L)이고, C로 구현된 set이 훨씬 빠르다.

차이는 접두사를 물을 때 생긴다. set은 단어를 통째로 해시하므로 any(w.startswith('ca') for w in words)처럼 모든 단어를 훑어야 한다. 접두사를 전부 잘라 Counter(4장)에 세어 두면 빠르지만, 단어 하나가 1 + 2 + … + L글자를 만들어 공간이 O(L²)이다.

트라이가 이기는 질문들

트라이는 같은 접두사를 한 벌만 저장한다. interval, internet, internal, interview는 모두 33글자지만 트라이 노드는 루트를 빼고 16개다. 가장 긴 공통 접두사는 갈림길이 나올 때까지 내려가면 된다.


class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_end = False


def longest_common_prefix(words: list[str]) -> str:
    root = TrieNode()
    for word in words:
        node = root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_end = True

    prefix = []
    node = root
    while len(node.children) == 1 and not node.is_end:   # 갈림길 전까지
        ch, node = next(iter(node.children.items()))
        prefix.append(ch)
    return ''.join(prefix)


words = ['interval', 'internet', 'internal', 'interview']
print(longest_common_prefix(words))
print(repr(longest_common_prefix(['car', 'dog'])))

지우기와 자동완성

지우기: 내려갔다 올라오며 떼어 내기

끝 노드의 is_end를 끄면 search는 그 단어를 찾지 못하지만, 아무 단어도 쓰지 않는 노드가 남는다. 자식이 있거나 끝 표시가 있는 노드는 다른 단어가 쓰므로 남긴다. 자식을 먼저 떼어 내야 부모가 "자식 없음"이 되므로, 재귀로 끝까지 내려간 뒤 돌아오는 길에 판단한다. 자식도 없고 끝 표시도 없는 노드만 떼어 낸다.


class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_end = False


def insert(root: TrieNode, word: str) -> None:
    node = root
    for ch in word:
        node = node.children.setdefault(ch, TrieNode())
    node.is_end = True


def delete(node: TrieNode, word: str, depth: int = 0) -> bool:
    """word 를 지운다. node 를 부모에서 떼어 내도 되면 True."""
    if depth == len(word):
        node.is_end = False
    else:
        ch = word[depth]
        child = node.children.get(ch)
        if child is None:                           # 없는 단어
            return False
        if delete(child, word, depth + 1):          # 돌아오는 길에
            del node.children[ch]                   # 빈 자식을 떼어 낸다
    return not node.children and not node.is_end

for word in ['car', 'cart', 'cat']:
    insert(root, word)
a = root.children['c'].children['a']

delete(root, 'cart')
print(list(a.children['r'].children), a.children['r'].is_end)
delete(root, 'car')
print(list(a.children))

자동완성: 접두사 노드에서 DFS

자동완성은 접두사 노드까지 내려간 뒤, 그 아래를 DFS(13장)로 훑으며 is_end인 노드의 단어를 모으는 일이다. 자식을 sorted(children) 순서로 방문하면 앞선 글자의 서브트리를 먼저 다 훑으므로 단어가 사전순으로 모인다.


class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_end = False


def insert(root: TrieNode, word: str) -> None:
    node = root
    for ch in word:
        node = node.children.setdefault(ch, TrieNode())
    node.is_end = True


def autocomplete(root: TrieNode, prefix: str) -> list[str]:
    node = root
    for ch in prefix:                       # 1) 접두사 노드까지 내려간다
        if ch not in node.children:
            return []
        node = node.children[ch]

    found: list[str] = []
    path = list(prefix)

    def collect(current: TrieNode) -> None:  # 2) 그 아래를 DFS 로 훑는다
        if current.is_end:
            found.append(''.join(path))
        for ch in sorted(current.children):
            path.append(ch)
            collect(current.children[ch])
            path.pop()

    collect(node)
    return found


root = TrieNode()
for word in ['tea', 'ten', 'to', 'tree', 'trie', 'try', 'team', 'tent']:
    insert(root, word)

print(autocomplete(root, 'te'))
print(autocomplete(root, 'tr'))

['tea', 'team', 'ten', 'tent']
['tree', 'trie', 'try']

tea가 team보다 앞인 것은 a 노드에서 단어를 먼저 담은 뒤에 자식으로 내려가기 때문이다. path는 내려온 글자를 담는 스택이다. 후보를 몇 개만 보여 주려면 found가 차면 멈춘다.

전화번호 목록의 접두사 충돌

사내 단축 다이얼은 누르는 도중 등록된 번호와 같아지면 바로 전화를 건다. 31과 3172가 함께 있으면 3172로는 걸 수 없다. 번호 목록마다, 어떤 번호도 다른 번호의 접두사가 아니면 YES, 아니면 NO를 한 줄에 하나씩 출력하라.

첫 줄에 목록 수 t(1 ≤ t ≤ 50)가 주어진다. 목록마다 첫 줄에 번호 수 n(1 ≤ n ≤ 10,000)이, 다음 n줄에 번호가 하나씩 주어진다. 번호는 숫자로만 된 길이 1~10의 문자열이고, 한 목록 안의 번호는 모두 다르다.

번호 쌍을 모두 비교하면 n이 1만일 때 5천만 쌍이라 느리다. 트라이로 보면 "A가 B의 접두사인가"는 곧 B를 따라 내려가는 길 위에 A가 끝나는 노드가 있는가다.

  1. 번호를 하나씩 넣고, 번호 끝 노드에 is_end를 켠다.
  2. 내려가는 도중 is_end인 노드를 만나면, 먼저 넣은 짧은 번호가 지금 번호의 접두사다. 바로 NO다.
  3. 긴 번호가 먼저 들어가 있을 수도 있다. 다 넣은 마지막 노드에 이미 자식이 있으면 지금 번호가 앞선 번호의 접두사다. 두 경우를 다 보므로 넣는 순서와 상관없이 잡힌다.

다른 길도 있다. 문자열로 정렬하면 접두사 관계인 번호가 바로 이웃하므로(19장), 이웃끼리만 b.startswith(a)로 확인해도 된다.

풀이 코드 

import sys

input = sys.stdin.readline


class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_end = False


def insert_and_check(root: TrieNode, number: str) -> bool:
    """number 를 넣는다. 접두사 충돌이 생기면 False."""
    node = root
    for digit in number:
        if node.is_end:                    # 앞선 번호가 내 접두사다
            return False
        node = node.children.setdefault(digit, TrieNode())
    if node.children:                      # 내가 앞선 번호의 접두사다
        return False
    node.is_end = True
    return True


def is_consistent(numbers: list[str]) -> bool:
    root = TrieNode()
    return all(insert_and_check(root, num) for num in numbers)


t = int(input())
answers = []
for _ in range(t):
    n = int(input())
    numbers = [input().strip() for _ in range(n)]   # '\n' 을 지운다
    answers.append('YES' if is_consistent(numbers) else 'NO')
print('\n'.join(answers))

복잡도
시간
O(n·L) 번호 n개를 길이 L(≤ 10)만큼 내려가며 넣는다.
공간
O(n·L) 노드 수는 목록의 전체 숫자 수, 최대 10만 개를 넘지 않는다.

시간보다 메모리가 먼저 빠듯해진다. 메모리 제한이 작으면 정렬 후 이웃끼리 비교(O(n log n · L))하는 편이 안전하다.

스스로 확인

car, cart, cat, dog가 든 트라이에서 search('ca')는 False인데 starts_with('ca')는 True인 이유는?

둘 다 c, a를 따라 같은 노드에 닿는다. starts_with는 길이 있기만 하면 True지만, search는 그 노드의 is_end까지 본다. ca로 끝나는 단어는 넣은 적이 없어 꺼져 있다.

단어 100만 개가 든 트라이와 10개가 든 트라이에서, 길이 5인 단어를 찾는 시간은 어떻게 다른가?

거의 같다. 자식 하나로 내려가는 일을 5번 할 뿐, 다른 단어와 비교하지 않는다. 시간은 O(L)이다.

"이 단어가 목록에 있나"만 수없이 묻는 문제에 트라이를 쓸 필요가 있는가?

없다. set도 O(L)이고, C로 구현되어 더 빠르며 메모리도 적게 쓴다. 트라이는 접두사를 물을 때 꺼낸다.

car와 cart가 든 트라이에서 car를 지우면 어떤 노드가 떨어지는가?

아무 노드도 떨어지지 않고 r 노드의 is_end만 꺼진다. r에는 cart로 가는 자식 t가 있어 "자식도 없고 끝 표시도 없는 노드"가 아니기 때문이다.

정리

  1. 트라이는 글자 하나를 간선 하나로 삼아, 같은 접두사를 가진 단어들이 같은 길을 함께 쓰는 트리다.
  2. 노드는 자식 딕셔너리 children과 is_end만 가진다. 노드가 있다고 단어가 있는 것은 아니다. 단어의 끝은 is_end로 따로 표시한다.
  3. 넣기, 찾기, 접두사 확인은 모두 루트에서 글자마다 한 칸씩 내려가는 일이다. 트라이 연산은 단어 수가 아니라 단어 길이 L만큼만 걸린다.
  4. 노드마다 지나간 단어 수를 적어 두면, 접두사로 시작하는 단어 수는 접두사 노드에 이미 적혀 있다.
  5. "이 단어가 있나"만 묻는다면 set이면 충분하다. 트라이는 접두사 질의, 사전순 나열, 가장 긴 공통 접두사에서 이긴다.
  6. 지우기는 재귀로 내려갔다 올라오며 자식도 없고 끝 표시도 없는 노드만 떼어 낸다. 자동완성은 접두사 노드에서 sorted(children) 순서로 DFS 한다.
  7. 노드 하나가 무거우니 글자 수가 크면 메모리를 먼저 어림한다. 입력은 strip() 등으로 정규화한다.
