본문으로 건너뛰기

투 포인터와 슬라이딩 윈도우

배열 위의 두 위치를 앞으로만 움직이며 한 번에 훑는 기법입니다. 중첩 반복문으로 O(n²)이 걸리던 쌍 찾기와 구간 문제를 O(n)으로 줄입니다.

투 포인터양끝 포인터고정 창가변 창O(n)

이 장에서 배울 것

  • 두 포인터가 되돌아가지 않으면 왜 O(n)이 되는지 설명할 수 있다
  • 같은 방향 포인터와 양끝 포인터를 문제에 맞게 고를 수 있다
  • 고정 길이 창의 합을 더하고 빼기로 갱신할 수 있다
  • 가변 길이 창을 늘리고 줄이며 최소·최대 길이를 구할 수 있다
  • 음수가 섞이거나 정렬이 안 된 경우처럼 이 기법이 통하지 않는 때를 안다

왜 두 위치인가

핵심

두 위치가 각각 앞으로만 움직이면 둘이 합쳐 많아야 2n번 움직이므로, O(n²)이던 탐색이 O(n)이 된다.

포인터는 여기서 "배열의 몇 번 칸을 보고 있는지"를 담은 인덱스 변수다. 투 포인터는 이런 변수 두 개를 두고, 조건에 따라 한쪽씩 움직이는 기법이다.

정렬된 배열에서 합이 14인 두 수를 찾는다고 하자. 가장 쉬운 방법은 모든 쌍을 보는 중첩 반복이다.


def find_pair_nested(a: list[int], target: int):
    compared = 0
    for i in range(len(a)):
        for j in range(i + 1, len(a)):
            compared += 1
            if a[i] + a[j] == target:
                return (a[i], a[j]), compared
    return None, compared


a = [1, 3, 6, 8, 11, 15]
print(find_pair_nested(a, 14))
print(find_pair_nested(a, 100))

((3, 11), 8)
(None, 15)

답이 없으면 n(n-1)/2개의 쌍을 모두 본다. 원소가 10만 개면 약 50억 번이다. 중첩 반복이 느린 진짜 이유는 j가 i가 바뀔 때마다 처음부터 다시 시작한다는 데 있다. 뒤로 돌아갈 필요가 없다는 근거만 찾으면, 두 인덱스를 각자 한 방향으로만 보내도 된다.

방식안쪽 인덱스의 움직임전체 이동 횟수시간
중첩 반복바깥이 바뀔 때마다 처음으로 돌아간다약 n²/2O(n²)
투 포인터되돌아가지 않는다많아야 2nO(n)

투 포인터의 모양은 두 가지다. 두 포인터가 같은 방향으로 가는 경우(2절, 4~5절의 창)와, 양 끝에서 서로를 향해 오는 경우(3절)다. 문제에서 다음 말이 보이면 먼저 떠올린다.

  • 정렬된 배열에서 조건을 만족하는 두 수를 찾는다 → 양끝 포인터
  • 정렬된 리스트 두 개를 한 번에 훑는다 → 같은 방향 포인터
  • 연속한 구간의 합·개수·길이를 묻고, n이 10만 이상이다 → 슬라이딩 윈도우

같은 방향 두 포인터

정렬된 리스트 두 개를 하나로 합치는 문제가 가장 기본적인 예다. 각 리스트에 포인터를 하나씩 두고, 두 포인터가 가리키는 값 중 작은 쪽을 꺼내 결과에 붙인 뒤 그 포인터만 한 칸 옮긴다.


def merge(a: list[int], b: list[int]) -> list[int]:
    i = j = 0
    merged = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            merged.append(a[i])
            i += 1
        else:
            merged.append(b[j])
            j += 1
    merged.extend(a[i:])     # 남은 쪽은 이미 정렬돼 있다
    merged.extend(b[j:])
    return merged


print(merge([1, 4, 9], [2, 3, 10, 12]))
print(merge([], [5, 6]))

[1, 2, 3, 4, 9, 10, 12]
[5, 6]

매 반복에서 i나 j 중 하나가 반드시 한 칸 나아가므로, 길이가 n, m이면 O(n + m)이다. 이 함수가 19장 병합 정렬의 "합치기" 단계다.

읽는 포인터와 쓰는 포인터

한 리스트 안에서도 두 포인터를 쓸 수 있다. 정렬된 리스트에서 중복을 제자리에서 지울 때, read는 모든 칸을 읽고 write는 남길 값을 쓸 다음 자리를 가리킨다.


def dedupe_sorted(a: list[int]) -> int:
    if not a:
        return 0
    write = 1
    for read in range(1, len(a)):
        if a[read] != a[write - 1]:   # 마지막으로 남긴 값과 다르면
            a[write] = a[read]
            write += 1
    return write                      # 앞의 write 칸이 결과다


nums = [1, 1, 2, 3, 3, 3, 5]
n = dedupe_sorted(nums)
print(n, nums[:n])

4 [1, 2, 3, 5]

정렬돼 있으니 같은 값은 붙어 있고, 마지막으로 남긴 값 하나와만 비교하면 된다. write는 read를 앞지르지 않으므로 아직 읽지 않은 칸을 덮어쓰지 않는다.

양끝 포인터

다시 정렬된 배열에서 합이 목표인 두 수를 찾아 보자. 이번에는 lo를 맨 앞에, hi를 맨 뒤에 두고 두 값의 합을 본다.

  • 합이 목표보다 크면 합을 줄여야 하니 hi를 왼쪽으로 옮긴다.
  • 합이 목표보다 작으면 합을 키워야 하니 lo를 오른쪽으로 옮긴다.
  • 같으면 찾았다. lo와 hi가 만나면 답이 없다.

def find_pair(a: list[int], target: int):
    lo, hi = 0, len(a) - 1
    compared = 0
    while lo < hi:                 # 같은 칸을 두 번 쓰지 않는다
        compared += 1
        total = a[lo] + a[hi]
        if total == target:
            return (a[lo], a[hi]), compared
        if total < target:
            lo += 1
        else:
            hi -= 1
    return None, compared


a = [1, 3, 6, 8, 11, 15]
print(find_pair(a, 14))
print(find_pair(a, 100))

((3, 11), 3)
(None, 5)

답이 없을 때 비교 횟수가 15번에서 5번으로 줄었다. 매번 lo와 hi 사이가 한 칸 좁아지므로 많아야 n-1번이다.

버린 값을 다시 볼 필요가 없는 이유는 정렬에 있다. 1 + 15가 이미 목표보다 크다면, 15는 1보다 큰 어떤 값과 짝지어도 더 커질 뿐이다. 그러니 15가 들어간 쌍은 전부 답이 될 수 없고, hi를 옮겨 15를 버려도 놓치는 답이 없다. 작은 쪽도 마찬가지다. 이 "한쪽을 통째로 버릴 수 있다"는 판단이 포인터가 되돌아가지 않아도 되는 근거다.

고정 길이 창

같은 방향 투 포인터의 두 끝 사이를 하나의 구간으로 보면 슬라이딩 윈도우(sliding window)가 된다. 창문을 옆으로 밀듯 구간을 한 칸씩 옮기며 본다는 뜻이다. 창의 길이가 k로 정해져 있으면 고정 창이다.

길이 k인 구간의 합 중 최댓값을 구해 보자. 창을 한 칸 옮길 때 바뀌는 것은 오른쪽에 새로 들어오는 값 하나와 왼쪽에서 빠지는 값 하나뿐이다. 그러니 합을 처음부터 다시 구하지 않고 더하고 빼기만 한다.


a = [2, 5, 1, 8, 3, 7]
k = 3

window = sum(a[:k])                 # 첫 창만 직접 더한다
best = window
print(f'[0, {k - 1}] 합 {window}')
for right in range(k, len(a)):
    window += a[right] - a[right - k]   # 들어온 값 더하고, 빠진 값 빼고
    best = max(best, window)
    print(f'[{right - k + 1}, {right}] 합 {window}')
print(best)

[0, 2] 합 8
[1, 3] 합 14
[2, 4] 합 12
[3, 5] 합 18
18

첫 창에 O(k), 이후 한 칸마다 O(1)이라 전체 O(n)이다. 같은 문제를 23장의 누적합으로도 O(n)에 풀 수 있다. 질의가 여러 번이면 누적합이, 창을 한 번 훑으면 되면 이 방식이 간단하다.

합이 아닌 상태를 들고 다니기

창이 들고 다니는 값은 합이 아니어도 된다. 들어온 값을 반영하고 빠진 값을 되돌릴 수만 있으면 된다. 길이 k인 창마다 서로 다른 값이 몇 종류인지 세려면 값별 개수를 딕셔너리(4장)에 담는다. 개수가 0이 된 키를 지워야 len이 종류 수가 된다.


from collections import Counter


def distinct_counts(a: list[int], k: int) -> list[int]:
    counts = Counter(a[:k])
    result = [len(counts)]
    for right in range(k, len(a)):
        counts[a[right]] += 1            # 들어온 값
        out = a[right - k]
        counts[out] -= 1                 # 빠진 값
        if counts[out] == 0:
            del counts[out]              # 0 개짜리 키를 남기지 않는다
        result.append(len(counts))
    return result


print(distinct_counts([1, 2, 1, 3, 3, 2, 2], 3))

[2, 3, 2, 2, 2]

가변 길이 창

창의 길이가 정해져 있지 않을 때도 있다. "양의 정수 배열에서 합이 S 이상인 가장 짧은 구간"이 대표적이다. 이때 창은 두 동작을 번갈아 한다.

  • 늘리기 — right를 한 칸 옮겨 값을 더한다.
  • 줄이기 — 합이 S 이상인 동안 답을 기록하고 left를 옮겨 값을 뺀다.

줄이기를 while로 반복한다는 점이 중요하다. 한 번 늘렸을 때 여러 칸을 줄여야 할 수도 있다.


def min_length_at_least(a: list[int], s: int) -> int:
    best = 0                       # 0 은 "아직 못 찾음"
    window = 0
    left = 0
    for right in range(len(a)):
        window += a[right]                 # 늘리기
        while window >= s:                 # 조건을 만족하는 동안 줄이기
            length = right - left + 1
            if best == 0 or length < best:
                best = length
            window -= a[left]
            left += 1
        print(f'right={right} 창=[{left}, {right}] 합={window} 최소={best}')
    return best


print(min_length_at_least([2, 1, 4, 3, 1, 5, 4], 8))

right=1 창=[0, 1] 합=3 최소=0
right=2 창=[0, 2] 합=7 최소=0
right=3 창=[2, 3] 합=7 최소=3
right=4 창=[3, 4] 합=4 최소=3
right=5 창=[4, 5] 합=6 최소=3

while이 for 안에 있어 O(n²)처럼 보이지만 그렇지 않다. left는 전체 실행 동안 0에서 n까지 한 방향으로만 가므로, while 본문은 모두 합쳐 많아야 n번 돈다. right의 n번과 더해 O(n)이다.

서로 다른 문자로만 된 가장 긴 부분 문자열

창 안의 상태를 합 대신 집합(4장)으로 들고 있을 수도 있다. 새 문자가 이미 창 안에 있으면, 그 문자가 빠질 때까지 왼쪽을 줄인다. 집합의 in, add, remove는 평균 O(1)이다.


def longest_unique(s: str) -> int:
    seen = set()
    best = 0
    left = 0
    for right, ch in enumerate(s):
        while ch in seen:            # 겹치는 문자가 빠질 때까지 줄인다
            seen.remove(s[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best


print(longest_unique('bananas'))
print(longest_unique('coding'))
print(longest_unique('aaaa'))

3
6
1

최소 길이를 구할 때는 "조건을 만족하는 동안" 줄이며 답을 기록하고, 최대 길이를 구할 때는 "조건이 깨진 동안" 줄인 뒤 답을 기록한다. 줄이는 조건과 답을 기록하는 위치가 반대라는 점만 기억하면 두 모양 모두 같은 틀이다.

가변 창의 뼈대

for right로 한 칸 늘려 상태에 반영한다 → while 줄여야 하는 동안 a[left]를 상태에서 빼고 left += 1 → 답을 갱신한다. 문제마다 바뀌는 것은 "상태"(합, 집합, 개수 딕셔너리)와 while의 조건, 답을 갱신하는 자리 셋뿐이다.

언제 안 되는가

투 포인터는 "한쪽으로 옮기면 값이 한 방향으로만 변한다"는 성질, 즉 단조성에 기대고 있다. 가변 창에서는 창을 늘리면 합이 커지고 줄이면 작아진다는 것이 그 성질이다. 배열에 음수가 섞이면 이 성질이 깨진다.


def min_length_window(a: list[int], s: int) -> int:
    best = 0
    window = 0
    left = 0
    for right in range(len(a)):
        window += a[right]
        while window >= s:
            if best == 0 or right - left + 1 < best:
                best = right - left + 1
            window -= a[left]
            left += 1
    return best


def min_length_brute(a: list[int], s: int) -> int:
    best = 0
    for i in range(len(a)):
        total = 0
        for j in range(i, len(a)):
            total += a[j]
            if total >= s and (best == 0 or j - i + 1 < best):
                best = j - i + 1
    return best


a = [3, -5, 7, 1]
print(min_length_window(a, 7), min_length_brute(a, 7))

0 1

답은 [7] 하나로 길이 1인데, 창은 0을 낸다. 창이 [3, -5, 7]일 때 합은 5라서 줄이지 않는다. 그런데 실제로는 왼쪽의 3과 -5를 빼야 합이 7로 커진다. 줄이면 합이 커질 수도 있으니 "합이 모자라면 늘린다"는 판단이 틀린 것이다. 음수가 있는 구간 합 문제는 23장의 누적합과 다른 방법으로 푼다.

문제 모양정렬이유
합이 목표인 두 수 (양끝 포인터)필요하다정렬돼야 한쪽을 통째로 버릴 수 있다. 정렬에 O(n log n)이 든다
연속 구간의 합·길이 (창)하면 안 된다정렬하면 "연속"이라는 조건이 사라져 다른 문제가 된다
정렬된 두 리스트 합치기이미 돼 있어야 한다입력이 정렬돼 있다는 전제로 작은 값부터 꺼낸다

두 수의 합 문제에서 원래 위치를 답해야 한다면, 정렬하면 위치가 섞인다. 정렬하기 전에 (값, 인덱스) 튜플로 묶어 두면 튜플은 첫 값부터 비교되므로 값 순서로 정렬되고(3장), 원래 인덱스는 함께 따라온다.


def find_pair_index(a: list[int], target: int):
    items = sorted((value, i) for i, value in enumerate(a))
    lo, hi = 0, len(items) - 1
    while lo < hi:
        total = items[lo][0] + items[hi][0]
        if total == target:
            return sorted((items[lo][1], items[hi][1]))
        if total < target:
            lo += 1
        else:
            hi -= 1
    return None


print(find_pair_index([8, 15, 3, 11, 1, 6], 14))

[2, 3]

정렬 없이 풀고 싶다면 지나온 값을 집합에 넣고 target - x가 있는지 보는 O(n) 방법(4장)도 있다. 투 포인터는 정렬이 이미 돼 있거나, 쌍을 여러 개 세야 할 때 더 빛난다.

자주 하는 실수

창을 줄이는 while을 if로 쓰기

한 번 늘릴 때 한 칸만 줄이면, 여러 칸을 줄일 수 있는 순간을 놓쳐 더 짧은 답을 찾지 못한다.


def min_length_wrong(a: list[int], s: int) -> int:
    best = 0
    window = 0
    left = 0
    for right in range(len(a)):
        window += a[right]
        if window >= s:                # while 이어야 한다
            if best == 0 or right - left + 1 < best:
                best = right - left + 1
            window -= a[left]
            left += 1
    return best


print(min_length_wrong([2, 1, 4, 3, 1, 5, 4], 8))   # 2 를 기대했다

4

창이 한 번 길이 4가 된 뒤로는 한 칸 늘고 한 칸 줄기만 해서 길이가 4에 머문다. while로 바꾸면 2가 나온다.

포인터 이동 조건을 뒤바꾸기

양끝 포인터에서 합이 작은데 hi를 줄이면 합이 더 작아져 답을 지나친다. "작으면 lo를 키우고, 크면 hi를 줄인다"를 그림 21-1처럼 한 번 손으로 따라가 보고 쓴다.

빈 창과 끝 처리

답이 없을 때 무엇을 출력할지 정한다. 최솟값을 float('inf')로 시작했다면 끝에서 0으로 바꾸는 것을 잊지 않는다. 양끝 포인터는 while lo < hi로 써야 한 원소를 두 번 쓰지 않는다. 합치기에서는 반복이 끝난 뒤 남은 원소를 붙이는 줄을 빠뜨리기 쉽다.

슬라이스로 합을 다시 구하기

창을 옮길 때마다 sum(a[i:i + k])를 부르면 슬라이스가 k칸을 복사하고(3장) sum이 다시 k칸을 더한다. 한 칸에 O(k), 전체 O(nk)라 k가 n에 가까우면 O(n²)이다.


best = max(sum(a[i:i + k]) for i in range(len(a) - k + 1))   # O(nk)

대표 문제

Problem보통슬라이딩 윈도우

짧은 구간 찾기

양의 정수 N개로 된 수열과 정수 S가 주어진다. 연속한 원소들의 합이 S 이상인 구간 중 가장 짧은 구간의 길이를 출력하라. 그런 구간이 없으면 0을 출력하라.

첫 줄에 N과 S가 주어진다(1 ≤ N ≤ 100,000, 1 ≤ S ≤ 1,000,000,000). 둘째 줄에 수열의 원소 N개가 공백으로 구분되어 주어진다. 각 원소는 1 이상 10,000 이하이다.

입력출력설명
7 12
4 2 6 1 3 7 5		27 + 5 = 12가 가장 짧다
4 5
1 6 2 1		16 하나로 충분하다
3 10
1 2 3		0전체 합이 6이라 만들 수 없다
접근 방법먼저 생각해 보고 펼치세요

원소가 모두 양수라서 창을 늘리면 합이 커지고, 줄이면 합이 작아진다. 그래서 왼쪽 끝은 되돌아갈 필요가 없고 가변 창으로 O(n)에 풀린다. 모든 구간을 보면 약 50억 쌍이라 시간 안에 끝나지 않는다.

  1. right를 0부터 한 칸씩 옮기며 창의 합에 더한다.
  2. 합이 S 이상인 동안, 현재 길이 right - left + 1로 최솟값을 갱신하고 a[left]를 빼며 left를 옮긴다.
  3. 끝까지 돈 뒤 한 번도 갱신되지 않았다면 0을 출력한다.
풀이 코드 

import sys

input = sys.stdin.readline

n, s = map(int, input().split())
a = list(map(int, input().split()))

best = 0                    # 0 은 아직 못 찾았다는 뜻이자, 답이 없을 때의 출력
window = 0
left = 0
for right in range(n):
    window += a[right]
    while window >= s:
        length = right - left + 1
        if best == 0 or length < best:
            best = length
        window -= a[left]
        left += 1

print(best)

길이는 1 이상이라 0을 "못 찾음" 표시로 겸해 쓸 수 있다. 덕분에 끝에서 따로 바꿀 필요가 없다. 원소가 하나뿐인 창이 S 이상이면 left가 right + 1이 되어 창이 빈다. 이때 합은 0이라 while이 저절로 멈춘다.

시간
O(n) right와 left가 각각 많아야 n번 움직인다.
공간
O(n) 입력 리스트를 저장한다. 창 자체는 합 하나와 인덱스 둘만 쓴다.

스스로 확인

정렬된 배열의 양끝 포인터에서 a[lo] + a[hi]가 목표보다 크면 왜 hi를 옮겨도 답을 놓치지 않는가?

남은 후보 중 가장 작은 a[lo]와 짝지어도 이미 목표보다 크므로, a[hi]가 들어간 다른 쌍은 모두 더 크다. a[hi]는 어떤 답에도 들어갈 수 없어 버려도 된다.

길이 k인 창을 한 칸 옮길 때 합을 어떻게 갱신하고, 그 비용은 얼마인가?

새로 들어온 a[right]를 더하고 빠지는 a[right - k]를 뺀다. 한 칸에 O(1)이고, 처음 창의 합만 O(k)로 구하므로 전체 O(n)이다.

가변 창 코드는 for 안에 while이 있는데도 왜 O(n)인가?

while 한 번에 left가 한 칸 나아가고, left는 전체 실행 동안 되돌아가지 않으며 n을 넘지 않는다. 그래서 while 본문은 모두 합쳐 많아야 n번 돌고, for의 n번과 더해 O(n)이다.

배열에 음수가 섞이면 "합이 S 이상인 가장 짧은 구간"을 가변 창으로 풀 수 없는 이유는?

창을 줄이면 합이 작아진다는 성질이 깨지기 때문이다. 왼쪽의 음수를 빼면 오히려 합이 커질 수 있는데, 창은 합이 모자라면 줄이지 않으므로 그 구간을 보지 못한다.

정리

  1. 두 포인터가 각각 앞으로만 움직이면 이동은 모두 합쳐 많아야 2n번이라 O(n)이다.
  2. 포인터가 되돌아가지 않아도 되는 근거, 즉 "버린 쪽에는 답이 없다"는 판단이 서야 투 포인터를 쓸 수 있다.
  3. 같은 방향 포인터는 정렬된 리스트 합치기와 제자리 중복 제거에 쓴다.
  4. 양끝 포인터는 정렬된 배열에서 합이 작으면 lo를, 크면 hi를 옮긴다.
  5. 고정 창은 들어온 값을 더하고 빠진 값을 빼서 갱신한다. 슬라이스로 다시 더하면 O(nk)가 된다.
  6. 가변 창은 right로 늘리고 while로 left를 줄인다. 원소가 모두 양수일 때처럼 단조성이 있어야 맞다.
