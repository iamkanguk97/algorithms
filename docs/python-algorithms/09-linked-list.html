본문으로 건너뛰기

연결 리스트

원소를 메모리에 붙여 두지 않고, 원소마다 "다음 원소가 어디 있는지"를 들려 줄줄이 잇는 자료구조입니다. 파이썬 코딩 테스트에서 직접 만들 일은 드물지만, 다음을 가리키는 연결을 옮기고 다시 잇는 감각은 트리와 그래프까지 그대로 이어집니다.

노드 · next삽입 O(1)더미 머리빠른·느린 포인터뒤집기

이 장에서 배울 것

  • 연결 리스트가 배열과 어떻게 다르고, 그래서 어떤 연산이 빠르고 느린지 설명할 수 있다
  • 노드를 만들고 head부터 끝까지 순회할 수 있다
  • 노드를 넣고 지울 때 연결을 바꾸는 순서가 왜 중요한지 안다
  • 더미 머리와 빠른·느린 포인터로 경계 처리, 가운데 찾기, 사이클 판별을 할 수 있다
  • 연결 리스트를 새 노드 없이 제자리에서 뒤집을 수 있다

연결 리스트란

핵심

연결 리스트는 각 노드가 다음 노드의 위치를 들고 있어서, 앞에서부터 줄을 따라가야만 원소에 닿는 자료구조다. 대신 자리만 알면 이웃 노드 하나만 고쳐서 넣고 뺄 수 있다.

배열(8장)은 칸이 메모리에 빈틈없이 붙어 있어서 "시작 위치 + 칸 크기 × 인덱스"로 원하는 칸에 바로 간다. 연결 리스트의 원소는 메모리 여기저기에 흩어져 있다. 위치를 계산할 방법이 없으니, 각 원소가 다음 원소의 위치를 직접 적어 둔다.

보물찾기 쪽지를 떠올리면 쉽다. 쪽지마다 다음 쪽지의 위치가 적혀 있어서, 세 번째 쪽지를 보려면 첫 쪽지부터 따라가야 한다. 대신 쪽지 하나를 끼워 넣을 때는 앞 쪽지의 글만 고치면 된다.

쪽지 하나에 해당하는 것을 노드(node)라고 한다. 노드는 값(val)과 다음 노드를 가리키는 next를 담는다. 첫 노드를 가리키는 이름을 head라 하고, 마지막 노드의 next는 "다음이 없다"는 뜻으로 None이다.

파이썬에서 "다음 노드의 위치를 들고 있다"는 말은 next 속성이 다음 노드 객체를 가리킨다(참조한다)는 뜻이다. a.next = b는 b를 복사하지 않고, 같은 객체를 가리키는 화살표 하나를 만들 뿐이다.

코딩 테스트에서는

파이썬 코딩 테스트에서 연결 리스트를 직접 만들 일은 드물고, 대부분 리스트와 deque(7장)로 충분하다. 그래도 노드 클래스를 주고 함수만 채우라는 문제가 가끔 나오고, 다음을 가리키는 참조를 따라가고 고치는 감각은 트리(15장)와 그래프의 인접 리스트(13장)에서 그대로 쓴다.

노드 만들고 순회하기

노드는 값과 next만 가진 작은 클래스로 만든다. 여기에 파이썬 리스트를 연결 리스트로 바꾸는 from_list와, 거꾸로 연결 리스트를 파이썬 리스트로 모으는 to_list를 함께 둔다. 이 장의 뒤 코드는 모두 이 파일을 from linked_list import …로 가져다 쓴다.


class Node:
    """값 하나와 다음 노드를 담는다."""
    def __init__(self, val, next=None):
        self.val = val
        self.next = next


def from_list(values):
    """리스트 -> 연결 리스트. 첫 노드를 돌려준다."""
    head = tail = None
    for v in values:
        node = Node(v)
        if head is None:            # 첫 노드
            head = node
        else:
            tail.next = node        # 마지막 노드 뒤에 붙인다
        tail = node                 # 마지막 노드를 기억해 둔다
    return head


def to_list(head):
    """연결 리스트 -> 리스트."""
    out = []
    cur = head
    while cur:                      # None 을 만나면 끝
        out.append(cur.val)
        cur = cur.next
    return out


if __name__ == '__main__':
    head = from_list([7, 3, 9])
    print(to_list(head))
    print(head.val, head.next.val, head.next.next.next)

[7, 3, 9]
7 3 None

from_list는 마지막 노드를 tail에 들고 다닌다. 그래서 새 노드를 붙일 때마다 끝까지 걸어갈 필요가 없고, 전체가 O(n)이다. 마지막 줄의 head.next.next.next가 None인 것은 세 번째 노드(9)의 next이기 때문이다.

if __name__ == '__main__': 아래는 이 파일을 직접 실행할 때만 돌고, import할 때는 돌지 않는다. Node를 그냥 print하면 실행마다 바뀌는 메모리 주소가 나오므로 내용은 늘 to_list로 바꿔 출력한다.

head부터 따라가기

순회는 cur라는 이름을 head에 두고, cur = cur.next로 한 칸씩 옮기다가 None을 만나면 멈추는 것이 전부다. to_list도 이 모양이다.


from linked_list import from_list, to_list

head = from_list([7, 3, 9])

cur = head                      # 첫 노드에서 출발
while cur:                      # None 이면 끝
    print(cur.val, end=' -> ')
    cur = cur.next              # 다음 노드로 한 칸
print(None)


def nth(head, i):               # i 번째 노드: i 칸을 걸어가야 한다
    cur = head
    for _ in range(i):
        cur = cur.next
    return cur


print(nth(head, 2).val)
print(to_list(head)[2])         # 배열이라면 계산 한 번이면 된다

7 -> 3 -> 9 -> None
9
9

i번째 노드를 보려면 i번을 걸어야 하므로 O(n)이다. 배열처럼 계산으로 건너뛸 수 없는 이유는, i번째 노드의 위치가 바로 앞 노드 안에만 적혀 있기 때문이다. 앞 노드에 가 보기 전에는 어디 있는지 알 수 없다.

삽입과 삭제

연결 리스트가 배열보다 나은 점은 넣고 빼기다. 배열은 중간에 하나를 넣으면 뒤의 원소를 모두 한 칸씩 밀어야 하지만(8장), 연결 리스트는 이웃 노드의 next 한두 개만 바꾸면 된다. 단, 넣을 자리의 앞 노드를 이미 알 때 이야기다. 자리를 찾느라 걷는 시간은 따로 든다.

맨 앞에 넣기


from linked_list import Node, from_list, to_list

head = from_list([3, 9])

new = Node(7)          # 1) 새 노드를 만들고
new.next = head        # 2) 새 노드가 지금의 첫 노드를 가리키게 한 뒤
head = new             # 3) head 를 새 노드로 옮긴다
print(to_list(head))

head = Node(1, head)   # 세 줄을 한 줄로: 생성자에 next 를 넘긴다
print(to_list(head))

[7, 3, 9]
[1, 7, 3, 9]

원소 수와 상관없이 세 줄이라 O(1)이다. head = new를 먼저 하면 원래 첫 노드를 가리키는 이름이 사라져 나머지를 통째로 잃는다.

맨 뒤에 넣기


from linked_list import Node, from_list, to_list

head = from_list([7, 3])

cur = head                 # tail 을 모르면 끝까지 걸어가야 한다: O(n)
while cur.next:            # next 가 None 인 마지막 노드에서 멈춘다
    cur = cur.next
cur.next = Node(9)
print(to_list(head))

tail = cur.next            # 마지막 노드를 따로 들고 있으면
tail.next = Node(5)        # 걷지 않고 바로 붙인다: O(1)
tail = tail.next
print(to_list(head), tail.val)

[7, 3, 9]
[7, 3, 9, 5] 5

마지막 노드를 모르면 끝까지 걸어야 해서 O(n)이다. from_list처럼 tail을 들고 있으면 O(1)이 되지만, 넣고 뺄 때마다 tail도 고쳐야 한다.

중간에 넣기

3 노드(prev) 뒤에 5를 넣는다. 바꿀 화살표는 두 개다. 새 노드에서 9로 가는 것, 그리고 3에서 새 노드로 가는 것이다.


from linked_list import Node, from_list, to_list

head = from_list([7, 3, 9])
prev = head.next          # 3 노드. 이 뒤에 5 를 넣는다

new = Node(5)
new.next = prev.next      # 1) 새 노드가 먼저 뒤쪽(9)을 붙잡고
prev.next = new           # 2) 그다음에 앞 노드가 새 노드를 가리킨다
print(to_list(head))

[7, 3, 5, 9]

순서가 중요한 이유는 9로 가는 길이 처음에는 prev.next 하나뿐이기 때문이다. ②를 먼저 하면 그 길이 덮어써져 9 이후를 잃는다. 그래서 규칙은 하나다. 새 노드가 뒤쪽을 먼저 붙잡고, 그다음에 앞 노드가 새 노드를 가리킨다.

지우기

노드를 지운다는 것은 앞 노드가 그 노드를 건너뛰게 만드는 것이다. 그래서 지울 노드 자체보다 그 앞 노드가 필요하다. 화살표가 한 방향뿐이라 뒤 노드에서 앞 노드로 거슬러 갈 수 없기 때문이다.


from linked_list import from_list, to_list

head = from_list([7, 3, 5, 9])
prev = head.next          # 3 노드. 이 뒤의 5 를 지운다

removed = prev.next
prev.next = removed.next  # 3 이 5 를 건너뛰고 9 를 가리킨다
removed.next = None       # 떼어 낸 노드는 깨끗이 끊어 둔다
print(to_list(head))
print(removed.val, removed.next)

[7, 3, 9]
5 None

아무도 가리키지 않게 된 노드는 파이썬이 알아서 메모리를 회수한다. removed.next = None은 떼어 낸 노드를 따라 원래 리스트로 잘못 들어가는 일을 막는다.

더미 머리로 경계 없애기

값이 target인 첫 노드를 지우는 함수를 만들어 보자. 앞 절에서 본 대로 앞 노드(prev)를 찾아 건너뛰게 하면 되는데, 문제는 첫 노드에는 앞 노드가 없다는 점이다. 첫 노드를 지우면 head 자체가 바뀌므로 따로 처리해야 하고, 빈 리스트도 따로 막아야 한다.


from linked_list import from_list, to_list


def delete_value(head, target):
    if head is None:                # 빈 리스트
        return None
    if head.val == target:          # 첫 노드가 대상이면 head 자체가 바뀐다
        return head.next
    prev = head
    while prev.next and prev.next.val != target:
        prev = prev.next
    if prev.next:                   # 찾았으면 건너뛴다
        prev.next = prev.next.next
    return head


head = from_list([7, 3, 9])
head = delete_value(head, 7)        # 첫 노드
print(to_list(head))
head = delete_value(head, 9)        # 마지막 노드
print(to_list(head))
head = delete_value(head, 4)        # 없는 값
print(to_list(head))

[3, 9]
[3]
[3]

경계 검사가 두 번 붙었고, 이런 특수 처리는 빠뜨리기 쉽다. 해결책은 값 없는 가짜 노드를 첫 노드 앞에 세우는 것이다. 이 노드를 더미 머리(dummy head, 자리만 지키는 가짜 첫 노드)라고 한다.


from linked_list import Node, from_list, to_list


def delete_value(head, target):
    dummy = Node(None, head)        # 가짜 머리가 진짜 첫 노드 앞에 선다
    prev = dummy
    while prev.next and prev.next.val != target:
        prev = prev.next
    if prev.next:
        prev.next = prev.next.next
    return dummy.next               # 진짜 head 는 언제나 dummy.next


head = from_list([7, 3, 9])
head = delete_value(head, 7)        # 첫 노드도 같은 코드로 지워진다
print(to_list(head))
head = delete_value(head, 3)
head = delete_value(head, 9)        # 마지막 하나까지 지우면
print(to_list(head), head)

[3, 9]
[] None

더미를 세우면 모든 진짜 노드에 앞 노드가 생기므로, 첫 노드도 다른 노드와 같은 코드로 지워진다. 빈 리스트여도 dummy는 있으니 따로 막을 필요가 없다. head가 바뀌었을 수 있으니 돌려줄 때는 처음 받은 head가 아니라 언제나 dummy.next를 돌려준다.

빠른 포인터와 느린 포인터

속도가 다른 이름 둘을 함께 움직이면 길이를 세지 않고도 위치를 알아낼 수 있다. 한 칸씩 가는 slow와 두 칸씩 가는 fast다.

가운데 노드 찾기


from linked_list import from_list


def middle(head):
    slow = fast = head
    while fast and fast.next:       # fast 가 두 칸 갈 수 있는 동안
        slow = slow.next            # slow 는 한 칸
        fast = fast.next.next       # fast 는 두 칸
    return slow                     # fast 가 끝에 닿으면 slow 는 가운데


print(middle(from_list([1, 2, 3, 4, 5])).val)
print(middle(from_list([1, 2, 3, 4, 5, 6])).val)   # 짝수 개면 뒤쪽 가운데

3
4

fast가 늘 slow의 두 배를 걸으니, fast가 끝에 닿는 순간 slow는 절반 지점에 있다. 길이를 먼저 세고 다시 절반을 걷는 방법보다 한 번만 훑는다. 조건 fast and fast.next는 순서가 중요하다. and는 앞이 거짓이면 뒤를 보지 않으므로, fast가 None일 때 fast.next를 읽다가 멈추는 일이 없다.

사이클 판별: 토끼와 거북이

마지막 노드가 None 대신 앞쪽 노드를 가리키면 리스트에 고리가 생긴다. 이를 사이클(cycle)이라 한다. 사이클이 있으면 while cur:는 영원히 끝나지 않는다. 같은 두 포인터로 사이클이 있는지 알아낼 수 있다.


from linked_list import from_list


def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:            # 같은 노드를 밟았다: 고리가 있다
            return True
    return False                    # None 에 닿았다: 끝이 있다


head = from_list([1, 2, 3, 4])
print(has_cycle(head))

last = head.next.next.next          # 4 노드
last.next = head.next               # 4 -> 2 로 되돌려 고리를 만든다
print(has_cycle(head))

False
True

고리가 없으면 fast가 먼저 None에 닿는다. 고리가 있으면 둘 다 고리 안을 돌게 되고, 한 번 움직일 때마다 fast가 거리를 한 칸씩 좁히므로 반드시 같은 노드에서 만난다. 이 방법을 플로이드의 토끼와 거북이라고 부르며, 시간 O(n)에 추가 공간은 O(1)이다. 지나간 노드를 집합에 모아도 되지만 공간이 O(n) 든다.

is는 값이 아니라 같은 객체인지를 본다. 값이 같은 노드가 여럿일 수 있으니 노드 비교에는 is를 쓴다.

이중 연결 리스트와 deque

지금까지 본 연결 리스트는 화살표가 한 방향뿐인 단일 연결 리스트다. 노드마다 앞 노드를 가리키는 prev를 하나 더 두면 이중 연결 리스트가 된다.


class DNode:
    def __init__(self, val):
        self.val = val
        self.prev = None
        self.next = None


a, b, c = DNode(1), DNode(2), DNode(3)
a.next, b.prev = b, a            # 양쪽 방향을 모두 이어 둔다
b.next, c.prev = c, b

b.prev.next = b.next             # b 만 알면 앞 노드를 찾지 않고 뗀다
b.next.prev = b.prev
print(a.next.val, c.prev.val)

vals = []
cur = c                          # 뒤에서 앞으로도 걸을 수 있다
while cur:
    vals.append(cur.val)
    cur = cur.prev
print(vals)

3 1
[3, 1]

노드가 앞 노드를 스스로 아니, 지울 노드만 쥐고 있으면 앞 노드를 찾아 걷지 않고 O(1)에 뗀다. 뒤에서 앞으로도 걷는다. 대신 화살표가 두 개라 메모리가 더 들고 고칠 화살표도 두 배다.

7장의 deque가 이 구조의 응용이다. 원소마다 노드를 두는 대신 원소 여러 개를 담은 블록끼리 앞뒤로 잇는다. 그래서 양 끝은 O(1)이고, 가운데를 인덱스로 찾으면 블록을 따라가야 해서 O(n)이다.

앞 노드의 next를 먼저 바꿔 뒤를 잃기

중간에 넣을 때 prev.next = new를 먼저 하면 뒤쪽으로 가는 유일한 길이 사라진다. 그다음 new.next = prev.next를 해도 prev.next는 이미 new라서, 새 노드가 자기 자신을 가리키는 고리가 생긴다.


from linked_list import Node, from_list

head = from_list([7, 3, 9])
prev = head.next          # 3 노드 뒤에 5 를 넣으려 한다

new = Node(5)
prev.next = new           # 앞 노드를 먼저 바꾸면 9 로 가는 길이 사라진다
print(new.next)           # 아무도 9 를 가리키지 않는다
new.next = prev.next      # prev.next 는 이미 new 자신이다
print(new.next is new)    # 자기 자신을 가리키는 고리

head를 갱신하지 않기

함수 안에서 head = head.next를 해도 바뀌는 것은 함수 안의 지역 변수 head뿐이다(6장). 맨 앞이 바뀔 수 있는 함수는 새 head를 돌려주고, 부르는 쪽에서 head = f(head)로 다시 받아야 한다.


from linked_list import from_list, to_list


def drop_first_wrong(head):
    head = head.next        # 함수 안의 이름 head 만 바뀐다


def drop_first(head):
    return head.next        # 새 head 를 돌려준다


head = from_list([7, 3, 9])
drop_first_wrong(head)
print(to_list(head))        # 그대로다
head = drop_first(head)     # 돌려받은 값을 다시 head 에 넣어야 한다
print(to_list(head))

연결 리스트 뒤집기

단일 연결 리스트의 첫 노드 head가 주어진다. 노드의 순서를 거꾸로 바꾼 뒤 새 첫 노드를 돌려주는 함수 reverse(head)를 작성하라.

  • 새 노드를 만들지 말고, 기존 노드의 next만 바꾼다.
  • 노드 수는 0 이상 100,000 이하다. 빈 리스트면 head는 None이다.
입력출력이유
1 → 2 → 3 → 44 → 3 → 2 → 1화살표 방향이 모두 뒤집힌다
55노드가 하나면 그대로다
빈 리스트빈 리스트뒤집을 노드가 없어 None을 돌려준다
접근 방법먼저 생각해 보고 펼치세요

값을 모아 거꾸로 새로 만들면 쉽지만 조건에 어긋나고 공간도 O(n) 든다. 노드는 그대로 두고 화살표마다 방향만 뒤로 돌리면 된다.

걸림돌은 삽입 때와 같다. cur.next = prev로 화살표를 돌리는 순간, 원래 다음 노드로 가는 길이 사라진다. 그래서 돌리기 전에 다음 노드를 nxt에 먼저 적어 둔다. 이름 세 개가 필요하다.

  1. prev = None, cur = head로 시작한다. prev는 이미 뒤집은 앞부분의 첫 노드다.
  2. nxt = cur.next로 남은 뒷부분을 붙잡는다.
  3. cur.next = prev로 화살표를 돌린다.
  4. prev = cur, cur = nxt로 한 칸씩 나아간다. cur가 None이 되면 prev가 새 head다.

재귀로도 풀 수 있지만 노드 수만큼 호출이 쌓여, 노드가 10만 개면 기본 한도 1000(6장)을 넘어 RecursionError가 난다. 반복문이 안전하다.

풀이 코드 

from linked_list import from_list, to_list


def reverse(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next        # 1) 다음 노드를 먼저 기억해 두고
        cur.next = prev       # 2) 화살표를 뒤로 돌린 뒤
        prev = cur            # 3) 두 포인터를 한 칸씩 전진한다
        cur = nxt
    return prev               # 끝나면 prev 가 새 head


print(to_list(reverse(from_list([1, 2, 3, 4]))))
print(to_list(reverse(from_list([5]))))
print(to_list(reverse(from_list([]))))

[4, 3, 2, 1]
[5]
[]

빈 리스트면 반복문이 돌지 않고 None을 돌려주고, 노드가 하나면 next에 None이 다시 적힐 뿐이다. 경계 검사 없이 세 경우가 모두 맞는다.

복잡도
시간
O(n) 노드마다 화살표를 한 번씩 돌린다.
공간
O(1) 노드 수와 상관없이 이름 세 개(prev, cur, nxt)만 쓴다.

스스로 확인

배열은 i번째 원소를 O(1)에 읽는데 연결 리스트는 O(n)이 걸리는 이유는?

배열은 칸이 붙어 있어 시작 위치와 인덱스로 주소를 계산한다. 연결 리스트의 i번째 노드 위치는 바로 앞 노드의 next에만 적혀 있어서, head부터 i번 따라가야 알 수 있다.

insert_after.py에서 new.next = prev.next와 prev.next = new의 순서를 바꾸면 어떻게 되는가?

9로 가는 유일한 길인 prev.next가 먼저 덮어써져 9 이후를 잃는다. 이어서 new.next = prev.next는 new 자신을 가리키게 되어 고리가 생기고, 순회가 끝나지 않는다.

더미 머리를 쓴 delete_value가 처음 받은 head 대신 dummy.next를 돌려주는 이유는?

첫 노드를 지웠다면 처음 받은 head는 지워진 노드를 가리킨다. 지금의 첫 노드는 언제나 더미 바로 뒤인 dummy.next이고, 모두 지웠다면 None이다.

has_cycle의 반복 조건을 while fast.next:로만 쓰면 어떤 입력에서 문제가 생기는가?

빈 리스트면 fast가 처음부터 None이라 바로 AttributeError가 난다. 노드가 두 개처럼 짝수 개여도 fast = fast.next.next가 None이 된 뒤 None.next를 읽다가 같은 에러가 난다. fast and fast.next로 두 칸을 모두 확인해야 한다.

정리

  1. 연결 리스트는 값과 next를 담은 노드를 줄줄이 이은 구조다. 첫 노드는 head, 마지막 노드의 next는 None이다.
  2. i번째 원소를 읽으려면 head부터 걸어야 해서 O(n)이고, 자리를 알면 넣고 빼기는 화살표 한두 개만 바꿔 O(1)이다.
  3. 넣을 때는 새 노드가 뒤쪽을 먼저 붙잡고 나서 앞 노드를 새 노드에 잇는다. 지울 때는 앞 노드가 지울 노드를 건너뛰게 한다.
  4. 더미 머리를 세우면 첫 노드와 빈 리스트의 특수 처리가 사라진다. 결과는 dummy.next로 돌려준다.
  5. 한 칸·두 칸씩 걷는 두 포인터로 가운데 노드를 찾고 사이클을 O(1) 공간으로 판별한다. 뒤집기는 prev, cur, nxt 세 이름으로 한 번에 한다.
  6. 파이썬 실전에서는 직접 만든 연결 리스트 대신 deque와 list를 쓴다. 노드와 화살표로 생각하는 법은 트리와 그래프에서 다시 쓴다.
