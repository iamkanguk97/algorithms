완전 탐색과 백트래킹

가능한 경우를 하나도 빠짐없이 만들어 보고 답을 고르는 방법은 가장 단순하면서도 가장 확실합니다. 이 장에서는 경우의 수를 먼저 세는 습관부터, 재귀로 경우를 만들고 가망 없는 가지를 일찍 잘라 내는 백트래킹까지 다룹니다.

완전 탐색순열 · 조합재귀상태 되돌리기가지치기

이 장에서 배울 것

  • 입력 범위를 보고 경우의 수를 세어 완전 탐색이 시간 안에 되는지 판단할 수 있다
  • 반복문과 itertools로 순열, 조합, 부분집합을 만들 수 있다
  • visited와 path를 써서 재귀로 순열과 조합을 직접 만들 수 있다
  • 재귀에서 돌아올 때 상태를 되돌려야 하는 이유를 설명할 수 있다
  • 가지치기로 호출 횟수를 줄이고, 그 효과를 직접 세어 확인할 수 있다

완전 탐색이란

핵심

경우의 수를 먼저 센다. 셀 수 있을 만큼 작으면 전부 본다. 크면 가망 없는 가지를 일찍 자른다.

완전 탐색(brute force)은 답이 될 수 있는 후보를 모두 만들어 하나씩 확인하는 방법이다. 빠뜨리는 경우가 없으니 답이 틀릴 일이 없다. 문제는 시간이다. 후보가 몇 개인지 모르고 시작하면, 맞는 코드가 시간 초과로 끝난다.

그래서 코드를 쓰기 전에 후보의 개수부터 센다. 경우를 만드는 방식은 대부분 아래 네 가지 중 하나다. 2장의 어림값인 "1초에 대략 1천만 번"을 기준으로 n의 한계를 함께 적었다.

경우뜻개수1초 안에 되는 대략의 n
순열n개를 모두 줄 세우기n!n ≤ 10 (약 363만)
조합n개 중 r개 고르기, 순서 무시C(n, r)r이 작으면 n이 커도 된다. C(100, 3) = 161,700
부분집합각 원소를 넣거나 빼기2ⁿn ≤ 20 (약 105만)
중복 순열n가지 중 하나를 r번 고르기nʳnʳ ≤ 1천만 정도. 10⁷이면 n = 10, r = 7
 

from math import comb, perm

n = 10
print(perm(n), comb(n, 3), 2 ** n, n ** 3)

LIMIT = 10_000_000              # 1초에 대략 1천만 번(2장)
print(perm(10) <= LIMIT, perm(11) <= LIMIT)
print(2 ** 20 <= LIMIT, 2 ** 24 <= LIMIT)

후보 하나를 만들고 확인하는 데에도 몇 번의 연산이 드니, 실제로는 이 한계보다 넉넉히 잡는다. 반대로 문제의 입력 범위가 n ≤ 10이나 n ≤ 20처럼 유난히 작다면, 그 자체가 "전부 봐도 된다"는 신호다.

반복문으로 고르기

고를 개수가 2개나 3개로 정해져 있으면 반복문을 그만큼 겹치면 된다. 합이 9가 되는 두 수와 세 수를 찾아보자.


nums = [3, 8, 1, 6, 5, 2]
target = 9
n = len(nums)

pairs = []
for i in range(n):
    for j in range(i + 1, n):            # j 는 항상 i 뒤에서 시작한다
        if nums[i] + nums[j] == target:
            pairs.append((nums[i], nums[j]))
print(pairs)

triples = 0
for i in range(n):
    for j in range(i + 1, n):
        for k in range(j + 1, n):
            if nums[i] + nums[j] + nums[k] == target:
                triples += 1
print(triples)

[(3, 6), (8, 1)]
2

j를 i + 1부터 시작하는 것이 요점이다. (3, 6)과 (6, 3)을 두 번 세지 않고, 자기 자신과 짝짓지도 않는다. 두 수 고르기는 C(n, 2)로 O(n²), 세 수는 O(n³)이다.

이 방식은 고를 개수가 코드에 박혀 있다는 한계가 있다. "몇 개를 고를지"가 입력으로 바뀌면 반복문을 몇 겹 쓸지 정할 수 없다. 이럴 때 쓰는 도구가 다음 절의 itertools와 그다음 절의 재귀다. 각 원소를 넣을지 말지를 정수의 비트로 표현하는 방법은 27장 비트마스크에서 다룬다.

itertools로 경우 만들기

7장에서 본 itertools는 순열과 조합을 대신 만들어 준다. 앞 절의 두 수, 세 수 고르기가 한 줄씩으로 줄어든다.


from itertools import combinations, permutations, product

nums = [3, 8, 1, 6, 5, 2]
target = 9

print([pair for pair in combinations(nums, 2) if sum(pair) == target])
print(sum(1 for triple in combinations(nums, 3) if sum(triple) == target))

digits = [2, 7, 4]
print(max(permutations(digits)))           # 세 자리를 가장 크게 늘어놓기
print(len(list(product('01', repeat=4))))  # 0/1 네 자리: 2⁴ 가지

[(3, 6), (8, 1)]
2
(7, 4, 2)

permutations는 순열, combinations는 조합, product는 중복 순열을 만든다. product([0, 1], repeat=n)은 각 원소를 넣을지(1) 뺄지(0)의 모든 조합이라 부분집합을 만드는 데에도 쓴다. 모두 C로 구현돼 있어 직접 짠 재귀보다 빠르다.

팁

"전부 만들어 본 뒤 조건을 확인"하면 되는 문제는 itertools가 가장 짧고 빠르다. 만드는 도중에 조건을 보고 멈춰야 한다면 재귀로 직접 만든다.

재귀로 직접 만들기

itertools는 경우를 끝까지 다 만든 다음에야 건네준다. 세 번째 자리에서 이미 틀렸다는 것을 알아도 나머지 자리까지 채운다. 경우를 만드는 과정에 끼어들려면 직접 만들어야 한다.

순열을 만드는 과정은 "자리를 하나씩 채우는 일"로 볼 수 있다. 첫 자리에 무엇을 놓을지 고르고, 남은 것으로 둘째 자리를 고르고, 이것을 자리가 다 찰 때까지 반복한다. 매 자리에서 하는 일이 같으니 재귀(6장)로 짠다. 필요한 상태는 둘이다.

  • path — 지금까지 고른 원소의 리스트
  • visited — visited[i]가 참이면 i번 원소는 이미 path에 있다

def permutations(nums: list[int]) -> list[list[int]]:
    result = []
    visited = [False] * len(nums)     # i번 원소를 이미 썼는가
    path = []                         # 지금까지 고른 원소

    def choose() -> None:
        if len(path) == len(nums):    # 다 골랐다: 순열 하나 완성
            result.append(path[:])    # 복사본을 넣는다
            return
        for i in range(len(nums)):
            if visited[i]:
                continue
            visited[i] = True
            path.append(nums[i])
            choose()                  # 다음 자리를 고른다
            path.pop()                # 고른 것을 되돌린다
            visited[i] = False

    choose()
    return result


for p in permutations([1, 2, 3]):
    print(p)

조합은 순서를 따지지 않으므로 visited 대신 "어디부터 고를 수 있는가"를 넘긴다. i번을 골랐다면 다음은 i + 1번부터 고른다. 앞 절 반복문의 range(i + 1, n)과 같은 생각이다.


def combinations(nums: list[int], r: int) -> list[list[int]]:
    result = []
    path = []

    def choose(start: int) -> None:
        if len(path) == r:
            result.append(path[:])
            return
        for i in range(start, len(nums)):   # start 앞으로는 돌아가지 않는다
            path.append(nums[i])
            choose(i + 1)
            path.pop()

    choose(0)
    return result


print(combinations([1, 2, 3, 4], 2))
print(len(combinations([1, 2, 3, 4], 2)))

[[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]
6

고를 개수 r이 인자라서 반복문을 몇 겹 쓸지 고민할 필요가 없다. 재귀 깊이가 곧 반복문의 겹 수가 된다.

상태 되돌리기

앞의 두 코드에는 append 뒤에 반드시 pop이 짝으로 붙어 있다. 이렇게 한 가지를 골라 끝까지 가 본 뒤, 고른 것을 취소하고 바로 전 갈림길로 돌아가 다른 것을 고르는 탐색을 백트래킹(backtracking)이라고 한다. 미로에서 막다른 길을 만나면 마지막 갈림길까지 되돌아가는 것과 같다.

[1, 2]의 순열을 만들 때 path가 어떻게 바뀌는지 찍어 보자.


nums = [1, 2]
path = []
visited = [False] * len(nums)


def choose(depth: int) -> None:
    for i in range(len(nums)):
        if visited[i]:
            continue
        visited[i] = True
        path.append(nums[i])
        done = ' 완성' if len(path) == len(nums) else ''
        print('  ' * depth + f'append -> {path}{done}')
        choose(depth + 1)
        path.pop()
        visited[i] = False
        print('  ' * depth + f'pop    -> {path}')


choose(0)

append -> [1]
  append -> [1, 2] 완성
  pop    -> [1]
pop    -> []
append -> [2]
  append -> [2, 1] 완성
  pop    -> [2]
pop    -> []

되돌려야 하는 이유는 path와 visited가 모든 호출이 함께 쓰는 리스트 하나이기 때문이다. 호출마다 복사본을 만들면 되돌릴 필요가 없지만, 매번 O(n)의 복사가 든다. 하나를 공유하고 고친 만큼만 되돌리면 복사 없이 탐색할 수 있다. 그 대가로 "고친 것은 돌아올 때 반드시 원래대로"라는 규칙을 지켜야 한다. 되돌리지 않으면 다음 가지가 앞 가지의 흔적을 안고 시작한다.

모든 백트래킹은 같은 틀을 따른다.


def backtrack(state):
    if is_complete(state):          # 끝까지 왔다
        record(state)
        return
    for choice in candidates(state):
        if not is_promising(state, choice):
            continue                # 가지치기 (다음 절)
        apply(state, choice)        # 고른다
        backtrack(state)
        undo(state, choice)         # 되돌린다

가지치기

탐색 과정을 나무로 그리면, 갈림길마다 가지가 갈라지고 맨 끝 잎 하나하나가 후보 하나다. 어떤 갈림길에서 "여기서부터는 무엇을 골라도 답이 될 수 없다"는 것을 안다면, 그 아래 가지 전체를 보지 않아도 된다. 이것을 가지치기(pruning)라고 한다. 재귀로 직접 만드는 이유가 바로 여기에 있다.

양의 정수 중에서 합이 10이 되는 부분집합을 세어 보자. 원소가 모두 양수이니, 지금까지의 합이 이미 10 이상이면 더 넣어 봐야 커지기만 한다. 가지치기 전후로 호출 횟수를 센다.


nums = [5, 3, 8, 2, 7, 4, 6, 1]
target = 10


def count_subsets(prune: bool) -> tuple[int, int]:
    """합이 target 인 부분집합의 수와 choose 호출 횟수를 돌려준다."""
    found = 0
    calls = 0

    def choose(start: int, total: int) -> None:
        nonlocal found, calls
        calls += 1
        if total == target:
            found += 1
        if prune and total >= target:       # 더 더해도 작아지지 않는다
            return
        for i in range(start, len(nums)):
            choose(i + 1, total + nums[i])

    choose(0, 0)
    return found, calls


print(count_subsets(prune=False))
print(count_subsets(prune=True))

(8, 256)
(8, 64)

답은 8개로 같고, 호출은 256번에서 64번으로 줄었다. 가지치기 없이는 부분집합 2⁸ = 256개를 하나도 빼지 않고 만든다. 이 차이는 n이 커질수록 벌어진다.

가지치기 조건이 지켜야 할 것이 예제에서
답이 될 가능성이 있는 가지는 자르지 않는다양수만 있어서 합이 줄어들 수 없다. 음수가 섞이면 이 조건은 틀린다
판단이 싸야 한다비교 한 번이다. 판단에 O(n)이 들면 아낀 만큼 다시 쓴다
되도록 위에서 자른다얕은 곳에서 자를수록 그 아래 가지가 많이 사라진다

가지치기는 최악의 경우 복잡도를 바꾸지 못할 때가 많다. 그래도 실제로 도는 호출 수를 크게 줄여서, 완전 탐색으로는 시간이 모자라던 문제를 통과하게 만든다. 원소를 미리 정렬해 두면 "이 원소를 넣어 넘친다면 뒤의 더 큰 원소도 넘친다"가 성립해 반복문을 break로 끊을 수도 있다.

자주 하는 실수

결과에 path를 그대로 넣기

result.append(path)는 리스트의 복사본이 아니라 같은 리스트를 가리키는 이름을 넣는다. 탐색이 끝나면 path는 다 비워지므로, 결과가 모두 같은 빈 리스트가 된다.


def subsets(nums: list[int]) -> list[list[int]]:
    result = []
    path = []

    def choose(start: int) -> None:
        result.append(path)            # path 자체를 넣었다
        for i in range(start, len(nums)):
            path.append(nums[i])
            choose(i + 1)
            path.pop()

    choose(0)
    return result


print(subsets([1, 2]))     # [[], [1], [1, 2], [2]] 를 기대했다

[[], [], [], []]

result.append(path[:])나 list(path)로 그 순간의 복사본을 넣는다(복사는 3장).

visited 복구 누락

path.pop()만 하고 visited[i] = False를 빠뜨리면, 한 번 쓴 원소를 다른 가지에서 다시 쓰지 못한다. 순열 6개 중 첫 번째만 나오고 끝난다. 고친 상태가 몇 개든 돌아올 때 모두 되돌린다.

같은 값이 있는데 중복을 거르지 않기

원소에 같은 값이 있으면 위치는 달라도 값이 같은 순열이 여러 번 나온다.


from itertools import permutations

nums = [1, 1, 2]
print(list(permutations(nums)))         # 같은 순열이 두 번씩 나온다

집합으로 거르면 답은 맞지만 중복까지 다 만든 뒤라 느리다. 처음부터 만들지 않으려면 정렬한 뒤, 같은 값은 앞의 것을 먼저 쓴 경우에만 뒤의 것을 쓰게 한다.


def unique_permutations(nums: list[int]) -> list[list[int]]:
    nums = sorted(nums)               # 같은 값을 이웃하게 둔다
    result = []
    path = []
    visited = [False] * len(nums)

    def choose() -> None:
        if len(path) == len(nums):
            result.append(path[:])
            return
        for i in range(len(nums)):
            if visited[i]:
                continue
            if i > 0 and nums[i] == nums[i - 1] and not visited[i - 1]:
                continue              # 같은 값은 앞의 것부터 쓴다
            visited[i] = True
            path.append(nums[i])
            choose()
            path.pop()
            visited[i] = False

    choose()
    return result


print(unique_permutations([1, 1, 2]))

[[1, 1, 2], [1, 2, 1], [2, 1, 1]]
재귀 깊이

재귀 깊이는 "몇 번 골랐는가"와 같다. 순열이나 조합은 n이 작아 문제가 없지만, 격자를 한 칸씩 따라가는 백트래킹은 깊이가 칸 수만큼 될 수 있다. 깊이가 1000에 가까우면 sys.setrecursionlimit으로 한도를 올린다(6장).

N-Queen

체스의 퀸은 같은 가로줄, 같은 세로줄, 같은 대각선에 있는 말을 공격할 수 있다. N×N 판에 퀸 N개를 어떤 두 퀸도 서로 공격하지 못하게 놓으려 한다. 첫 줄에 정수 N이 주어진다(1 ≤ N ≤ 10). 가능한 배치의 수를 출력하라.

입력출력설명
42그림 22-3의 배치와, 그것을 좌우로 뒤집은 배치
30어떻게 놓아도 두 퀸이 서로 공격한다
11한 칸에 하나를 놓는다
접근 방법먼저 생각해 보고 펼치세요

퀸이 N개이고 가로줄도 N개인데, 한 줄에 둘이 있으면 서로 공격한다. 그러니 각 가로줄에 정확히 하나씩 놓인다. 칸 N²개 중 N개를 고르는 문제가 "줄마다 몇 번째 열에 놓을까"로 줄어든다.

  1. 0번 줄부터 차례로, 그 줄의 각 열에 퀸을 놓아 본다.
  2. 그 칸의 세로줄이나 두 대각선에 이미 퀸이 있으면 그 가지는 자른다.
  3. 놓을 수 있으면 표시하고 다음 줄로 재귀한다. 돌아오면 표시를 지운다.
  4. N번 줄까지 내려왔다면 N개를 다 놓은 것이니 하나를 센다.

공격 확인을 O(1)로 하려면 칸이 어느 대각선에 있는지 번호로 바로 알아야 한다. ↙ 방향 대각선 위의 칸은 row + col이 모두 같고, ↘ 방향은 row - col이 모두 같다. 세 종류의 줄을 불리언 리스트 세 개로 기록한다.

풀이 코드 

import sys

input = sys.stdin.readline

n = int(input())
cols = [False] * n               # 그 열에 퀸이 있는가
diag1 = [False] * (2 * n - 1)    # row + col 이 같은 대각선(↙)
diag2 = [False] * (2 * n - 1)    # row - col 이 같은 대각선(↘), n-1 을 더해 0부터
count = 0


def place(row: int) -> None:
    global count
    if row == n:                 # 모든 줄에 하나씩 놓았다
        count += 1
        return
    for col in range(n):
        d1, d2 = row + col, row - col + n - 1
        if cols[col] or diag1[d1] or diag2[d2]:
            continue             # 공격받는 칸: 이 가지는 자른다
        cols[col] = diag1[d1] = diag2[d2] = True
        place(row + 1)
        cols[col] = diag1[d1] = diag2[d2] = False   # 되돌린다


place(0)
print(count)

row - col은 -(n-1)부터 n-1까지라 음수가 나온다. n - 1을 더해 0부터 시작하는 인덱스로 옮겼다. 줄마다 하나씩 놓기 때문에 가로줄 검사는 따로 필요 없다.

복잡도
시간
O(N!) 줄마다 앞에서 쓴 열을 빼고 고르므로 최악이라도 N × (N-1) × … 이다. 실제로는 대각선 가지치기 덕분에 훨씬 적어서, N = 10에서 place 호출은 35,539번이다. 칸마다 놓아 보는 Nᴺ = 100억과 비교된다.
공간
O(N) 표시용 리스트 세 개와, 깊이 N + 1의 호출 스택만 쓴다.

스스로 확인

n = 12인 수열의 순열을 모두 만들어 확인하는 풀이는 1초 안에 끝날까?

어렵다. 12!은 약 4억 8천만이고, 1초에 대략 1천만 번이라는 어림값으로 수십 초가 걸린다. 표에서 본 대로 순열 전체는 n ≤ 10 정도까지만 통한다. 이보다 크면 가지치기나 다른 방법을 찾는다.

백트래킹에서 result.append(path)로 저장하면 결과가 모두 빈 리스트가 되는 이유는?

결과에 들어간 것이 모두 같은 리스트 path이기 때문이다. 탐색이 끝나면 pop으로 path가 다 비워지고, 결과의 모든 항목이 그 빈 리스트를 가리킨다. path[:]로 복사해 넣는다.

재귀로 조합을 만들 때 visited 대신 start를 넘기는 이유는?

조합은 순서를 따지지 않아서 [1, 2]와 [2, 1]을 같은 것으로 본다. 다음 원소를 항상 지금 고른 원소의 뒤에서만 고르면 원소가 오름차순 위치로만 뽑혀, 같은 조합이 한 번만 나온다. 이미 쓴 원소를 다시 고를 일도 없으니 visited가 필요 없다.

N-Queen에서 두 칸이 같은 대각선에 있는지 row + col과 row - col로 판단할 수 있는 이유는?

↙ 방향으로 한 칸 가면 행은 1 늘고 열은 1 줄어서 row + col이 그대로다. ↘ 방향으로 한 칸 가면 행과 열이 함께 1씩 늘어 row - col이 그대로다. 그래서 이 두 값이 대각선의 번호가 된다.

정리

  1. 완전 탐색은 모든 후보를 확인하므로 확실하다. 코드를 쓰기 전에 후보의 개수부터 세어 시간 안에 되는지 본다.
  2. 순열 n!은 n ≤ 10, 부분집합 2ⁿ은 n ≤ 20 정도가 1초 안의 대략적인 한계다. 입력 범위가 유난히 작으면 완전 탐색을 의심한다.
  3. 고를 개수가 정해져 있으면 반복문, 다 만든 뒤 확인하면 되면 itertools, 만드는 도중에 멈춰야 하면 재귀로 직접 만든다.
  4. 재귀로 순열은 visited와 path로, 조합은 start와 path로 만든다. 결과에는 path[:]를 넣는다.
  5. 백트래킹은 공유하는 상태를 고르고, 재귀하고, 되돌린다. append와 pop, True와 False는 늘 짝을 이룬다.
  6. 가지치기는 답이 될 수 없는 가지만 일찍 자른다. 조건이 정말 안전한지(음수가 섞이지 않는지 등) 확인하고, 호출 수를 세어 효과를 본다.
