비트 조작

정수를 2진수로 적으면 0과 1이 한 줄로 늘어선 칸이 됩니다. 이 장에서는 그 칸을 하나씩 켜고 끄는 비트 연산으로, 작은 집합을 정수 하나에 담아 빠르게 다루는 법을 배웁니다.

& | ^시프트비트마스크부분집합비트 DP

이 장에서 배울 것

  • 비트 연산자 여섯 가지가 각 자리에서 하는 일을 설명할 수 있다
  • 정수 하나로 집합을 표현하고 원소를 넣고, 빼고, 뒤집고, 확인할 수 있다
  • x & -x, x & (x - 1) 같은 기법이 왜 동작하는지 안다
  • 모든 부분집합과, 특정 집합의 부분집합을 비트마스크로 순회할 수 있다
  • 방문한 집합을 상태로 쓰는 비트 DP의 모양과 상태 수를 안다

비트 연산자

핵심

비트 조작은 정수 하나를 켜짐·꺼짐 칸 n개의 집합으로 보는 기술이다. 집합 연산이 비트 연산 한 번이 되어 빠르고, 집합 자체를 리스트의 인덱스로 쓸 수 있다.

비트(bit)는 2진수의 한 자리, 곧 0 또는 1 하나다. 12는 2진수로 1100이고, 오른쪽 끝부터 0번, 1번, 2번 비트라고 센다. 비트 연산자는 두 수를 2진수로 늘어놓고 같은 자리끼리 계산한다. 자리올림이 없어서 자리마다 따로 논다.


a = 0b1100   # 12
b = 0b1010   # 10

print(bin(a), bin(b))
print(format(a & b, '04b'))   # 둘 다 1인 자리만 1
print(format(a | b, '04b'))   # 하나라도 1이면 1
print(format(a ^ b, '04b'))   # 서로 다를 때만 1
print(a << 2, a >> 2)         # 12 × 4, 12 // 4
print(int('1010', 2))         # 2진수 문자열을 정수로

~와 음수

~만 결과가 낯설다. C나 Java의 정수는 32비트, 64비트처럼 칸 수가 정해져 있어서 "모든 칸을 뒤집는다"의 뜻이 분명하다. 파이썬의 int는 크기 제한이 없어서(2장) 칸 수가 정해져 있지 않다. 그래서 파이썬은 음수를 왼쪽으로 1이 끝없이 이어지는 수로 다룬다. 이 표현을 2의 보수(two's complement)라고 한다. 0이 끝없이 이어지던 왼쪽이 뒤집혀 1이 끝없이 이어지므로, ~x는 언제나 -x - 1이다.


x = 5
print(~x, -x - 1)
print(bin(~x))                       # 음수는 부호와 절댓값으로 보여 준다
print(format(~x & 0b1111, '04b'))    # 아래 네 칸만 보면 0101 이 뒤집혀 있다
print(-7 >> 1, -7 // 2)              # 음수의 오른쪽 시프트는 내림 나눗셈

bin(~5)가 -0b110으로 나오는 것은 파이썬이 음수를 "부호 + 절댓값"으로 보여 주기 때문이다. 정해진 칸 수만큼만 보고 싶으면 & 0b1111처럼 그 칸이 모두 켜진 수와 AND 한다. 한 줄로 정리하면, 비트 연산자는 같은 자리끼리 계산하고, 파이썬에서는 ~x == -x - 1이다.

비트마스크로 집합 표현

원소가 0부터 n-1까지인 집합을 생각한다. i번 비트가 1이면 원소 i가 집합에 있다고 약속하면, 정수 하나가 집합 하나가 된다. 이렇게 집합을 담은 정수를 비트마스크(bitmask)라고 한다. 전등 스위치가 한 줄로 늘어선 판에서 켜진 스위치의 번호만 읽는 것과 같다.


def to_mask(items: list[int]) -> int:
    mask = 0
    for i in items:
        mask |= 1 << i          # i번 비트를 켠다
    return mask


def to_items(mask: int, n: int) -> list[int]:
    return [i for i in range(n) if mask >> i & 1]


mask = to_mask([1, 2, 4])
print(mask, bin(mask))
print(to_items(mask, 5))
print(to_items(0b11111, 5))

22 0b10110
[1, 2, 4]
[0, 1, 2, 3, 4]

1 << i는 i번 비트 하나만 켜진 수다. mask >> i & 1은 i번 비트를 맨 오른쪽으로 끌어내린 뒤 그 한 칸만 남긴다. 결과가 1이면 원소 i가 있다.

왜 set 대신 쓰는가

4장의 set으로도 같은 일을 할 수 있다. 그런데도 비트마스크를 쓰는 이유는 세 가지다.

비교set비트마스크

합집합·교집합원소 수에 비례n이 작으면 연산 한 번
리스트 인덱스로 쓰기안 된다dp[mask]처럼 바로 된다

가장 큰 장점은 마지막에서 두 번째 줄이다. 집합이 정수라서 집합을 상태로 하는 표를 리스트로 만들 수 있다. 대신 가능한 집합이 2n개라, 모든 집합을 다루는 문제는 n이 20 안팎일 때만 쓴다. 2장의 시간 제한 표에서 n ≈ 20이 O(2ⁿ)의 한계였던 것과 같은 이야기다. 정리하면, 원소가 적은 집합은 정수 하나로 담는다.

켜기·끄기·토글·확인

원소 하나를 다루는 연산은 모두 "i번 비트만 켜진 수" 1 << i와 무엇을 하느냐로 정해진다. 켜기는 OR, 끄기는 뒤집은 수와 AND, 토글(켜져 있으면 끄고 꺼져 있으면 켜기)은 XOR이다.

하는 일집합으로 보면코드
i번 켜기원소 i 넣기mask | (1 << i)
i번 끄기원소 i 빼기mask & ~(1 << i)
i번 토글있으면 빼고 없으면 넣기mask ^ (1 << i)
i번 확인원소 i가 있는가mask >> i & 1 또는 mask & (1 << i) != 0
모두 켜기전체 집합(1 << n) - 1
모두 끄기공집합0
 

mask = 0b00110             # {1, 2}

mask |= 1 << 4             # 원소 4 넣기
print(format(mask, '05b'))
mask &= ~(1 << 1)          # 원소 1 빼기
print(format(mask, '05b'))
mask ^= 1 << 0             # 원소 0 토글
print(format(mask, '05b'))
print(mask >> 2 & 1, mask >> 3 & 1)   # 원소 2, 3이 있는가

끄기에서 ~(1 << 1)은 1번 칸만 0이고 나머지가 모두 1인 수다. 이것과 AND 하면 1번 칸만 지워지고 다른 칸은 그대로 남는다.

집합끼리의 연산

4장의 집합 연산자 |, &, ^는 비트 연산자와 기호가 같고 뜻도 같다. 차집합 a - b만 a & ~b("a에 있고 b에 없는")로 바꿔 쓴다.


a = 0b01111   # {0, 1, 2, 3}
b = 0b11010   # {1, 3, 4}

print(format(a | b, '05b'))    # 합집합
print(format(a & b, '05b'))    # 교집합
print(format(a & ~b, '05b'))   # 차집합 a - b
print(format(a ^ b, '05b'))    # 대칭차집합
sub = 0b01010                  # {1, 3}
print((a & sub) == sub, (a & b) == b)   # 부분집합인가

11111
01010

10101

마지막 줄처럼 "sub의 원소가 모두 a에 있는가"는 a & sub == sub로 확인한다. 교집합을 해도 sub가 줄지 않았다는 뜻이다. 정리하면, 원소 하나는 1 << i와 OR·AND·XOR로, 집합끼리는 연산자 하나로 다룬다.

자주 쓰는 기법

비트마스크 문제에서 반복해서 나오는 짧은 식이 몇 개 있다. 외워 두면 반복문 하나를 식 하나로 줄일 수 있다.


x = 0b101100   # 44

print(x.bit_count(), bin(x).count('1'))   # 켜진 비트 개수
print(bin(x & -x))        # 가장 낮은 켜진 비트만 남기기
print(bin(x & (x - 1)))   # 가장 낮은 켜진 비트 끄기
print(x.bit_length())     # 2진수 자릿수

for n in [1, 6, 8, 64, 96]:
    print(n, n > 0 and n & (n - 1) == 0)   # 2의 거듭제곱인가

int.bit_count()는 켜진 비트 수, 곧 집합의 원소 수를 센다. 파이썬 3.10부터 있고, 그 전 버전에서는 bin(x).count('1')을 쓴다. bit_length()는 맨 앞 0을 뺀 2진수 자릿수다.

x & -x 가 가장 낮은 비트를 남기는 이유

앞 절에서 -x = ~x + 1이었다. ~x는 모든 칸을 뒤집으므로, x의 가장 낮은 1 아래에 있던 0들은 1이 되고 그 1은 0이 된다. 여기에 1을 더하면 아래쪽 1들이 자리올림으로 모두 0이 되고, 올림이 멈추는 곳이 바로 x의 가장 낮은 1의 자리다. 그 위쪽은 여전히 x와 반대다. 그래서 x와 -x가 함께 1인 칸은 그 한 칸뿐이다.

x & (x - 1)은 반대로 그 칸을 끈다. 1을 빼면 가장 낮은 1이 0이 되고 그 아래 0들이 1이 되므로, x와 AND 하면 그 아래쪽까지 모두 0이 된다. 2의 거듭제곱은 켜진 비트가 하나뿐이라 이것을 끄면 0이 된다. 그래서 n > 0이면서 n & (n - 1) == 0인 수가 2의 거듭제곱이다. 정리하면, x & -x는 가장 낮은 1을 남기고 x & (x - 1)은 지운다.

부분집합 순회

원소 n개의 부분집합은 2n개이고, 각각이 0부터 2n-1까지의 정수 하나에 대응한다. 그래서 모든 부분집합을 보려면 range(1 << n)을 돌면 끝이다. 22장에서 재귀로 고르기·안 고르기를 갈라 만들던 부분집합이 반복문 한 줄로 나온다.


items = ['A', 'B', 'C']
n = len(items)

for mask in range(1 << n):
    chosen = [items[i] for i in range(n) if mask >> i & 1]
    print(format(mask, '03b'), chosen)

특정 집합의 부분집합만 돌기

이번에는 집합 mask 안에서 고를 수 있는 부분집합만 보고 싶다. 0부터 다 세며 (sub & mask) == sub를 확인해도 되지만, 바깥 원소가 많으면 낭비가 크다. 다음 식은 mask의 부분집합만 큰 것부터 차례로 밟는다.


mask = 0b1011   # {0, 1, 3}

sub = mask
while sub:
    print(format(sub, '04b'))
    sub = (sub - 1) & mask
print(format(sub, '04b'))   # 마지막에 공집합 0

비트 DP 맛보기

비트마스크가 가장 빛나는 곳은 26장의 다이나믹 프로그래밍(DP)과 만날 때다. "지금까지 어떤 것들을 썼는가"가 상태에 들어가야 하는 문제에서, 그 집합을 마스크로 만들어 표의 인덱스로 쓴다. 이것을 비트 DP라고 한다.

대표 예가 외판원 문제(TSP, Traveling Salesman Problem)다. 도시 n개를 모두 한 번씩 들르고 출발점으로 돌아오는 가장 싼 경로를 찾는다. 순서를 모두 따지면 (n-1)!가지라 n이 조금만 커져도 못 본다. 그런데 다음 도시를 고를 때 필요한 정보는 "이미 들른 도시의 집합"과 "지금 있는 도시" 둘뿐이다. 들른 순서는 상관없다. 그래서 상태를 dp[mask][i] = "mask의 도시를 모두 들르고 지금 i에 있을 때의 최소 비용"으로 잡는다.


INF = 10**9
cost = [
    [0, 10, 15, 20],
    [10, 0, 35, 25],
    [15, 35, 0, 30],
    [20, 25, 30, 0],
]
n = len(cost)
full = (1 << n) - 1

dp = [[INF] * n for _ in range(1 << n)]
dp[1][0] = 0                      # 0번 도시에서 출발: {0}, 위치 0

for mask in range(1 << n):
    for last in range(n):
        if dp[mask][last] == INF:
            continue
        for nxt in range(n):
            if mask >> nxt & 1:   # 이미 들른 도시
                continue
            new_mask = mask | (1 << nxt)
            new_cost = dp[mask][last] + cost[last][nxt]
            dp[new_mask][nxt] = min(dp[new_mask][nxt], new_cost)

print(min(dp[full][i] + cost[i][0] for i in range(1, n)))
print(len(dp) * n)                # 상태 수 2^n × n

80
64

mask | (1 << nxt)는 항상 mask보다 크므로, 마스크를 작은 수부터 돌면 필요한 칸이 늘 먼저 채워진다. 계산 순서를 따로 고민하지 않아도 되는 것도 마스크의 장점이다. 상태가 2ⁿ · n개이고 상태마다 다음 도시 n개를 보므로 시간은 O(2ⁿ · n²)이다.

n = 16이면 2장의 어림값으로 1~2초가 걸리는 빠듯한 크기다. 지수 시간인 것은 같지만, 팩토리얼보다는 훨씬 큰 n까지 버틴다. 정리하면, 쓴 것들의 집합이 상태에 들어가는 DP는 마스크를 인덱스로 쓰고, 상태 수 2ⁿ · n으로 크기를 가늠한다.

연산자 우선순위

파이썬에서 +, -는 <<, &보다 먼저 계산된다. 그래서 전체 집합을 1 << n - 1로 쓰면 1 << (n - 1)이 되어 엉뚱한 값이 나온다. 반대로 ==는 &보다 나중이라 x & 1 == 0은 (x & 1) == 0으로 계산된다. C와 Java는 이 순서가 거꾸로라 같은 식이 다르게 동작한다. 헷갈리지 않게 비트 연산에는 괄호를 친다.


n = 3
print(1 << n - 1)       # 1 << (n - 1) 로 계산된다
print((1 << n) - 1)     # 의도한 전체 집합 0b111
x = 6
print(x & 1 == 0)       # 파이썬에서는 (x & 1) == 0
try:
    print(1 << -1)
except ValueError as e:
    print(f'{type(e).__name__}: {e}')

음수만큼 시프트하기

위 코드의 마지막처럼 시프트 횟수가 음수면 ValueError가 난다. 1 << (x - 1)에서 x가 0으로 들어오는 경우처럼 인덱스 계산이 어긋났을 때 터진다. 음수를 오른쪽으로 미는 것(-7 >> 1)은 에러가 아니라 내림 나눗셈이다.

1 << n 에서 n의 범위

파이썬 정수는 크기 제한이 없어서 1 << 100도 에러 없이 만들어진다. 마스크 하나로는 문제가 없지만, [0] * (1 << n)처럼 모든 집합의 표를 만들면 n = 20에서 약 105만 칸, n = 25에서 약 3,355만 칸이 된다. 표를 만들기 전에 n이 20 안팎인지 확인한다.

비트 번호는 0부터

원소가 1번부터 n번까지인데 1 << x를 그대로 쓰면 0번 칸은 비고 n번 칸까지 필요해, 전체 집합 (1 << n) - 1과 한 칸 어긋난다. 입력이 1부터 시작하면 1 << (x - 1)로 한 칸 당겨 쓴다.

~mask 로 여집합 구하기

~mask는 음수라서 그대로 출력하거나 개수를 세면 엉뚱하다. 전체 n칸 안의 여집합은 full ^ mask나 ~mask & full로 구한다.

집합 명령 처리

처음에 비어 있는 집합 S가 있다. S에 들어갈 수 있는 수는 1부터 20까지다. 첫 줄에 명령 수 M(1 ≤ M ≤ 1,000,000)이 주어지고, 다음 M줄에 명령이 하나씩 주어진다. 명령은 여섯 가지다.

  • add x — S에 x를 넣는다. 이미 있으면 그대로 둔다.
  • remove x — S에서 x를 뺀다. 없으면 그대로 둔다.
  • check x — S에 x가 있으면 1, 없으면 0을 출력한다.
  • toggle x — x가 있으면 빼고, 없으면 넣는다.
  • all — S를 {1, 2, …, 20}으로 바꾼다.
  • empty — S를 공집합으로 바꾼다.

check 명령의 결과를 한 줄에 하나씩 출력하라.

접근 방법먼저 생각해 보고 펼치세요

원소가 20개뿐이므로 S 전체를 정수 하나의 20칸으로 담으면 모든 명령이 비트 연산 한 번이 된다.

  1. 수 x는 x - 1번 비트에 둔다. 해당 칸만 켜진 수는 1 << (x - 1)이다.
  2. add는 OR, remove는 그 칸을 뒤집은 수와 AND, toggle은 XOR, check는 AND 결과가 0인지 본다.
  3. all은 20칸이 모두 켜진 (1 << 20) - 1, empty는 0으로 바꾼다.
  4. 명령이 많으므로 입력은 sys.stdin.readline으로 읽고, 출력은 모아서 한 번에 낸다(1장).
풀이 코드 

import sys

input = sys.stdin.readline

FULL = (1 << 20) - 1          # 1~20이 모두 켜진 상태

m = int(input())
mask = 0
out = []

for _ in range(m):
    parts = input().split()
    command = parts[0]
    if command == 'all':
        mask = FULL
    elif command == 'empty':
        mask = 0
    else:
        bit = 1 << (int(parts[1]) - 1)   # 수 x 는 x-1번 비트
        if command == 'add':
            mask |= bit
        elif command == 'remove':
            mask &= ~bit
        elif command == 'toggle':
            mask ^= bit
        else:                            # check
            out.append('1' if mask & bit else '0')

print('\n'.join(out))

스스로 확인

파이썬에서 ~12의 값은 무엇이고, 왜 그런가?

-13이다. 파이썬 정수는 칸 수가 정해져 있지 않아, 음수를 왼쪽으로 1이 끝없이 이어지는 2의 보수로 다룬다. 모든 칸을 뒤집으면 언제나 -x - 1이 된다.

mask = 0b10110에서 원소 2를 빼는 코드와 그 결과는?

mask & ~(1 << 2)이고 결과는 0b10010이다. 2번 칸만 0인 수와 AND 하므로 그 칸만 지워진다. mask ^ (1 << 2)도 지금은 같은 결과지만, 원소 2가 없을 때는 오히려 넣어 버린다.

sub = (sub - 1) & mask가 mask의 부분집합을 하나도 빠뜨리지 않는 이유는?

sub - 1은 sub 바로 아래 수이고, & mask는 mask 밖의 칸을 지운다. 그 결과는 sub보다 작은 mask의 부분집합 중 가장 큰 것이다. 그래서 부분집합을 큰 것부터 한 단계씩 차례로 밟는다.

도시가 15개인 외판원 문제를 비트 DP로 풀 때 상태 수는 몇 개인가?

215 × 15 = 491,520개다. 상태마다 다음 도시 15개를 보므로 계산은 약 737만 번으로, 14! ≈ 872억 가지 순서를 모두 보는 것보다 훨씬 적다.

정리

  1. 비트 연산자는 같은 자리끼리 계산한다. &는 둘 다, |는 하나라도, ^는 다를 때 1이고, <<·>>는 2k를 곱하고 나눈다.
  2. 파이썬 정수는 크기 제한이 없어서 ~x == -x - 1이다. 정해진 칸만 보려면 & full을 한다.
  3. i번 비트를 원소 i로 보면 정수 하나가 집합이다. 넣기 |, 빼기 & ~, 토글 ^, 확인 >> i & 1이다.
  4. bit_count()는 원소 수, x & -x는 가장 낮은 1, x & (x - 1)은 가장 낮은 1을 지운 수다.
  5. 모든 부분집합은 range(1 << n), 특정 집합의 부분집합은 sub = (sub - 1) & mask로 돈다.
  6. 쓴 것들의 집합이 상태인 DP는 마스크를 인덱스로 쓴다. 상태 수 2ⁿ · n이라 n이 20 안팎일 때 쓴다.
  7. +, -가 <<보다 먼저 계산되므로 비트 연산에는 괄호를 친다.
