직접 만들기 전에 꺼내 쓰기

핵심

큐, 힙, 이진 탐색, 순열과 조합은 직접 짜지 말고 내장 모듈을 꺼내 쓴다. 이미 검증되어 있고, 대부분 C로 구현되어 있어 손으로 짠 파이썬 코드보다 빠르다.

이 장은 도구마다 "언제 꺼내는지"와 "얼마나 빠른지"를 정리한다. 왜 빠른지는 표의 오른쪽에 적은 장에서 설명한다. 이미 다룬 Counter, defaultdict, cache는 빼고 나머지를 본다.

deque: 양쪽 끝이 빠른 큐

collections.deque(데크, double-ended queue)는 양쪽 끝에서 넣고 빼는 일이 모두 빠른 자료형이다. 먼저 넣은 것을 먼저 꺼내는 큐(11장)가 필요하면 리스트 대신 deque를 쓴다.


from collections import deque

q = deque([1, 2, 3])
q.append(4)          # 오른쪽 끝에 넣기
q.appendleft(0)      # 왼쪽 끝에 넣기
print(q)

print(q.popleft())   # 왼쪽 끝에서 꺼내기
print(q.pop())       # 오른쪽 끝에서 꺼내기
print(q)
print(q[0], q[-1])   # 양 끝은 인덱스로 바로 본다

4
deque([1, 2, 3])

리스트로 만든 큐가 느린 이유

리스트는 원소를 메모리에 빈틈없이 줄지어 둔다(8장). 맨 앞 원소를 빼면 빈자리를 메우려고 뒤의 원소를 모두 한 칸씩 당겨야 한다. 원소가 n개면 n번 가까이 옮기므로 pop(0)과 insert(0, x)는 O(n)이다. 큐에서 원소를 n번 꺼내면 전체가 O(n²)이 된다.

deque는 원소를 작은 블록 여러 개에 나눠 담고, 블록끼리 앞뒤로 이어 둔다. 끝에서 넣고 빼면 끝 블록만 건드리므로 다른 원소를 옮길 일이 없다. 대신 가운데 원소를 인덱스로 찾으려면 가까운 끝에서부터 블록을 따라가야 해서 O(n)이 걸린다. 그래서 deque는 for i in range(len(d))처럼 인덱스로 훑지 말고 for x in d:로 훑는다.

하는 일listdeque
오른쪽 끝에 넣기 · 빼기append · pop() O(1)*append · pop() O(1)
왼쪽 끝에 넣기insert(0, x) O(n)appendleft(x) O(1)
왼쪽 끝에서 빼기pop(0) O(n)popleft() O(1)
가운데를 인덱스로 보기a[i] O(1)d[i] O(n)

* 평균으로 따진 값이다. 8장에서 다룬다.

rotate와 maxlen


from collections import deque

d = deque([1, 2, 3, 4, 5])
d.rotate(2)               # 오른쪽으로 두 칸 (음수면 왼쪽)
print(d)

recent = deque([10, 20, 30], maxlen=3)
recent.append(40)         # 가득 차 있으면 반대쪽 끝이 밀려난다
print(recent)

deque([4, 5, 1, 2, 3])
deque([20, 30, 40], maxlen=3)

rotate는 둥글게 앉아 차례를 넘기는 문제에, maxlen은 "가장 최근 k개"만 들고 있어야 할 때 편하다.

heapq: 가장 작은 값부터 꺼내기

값을 넣으면서 그때그때 가장 작은 값을 꺼내야 할 때, 매번 정렬하면 느리다. heapq는 보통의 리스트를 최소 힙으로 다룬다. 최소 힙은 가장 작은 값이 언제나 맨 앞에 오도록 유지하는 자료구조다(17장).


import heapq

heap = []
for x in [5, 3, 8, 1, 9, 2]:
    heapq.heappush(heap, x)
print(heap)              # 정렬된 상태가 아니다
print(heap[0])           # 맨 앞은 언제나 최솟값

print(heapq.heappop(heap))
print(heapq.heappop(heap))
print(heap)

nums = [5, 3, 8, 1, 9, 2]
heapq.heapify(nums)      # 이미 있는 리스트를 힙으로 바꾼다
print(nums)

[1, 3, 2, 5, 9, 8]
1
1
2
[3, 5, 8, 9]
[1, 3, 2, 5, 9, 8]

처음 출력한 [1, 3, 2, 5, 9, 8]은 정렬되어 있지 않다. 힙이 지키는 약속은 하나뿐이다. 인덱스 k의 값은 그 자식인 인덱스 2k+1, 2k+2의 값보다 크지 않다. 이 약속만으로도 최솟값은 언제나 heap[0]에 있다.

전체를 정렬해 두지 않고 이 약속만 지키기 때문에 빠르다. 힙은 리스트를 트리처럼 보고, 값을 넣거나 뺄 때 트리의 높이만큼, 즉 log n번 정도만 자리를 바꿔 약속을 되살린다.

하는 일코드시간
넣기heappush(h, x)O(log n)
최솟값 꺼내기heappop(h)O(log n)
최솟값 보기h[0]O(1)
리스트를 힙으로 바꾸기heapify(a)O(n)

값이 처음부터 모여 있다면 하나씩 heappush하는 것(O(n log n))보다 heapify 한 번(O(n))이 빠르다.

최대 힙은 부호를 뒤집는다

heapq는 최소 힙만 지원한다. 가장 큰 값부터 꺼내려면 넣을 때 부호를 뒤집고, 꺼낼 때 다시 뒤집는다. 가장 큰 수가 가장 작은 음수가 되므로 맨 앞에 온다.


import heapq

scores = [70, 95, 82, 64]
max_heap = []
for score in scores:
    heapq.heappush(max_heap, -score)   # 부호를 뒤집어 넣는다

print(-heapq.heappop(max_heap))        # 꺼낼 때 다시 뒤집는다
print(-max_heap[0])                    # 볼 때도 뒤집는다

95
82

우선순위와 함께 넣기

튜플은 첫 번째 값끼리 비교하고, 같으면 두 번째 값끼리 비교한다. 그래서 (우선순위, 데이터) 꼴로 넣으면 우선순위가 작은 것부터 꺼낼 수 있다.


import heapq

tasks = []
heapq.heappush(tasks, (2, '빨래'))
heapq.heappush(tasks, (1, '설거지'))
heapq.heappush(tasks, (3, '청소'))
heapq.heappush(tasks, (1, '분리수거'))

while tasks:
    priority, name = heapq.heappop(tasks)
    print(priority, name)

1 분리수거
1 설거지
2 빨래
3 청소

우선순위가 1로 같은 두 작업은 이름끼리 비교해 순서가 정해졌다. 두 번째 값이 딕셔너리처럼 서로 비교할 수 없는 값이면 TypeError가 난다. 그럴 때는 (우선순위, 넣은 순번, 데이터)처럼 겹치지 않는 순번을 가운데에 끼운다.

가장 작은 것 k개나 가장 큰 것 k개만 필요하면 heapq.nsmallest(k, a)와 heapq.nlargest(k, a)를 쓴다. k가 1이면 min()과 max()가, k가 n에 가까우면 sorted()가 낫다.

bisect: 정렬된 리스트에서 자리 찾기

bisect는 이미 정렬된 리스트에서 어떤 값이 들어갈 자리를 찾는다. 범위를 절반씩 줄여 가며 찾는 이진 탐색(20장)을 쓰므로 O(log n)이다. 원소가 100만 개여도 20번 정도 비교하면 끝난다.


from bisect import bisect_left, bisect_right

a = [1, 2, 2, 2, 4, 7]
print(bisect_left(a, 2))     # 2가 처음 나오는 자리
print(bisect_right(a, 2))    # 마지막 2의 바로 다음 자리
print(bisect_left(a, 3))     # 없는 값이면 두 결과가 같다
print(bisect_right(a, 3))
print(bisect_right(a, 2) - bisect_left(a, 2))   # 2의 개수

1
4
4
4
3

두 함수는 같은 값이 여러 개 있을 때만 결과가 다르다. bisect_left는 x 이상인 값이 처음 나오는 자리를, bisect_right는 x 보다 큰 값이 처음 나오는 자리를 돌려준다. 그래서 두 결과의 차이가 곧 x의 개수다. 리스트에 없는 값이면 두 결과가 같아 개수는 0이 된다.

범위 안의 개수 세기


from bisect import bisect_left, bisect_right


def count_in_range(a: list[int], lo: int, hi: int) -> int:
    """정렬된 a에서 lo 이상 hi 이하인 값의 개수."""
    return bisect_right(a, hi) - bisect_left(a, lo)


scores = [52, 64, 71, 71, 80, 88, 95]   # 정렬되어 있다
print(count_in_range(scores, 70, 89))
print(count_in_range(scores, 96, 100))

4
0

정렬은 처음에 한 번만 하면 되고(O(n log n)), 그다음부터는 질문마다 O(log n)으로 답한다. 하나씩 세면 질문마다 O(n)이니 질문이 많을수록 차이가 커진다.

정렬을 유지하며 넣기와 key


import bisect

a = [10, 20, 40]
bisect.insort(a, 30)          # 정렬을 유지한 채 끼워 넣는다
print(a)

# key=: 원소에서 비교할 값을 꺼낸다 (3.10부터)
people = [('민수', 21), ('지아', 25), ('도윤', 30)]  # 나이순
print(bisect.bisect_left(people, 25, key=lambda p: p[1]))

[10, 20, 30, 40]
1

insort는 자리를 O(log n)에 찾지만, 끼워 넣을 때 뒤의 원소를 한 칸씩 밀어야 해서 전체로는 O(n)이다. bisect_left에 key를 주면 x 자리에는 원소가 아니라 키 값(25)을 넘긴다. insort에 key를 줄 때는 반대로 원소 전체를 넘긴다.

함수돌려주는 것시간
bisect_left(a, x)a[i] >= x인 첫 인덱스 iO(log n)
bisect_right(a, x)a[i] > x인 첫 인덱스 iO(log n)
insort(a, x)없음. 정렬을 유지하며 x를 넣는다O(n)

itertools: 순열, 조합, 누적합

"가능한 경우를 모두 만들어 보는" 문제에는 순열과 조합이 필요하다. 반복문을 몇 겹씩 쓰지 않아도 itertools가 만들어 준다. 순열은 고른 것의 순서까지 따지는 경우이고, 조합은 무엇을 골랐는지만 따지는 경우다.


from itertools import (combinations, combinations_with_replacement,
                       permutations, product)


def show(groups) -> None:
    print(' '.join(''.join(g) for g in groups))


items = 'ABC'
show(permutations(items, 2))                   # 순서 O, 반복 X
show(combinations(items, 2))                   # 순서 X, 반복 X
show(combinations_with_replacement(items, 2))  # 순서 X, 반복 O
show(product(items, repeat=2))                 # 순서 O, 반복 O

반복자는 한 번만 쓸 수 있다

itertools의 함수는 결과를 한꺼번에 만들어 두지 않는다. 다음 값을 요청할 때마다 하나씩 만들어 주는 반복자(iterator)를 돌려준다. 메모리를 거의 쓰지 않는 대신, 한 번 끝까지 훑으면 비어 버린다.


from itertools import combinations

pairs = combinations([1, 2, 3], 2)   # 아직 아무것도 만들지 않았다
print(next(pairs))    # 요청하면 하나를 만든다
print(list(pairs))    # 남은 것을 모두 만든다
print(list(pairs))    # 이미 다 써서 비어 있다

(1, 2)
[(1, 3), (2, 3)]
[]

accumulate로 누적합 만들기

누적합(prefix sum)은 앞에서부터 차례로 더해 온 합을 모아 둔 리스트다. 한 번 만들어 두면 어떤 구간의 합이든 뺄셈 한 번, 즉 O(1)로 구한다.


from itertools import accumulate

nums = [3, 1, 4, 1, 5, 9]
prefix = list(accumulate(nums, initial=0))
print(prefix)

# nums[i:j]의 합 = prefix[j] - prefix[i]
i, j = 1, 4
print(prefix[j] - prefix[i], sum(nums[i:j]))

print(list(accumulate(nums, max)))   # 지금까지의 최댓값

[0, 3, 4, 8, 9, 14, 23]
6 6
[3, 3, 4, 4, 5, 9]

initial=0을 주면 맨 앞에 0이 붙어 prefix[k]가 "앞의 k개의 합"이 된다. 그래서 i가 0일 때도 같은 식으로 구간 합이 나온다. 두 번째 인자로 max 같은 함수를 주면 덧셈 대신 그 함수로 누적한다.

큰 정수는 실수를 거치지 않는다

파이썬의 정수는 아무리 커도 정확하다(2장). 그런데 ** 0.5나 /를 쓰는 순간 결과가 실수(float)로 바뀐다. 실수는 유효 숫자가 십진수로 15~16자리쯤이라, 그보다 긴 정수는 끝자리가 반올림될 수 있다.


import math

n = 10**16 - 1          # 참값의 제곱근은 99999999.99999999…
print(int(n ** 0.5))    # 실수로 바뀌며 반올림되어 틀린다
print(math.isqrt(n))    # 정수로만 계산해 정확하다
print(float(n) == 10**16)

99999999
True

n을 실수로 바꾸는 순간 1016이 되어 버리고, 그 제곱근인 1억이 답으로 나온다. isqrt는 정수만으로 계산해 99999999를 정확히 돌려준다. 올림 나눗셈도 같은 함정이 있다.


import math

a, b = 10**17 + 1, 3
print(math.ceil(a / b))   # a / b가 실수라 끝자리가 틀린다
print(-(-a // b))         # 정수만으로 올림 나눗셈

33333333333333332
33333333333333334

-a // b는 −a/b를 내림(1장)하므로 a/b를 올림한 값에 마이너스가 붙은 수가 된다. 부호를 한 번 더 뒤집으면 올림이 된다.

최솟값의 초깃값은 math.inf

초깃값을 math.inf로 두면 처음 비교하는 수가 반드시 이긴다. 999999 같은 수를 지어내다 실제 값보다 작게 잡는 실수를 막는다. 최댓값을 찾을 때는 -math.inf를 쓴다.

자주 하는 실수

빈 힙에서 꺼내기

빈 리스트에 heappop을 하면 IndexError: index out of range가 나고, heap[0]으로 보려 해도 IndexError가 난다. 꺼내기 전에 while heap:이나 if heap:으로 비었는지 확인한다.

최대 힙에서 부호를 되돌리지 않기

-x로 넣었다면 꺼낸 값과 heap[0]에도 다시 -를 붙인다. 하나라도 빠뜨리면 음수가 답으로 나온다.

정렬하지 않은 리스트에 bisect 쓰기

bisect는 리스트가 정렬되어 있다고 믿고 절반씩 건너뛴다. 정렬되어 있지 않으면 에러 없이 엉뚱한 값을 돌려준다. bisect_left([7, 1, 3], 7)은 7이 인덱스 0에 있는데도 3을 돌려준다. 쓰기 전에 정렬되어 있는지 확인한다.

다 쓴 반복자를 다시 쓰기

combinations의 결과를 한 번 훑고 나면 두 번째 반복문은 에러 없이 아무 일도 하지 않아 찾기 어렵다. 반복자에는 len()도 쓸 수 없다(TypeError). 여러 번 쓰거나 개수가 필요하면 list()로 바꿔 둔다.

대표 문제

Problem쉬움조합itertools

카드 세 장 고르기

양의 정수가 적힌 카드 N장(3 ≤ N ≤ 100)과 한도 M이 주어진다. 카드 중 서로 다른 세 장을 골라, 적힌 수의 합이 M을 넘지 않으면서 M에 가장 가깝게 만들려고 한다. 그때의 합을 출력하라. 조건을 만족하는 세 장은 언제나 있다고 가정한다.

첫째 줄에 N과 M이, 둘째 줄에 카드에 적힌 수 N개가 공백으로 구분되어 주어진다.

입력출력이유
5 21
4 9 6 11 3		2111 + 6 + 4 = 21로 한도와 딱 맞는다
7 100
23 41 17 38 52 9 30		9952 + 38 + 9 = 99. 합이 100인 세 장은 없다
접근 방법먼저 생각해 보고 펼치세요

"서로 다른 세 장을 고른다"는 순서를 따지지 않고 같은 카드를 두 번 쓰지 않는 선택이다. 이것이 정확히 조합이고, combinations(cards, 3)이 모든 경우를 만들어 준다.

  1. 먼저 경우의 수를 센다. N이 최대 100이면 math.comb(100, 3) = 161,700가지라 모두 확인해도 충분히 빠르다.
  2. 세 장씩 합을 구해, M 이하인 합 중 가장 큰 값을 기억한다.
  3. 끝까지 본 뒤 기억해 둔 값을 출력한다.
풀이 코드 

import sys
from itertools import combinations

input = sys.stdin.readline


def best_sum(cards: list[int], limit: int) -> int:
    best = 0                        # 카드는 양수라 0이면 충분하다
    for trio in combinations(cards, 3):
        total = sum(trio)
        if best < total <= limit:   # 한도 안에서 더 가까우면 바꾼다
            best = total
    return best


n, m = map(int, input().split())
cards = list(map(int, input().split()))
print(best_sum(cards, m))

7 100
23 41 17 38 52 9 30

99
복잡도
시간
O(N³) 세 장을 고르는 경우가 N(N−1)(N−2)/6가지다. N = 100이면 161,700가지라 바로 끝난다.
공간
O(N) 카드 목록만 저장한다. combinations는 세 장짜리 튜플을 하나씩 만들어 주므로 경우의 수만큼 메모리를 쓰지 않는다.

N이 500이면 경우가 2천만 개를 넘어 느려진다. 그때는 정렬한 뒤 투 포인터를 써서 O(N²)으로 줄인다(21장).

스스로 확인

큐를 리스트로 만들고 pop(0)으로 꺼내면 무엇이 문제인가? deque의 popleft()는 왜 괜찮은가?

리스트는 맨 앞을 빼면 뒤의 원소를 모두 한 칸씩 당겨야 해서 pop(0)이 O(n)이다. deque는 끝에서 빼도 다른 원소를 옮기지 않아 popleft()가 O(1)이다.

힙 리스트 [1, 3, 2, 5, 9, 8]에서 heap[1]은 두 번째로 작은 값인가?

아니다. 힙이 보장하는 것은 부모가 자식보다 크지 않다는 것뿐이다. 두 번째로 작은 값은 0번의 자식인 1번과 2번 중 하나이고, 여기서는 heap[2]인 2다.

정렬된 a = [10, 20, 20, 30, 30, 30, 40]에서 20 이상 30 이하인 값의 개수를 bisect로 구하면?

bisect_right(a, 30) - bisect_left(a, 20) = 6 − 1 = 5다. 20, 20, 30, 30, 30의 다섯 개와 맞는다.

정수 n의 제곱근을 구할 때 int(n ** 0.5) 대신 math.isqrt(n)을 쓰는 이유는?

n ** 0.5는 계산 도중 실수로 바뀐다. 큰 n은 반올림되어 답이 틀릴 수 있다. isqrt는 정수만으로 계산해 정확하다.

정리

  1. 큐, 힙, 이진 탐색, 순열과 조합은 직접 만들기 전에 내장 모듈부터 찾는다. 검증되어 있고 빠르다.
  2. 양쪽 끝에서 넣고 빼면 deque를 쓴다. 양 끝 연산은 모두 O(1)이고, 리스트의 pop(0)은 O(n)이다.
  3. heapq는 리스트를 최소 힙으로 다룬다. 넣고 빼기는 O(log n), 최솟값 보기는 O(1)이다. 최대 힙은 부호를 뒤집어 만든다.
  4. bisect는 정렬된 리스트에서 자리를 O(log n)에 찾는다. bisect_right - bisect_left가 개수다.
  5. itertools의 순열과 조합은 개수가 매우 빨리 커지니 먼저 세어 본다. 반복자는 한 번만 쓸 수 있다.
  6. accumulate(nums, initial=0)로 누적합을 만들면 구간 합을 O(1)에 구한다.
  7. 큰 정수는 실수를 거치지 않게 math.isqrt, //, -(-a // b)처럼 정수 연산으로 계산한다.
