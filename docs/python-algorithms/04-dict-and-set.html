본문으로 건너뛰기

딕셔너리와 집합

이름표(키)로 값을 바로 꺼내는 딕셔너리와, 중복 없이 "있는지 없는지"만 기억하는 집합을 다룹니다. 둘 다 해시 덕분에 데이터가 아무리 많아도 거의 한 번에 찾습니다.

dict · set해시Counterdefaultdict두 수의 합

이 장에서 배울 것

  • 리스트의 in보다 딕셔너리·집합의 in이 빠른 이유를 해시로 설명할 수 있다
  • 딕셔너리에 값을 넣고, 찾고, 지우고, 순회할 수 있다
  • get, defaultdict, Counter로 개수를 세고 같은 것끼리 묶을 수 있다
  • 집합으로 중복을 없애고 합집합·교집합·차집합을 구할 수 있다
  • 어떤 값이 키가 될 수 있는지와 그 이유를 안다

해시로 바로 찾기

핵심

딕셔너리와 집합은 키를 해시 값으로 바꿔, 저장된 칸으로 바로 찾아간다. 그래서 데이터가 많아져도 찾는 시간이 거의 늘지 않는다.

리스트에서 x in a를 하면 파이썬은 맨 앞 원소부터 하나씩 비교한다. 원소가 백만 개이고 찾는 값이 없으면 백만 번을 비교하므로 O(n)이다.

번호가 붙은 사물함을 떠올려 보자. 열쇠에 "17번"이라고 적혀 있으면 1번부터 열어 볼 필요 없이 17번 앞으로 바로 가면 된다. 딕셔너리와 집합에서 키에 번호를 매기는 것이 해시 함수다.

해시 함수(hash function)는 값을 받아 정해진 규칙으로 정수 하나를 만드는 함수다. 이 정수를 해시 값이라고 한다. 같은 값을 넣으면 언제나 같은 해시 값이 나온다. 파이썬에서는 hash()로 직접 볼 수 있다.


print(hash(42))                        # 작은 양의 정수는 자기 자신
print(hash('apple') == hash('apple'))  # 같은 값이면 언제나 같은 해시
print(hash((1, 2)) == hash((1, 2)))

42
True
True

문자열의 해시 값은 보안을 위해 프로그램을 실행할 때마다 달라진다. 한 번 실행되는 동안에는 변하지 않으니 찾기에는 문제가 없지만, 문자열을 담은 집합은 출력 순서가 실행마다 바뀔 수 있다. 이 장의 예제가 집합을 출력할 때 늘 sorted()로 감싸는 이유다.

딕셔너리는 안쪽에 칸이 여러 개인 표를 두고, 키의 해시 값으로 넣을 칸을 정한다. 실제 규칙은 더 복잡하지만 "해시 값을 칸 수로 나눈 나머지"라고 생각해도 원리는 같다.

자료형x in 자료가 하는 일시간
list앞에서부터 하나씩 비교한다O(n)
dict, set해시 값으로 칸을 계산해 그 칸만 확인한다O(1) 평균

"평균"이 붙는 이유는 충돌(collision) 때문이다. 서로 다른 키가 같은 칸을 가리키면 몇 번 더 비교해야 하고, 충돌이 극단적으로 몰리면 최악에는 O(n)이 된다. 파이썬은 표가 어느 정도 차면 칸을 늘려 충돌을 줄이므로 실제로는 거의 항상 O(1)이다. 충돌은 12장에서 다룬다.

딕셔너리 기본

딕셔너리(dict)는 키(key)와 값(value)을 짝지어 저장하는 자료형이다. 사전에서 단어로 뜻을 찾듯 키로 값을 찾는다.


scores = {'kim': 90, 'lee': 75}

print(scores['kim'])          # 키로 값 읽기
scores['park'] = 82           # 없는 키에 대입하면 새로 추가
scores['lee'] = 80            # 있는 키에 대입하면 덮어쓰기
print(scores)

print('lee' in scores)        # in 은 키가 있는지 본다
print(80 in scores)           # 값은 보지 않는다
print(len(scores))

del scores['kim']             # 지우기
removed = scores.pop('park')  # 지우면서 값을 돌려받기
print(removed, scores)

{'kim': 90, 'lee': 80, 'park': 82}
True
False
3
82 {'lee': 80}

80 in scores가 False인 데 주의한다. 딕셔너리의 in은 키만 확인한다. 값을 찾으려면 80 in scores.values()라고 써야 하고, 이때는 하나씩 비교하므로 O(n)이다.

없는 키를 읽을 때

d[k]로 없는 키를 읽으면 KeyError가 난다. 키가 없을 수도 있다면 에러 대신 기본값을 돌려주는 get을 쓴다.


stock = {'apple': 3}

print(stock.get('apple'))      # 키가 있으면 값
print(stock.get('pear'))       # 없으면 None
print(stock.get('pear', 0))    # 없을 때 돌려줄 값을 정할 수 있다

try:
    print(stock['pear'])
except KeyError as e:
    print(f'{type(e).__name__}: {e}')

3
None
0
KeyError: 'pear'

지울 때도 같다. del d[k]와 d.pop(k)는 키가 없으면 KeyError를 내지만, d.pop(k, None)처럼 기본값을 주면 조용히 기본값을 돌려준다.

순회하기

딕셔너리를 그냥 돌면 키가 나오고, items()로 돌면 키와 값이 짝으로 나온다. 순서는 넣은 순서이고, 파이썬 3.7부터 언어 규칙으로 보장된다.


ages = {'kim': 25, 'lee': 31, 'park': 28}

for name in ages:                 # 그냥 돌면 키가 나온다
    print(name)

for name, age in ages.items():    # 키와 값을 함께 꺼낸다
    print(name, age)

print(list(ages.values()))        # 값만 모으기

딕셔너리 컴프리헨션

리스트 컴프리헨션(3장)처럼 중괄호 안에 키: 값을 적어 한 줄로 만들 수 있다.


words = ['apple', 'kiwi', 'banana']

lengths = {w: len(w) for w in words}
print(lengths)

세기와 묶기

코딩 테스트에서 딕셔너리를 가장 많이 쓰는 곳은 몇 번 나왔는지 세기와 같은 것끼리 묶기다. 방법은 세 가지이고, 결과는 같으며 쓰기 편한 정도만 다르다.

get으로 세기

처음 보는 키는 0에서, 본 적 있는 키는 원래 값에서 1을 더한다. get(name, 0)이 두 경우를 한 줄로 처리한다.


votes = ['kim', 'lee', 'kim', 'park', 'kim', 'lee']

count = {}
for name in votes:
    count[name] = count.get(name, 0) + 1   # 처음이면 0에서 시작
print(count)

{'kim': 3, 'lee': 2, 'park': 1}

defaultdict: 없는 키를 알아서 만든다

collections.defaultdict는 없는 키를 읽는 순간 기본값을 만들어 넣는 딕셔너리다. 괄호 안에 기본값을 만들 함수를 넘긴다. int()는 0을, list()는 빈 리스트를 돌려주므로 각각 세기와 묶기에 알맞다.


from collections import defaultdict

votes = ['kim', 'lee', 'kim', 'park', 'kim', 'lee']
count = defaultdict(int)          # 없는 키는 int() == 0 으로 시작
for name in votes:
    count[name] += 1
print(dict(count))

# 첫 글자가 같은 단어끼리 묶기
words = ['apple', 'banana', 'avocado', 'blueberry', 'cherry']
groups = defaultdict(list)        # 없는 키는 빈 리스트로 시작
for w in words:
    groups[w[0]].append(w)
print(dict(groups))

{'kim': 3, 'lee': 2, 'park': 1}
{'a': ['apple', 'avocado'], 'b': ['banana', 'blueberry'], 'c': ['cherry']}

일반 딕셔너리였다면 "키가 없으면 빈 리스트부터 넣는다"는 확인을 매번 해야 한다. 출력할 때 감싼 dict()는 모양을 보기 좋게 바꿀 뿐이다.

읽기만 해도 키가 생긴다

defaultdict는 count['choi']처럼 읽기만 해도 'choi': 0을 새로 넣는다. 그래서 if count['choi'] > 0:처럼 확인만 하려던 코드가 딕셔너리를 몰래 키운다. 키가 있는지 볼 때는 'choi' in count를 쓴다.

Counter: 세기 전용 도구

collections.Counter는 세는 일만을 위한 딕셔너리다. 리스트나 문자열을 통째로 넘기면 한 번에 센다. 없는 키를 읽으면 0을 돌려주지만 키를 만들지는 않는다.


from collections import Counter

votes = ['kim', 'lee', 'kim', 'park', 'kim', 'lee']
count = Counter(votes)
print(count)
print(count['kim'], count['choi'])   # 없는 키는 0
print(count.most_common(2))          # 많이 나온 순서로 2개

print(Counter('banana'))             # 문자열은 글자 단위로 센다

집합

집합(set)은 값 없이 키만 모아 둔 딕셔너리라고 생각하면 된다. 같은 값은 하나만 들어가고, 해시로 찾으니 in이 평균 O(1)이다. 대신 순서가 없어서 s[0] 같은 인덱스 접근은 할 수 없다. 빈 집합은 {}가 아니라 set()으로 만든다. {}는 빈 딕셔너리다.


nums = {3, 1, 3, 2, 1}
print(sorted(nums))        # 중복은 저절로 사라진다

nums.add(5)
nums.discard(9)            # 없는 값이어도 조용히 넘어간다
try:
    nums.remove(9)         # 없는 값이면 KeyError
except KeyError as e:
    print(f'{type(e).__name__}: {e}')

print(2 in nums, len(nums))
print(sorted({x % 3 for x in range(10)}))   # 집합 컴프리헨션

[1, 2, 3]
KeyError: 9
True 4
[0, 1, 2]

꼭 있어야 하는 값이면 remove로 실수를 일찍 잡고, 없어도 되면 discard를 쓴다.

중복 없애기: 순서를 지킬까 말까

중복을 없애는 가장 짧은 방법은 집합으로 바꾸는 것이지만, list(set(data))의 순서는 보장되지 않는다. 처음 나온 순서를 지키려면 원소를 딕셔너리의 키로 넣는 dict.fromkeys를 쓴다. 키는 중복 없이 넣은 순서대로 남는다.


data = [5, 3, 5, 1, 3, 9]

print(sorted(set(data)))           # 정렬된 결과가 필요할 때
print(list(dict.fromkeys(data)))   # 처음 나온 순서를 지킬 때

[1, 3, 5, 9]
[5, 3, 1, 9]

집합 연산

집합은 합집합, 교집합, 차집합을 연산자 하나로 계산한다. "두 목록에 모두 있는 것"이나 "한쪽에만 있는 것"을 반복문 없이 바로 구할 수 있다.


a = {1, 2, 3, 4}
b = {3, 4, 5, 6}

print(sorted(a | b))   # 합집합: 어느 한쪽에라도 있는 것
print(sorted(a & b))   # 교집합: 양쪽 모두에 있는 것
print(sorted(a - b))   # 차집합: a 에만 있는 것
print(sorted(b - a))   # 차집합은 순서를 바꾸면 결과가 다르다
print(sorted(a ^ b))   # 대칭차집합: 한쪽에만 있는 것

[1, 2, 3, 4, 5, 6]
[3, 4]
[1, 2]
[5, 6]
[1, 2, 5, 6]
연산연산자메서드결과
합집합a | ba.union(b)어느 한쪽에라도 있는 원소
교집합a & ba.intersection(b)양쪽 모두에 있는 원소
차집합a - ba.difference(b)a에만 있는 원소
대칭차집합a ^ ba.symmetric_difference(b)한쪽에만 있는 원소

연산자는 양쪽이 모두 집합이어야 하고, 메서드는 리스트도 받는다. a | [7, 8]은 TypeError지만 a.union([7, 8])은 동작한다.

써먹기: 빠진 번호 찾기

출석 번호가 1번부터 10번까지인 반에서 과제를 내지 않은 번호는 "전체 번호 − 낸 번호", 곧 차집합이다. 두 번 낸 번호는 집합으로 바꿀 때 하나로 합쳐진다.


submitted = [3, 7, 1, 10, 4, 7, 2]      # 두 번 낸 사람도 있다
everyone = set(range(1, 11))

missing = everyone - set(submitted)
print(sorted(missing))

[5, 6, 8, 9]

키가 될 수 있는 것

딕셔너리의 키와 집합의 원소는 해시 값을 계산할 수 있어야 한다. 이런 값을 해시 가능(hashable)하다고 한다. 내용이 바뀌지 않는(불변) 값이면 대부분 키가 될 수 있다.

그림 4-1을 떠올리면 이유를 알 수 있다. 키를 넣은 뒤 내용이 바뀌면 해시 값도 바뀌어, 찾을 때 계산한 칸과 실제로 들어 있는 칸이 어긋난다. 그래서 파이썬은 내용을 바꿀 수 있는 리스트를 키로 받지 않는다.

자료형키가 되는가이유
int, float, str, bool된다불변이다
tuple원소가 모두 해시 가능할 때만(1, 2)는 되고 (1, [2])는 안 된다
frozenset된다바꿀 수 없는 집합이다
list, dict, set안 된다내용을 바꿀 수 있다
 

pos = {}
pos[(0, 1)] = 'start'           # 튜플은 키가 된다
print(pos[(0, 1)])

for key in ([0, 1], (0, [1])):  # 리스트, 리스트를 품은 튜플
    try:
        pos[key] = 'x'
    except TypeError as e:
        print(f'{type(e).__name__}: {e}')

start
TypeError: unhashable type: 'list'
TypeError: unhashable type: 'list'

튜플의 해시 값은 원소들의 해시 값으로 계산하므로, 안에 리스트가 있으면 튜플도 키가 될 수 없다. 좌표처럼 여러 값을 묶은 키는 정수만 담은 튜플로 만든다. 격자 지도에서 지나간 칸을 visited.add((r, c))로 집합에 넣어 두면 (r, c) in visited로 평균 O(1)에 확인할 수 있다. 13장의 그래프 탐색에서 이 방식을 다시 쓴다.

연산별 시간복잡도

기본 연산은 해시로 칸을 계산하므로 평균 O(1)이고, 집합끼리의 연산은 원소를 하나씩 확인하므로 크기에 비례한다. 표에서 n은 a(또는 d)의 크기, m은 b의 크기다.

연산코드평균 시간이유
읽기·쓰기d[k], d[k] = vO(1)해시로 칸을 바로 찾는다
지우기del d[k], s.discard(x)O(1)지울 칸을 바로 찾는다
키·원소 확인k in d, x in sO(1)계산한 칸만 본다
값 확인v in d.values()O(n)값은 해시로 찾지 않아 하나씩 비교한다
합집합a | bO(n + m)양쪽 원소를 모두 새 집합에 넣는다
교집합a & bO(min(n, m))작은 쪽을 돌며 큰 쪽에 있는지 본다
차집합a - bO(n)a의 원소마다 b에 있는지 본다

차이가 가장 크게 드러나는 곳은 반복문 안에서 "있는지" 확인할 때다. 질문 n개를 크기 n인 리스트에 in으로 물으면 최악에 n × n번, n이 10만이면 100억 번을 비교한다. 반복문 밖에서 set(lst)로 한 번 바꿔 두면 바꾸는 데 n번, 질문마다 평균 한 번이라 20만 번 정도로 끝난다.

없을 수도 있는 키를 []로 읽기

d[k]는 키가 없으면 KeyError로 멈춘다. get을 쓰거나 if k in d:로 먼저 확인한다.

순회하면서 키를 넣거나 지우기

딕셔너리를 for로 도는 도중에 키를 추가하거나 지우면 RuntimeError가 난다. 있는 키의 값만 바꾸는 것은 괜찮다. 지워야 한다면 list(d)로 키 목록을 복사해 그것을 돌거나, {k: v for k, v in d.items() if 조건}으로 남길 것만 새로 만든다.


stock = {'apple': 0, 'pear': 2, 'kiwi': 0}
try:
    for name in stock:
        if stock[name] == 0:
            del stock[name]        # 도는 중에 크기가 바뀐다
except RuntimeError as e:
    print(f'{type(e).__name__}: {e}')

stock = {'apple': 0, 'pear': 2, 'kiwi': 0}
for name in list(stock):           # 키 목록을 복사해 두고 돈다
    if stock[name] == 0:
        del stock[name]
print(stock)

문자열을 담은 집합은 실행할 때마다 출력 순서가 달라질 수 있다. 내 컴퓨터에서 원하는 순서로 나왔어도 채점 서버에서는 다를 수 있다. 순서가 필요하면 sorted()나 dict.fromkeys를 쓴다.

Problem쉬움딕셔너리

두 수의 합

정수 리스트 nums와 정수 target이 주어진다. nums에서 더해서 target이 되는 두 원소를 찾아, 두 원소의 인덱스를 작은 것부터 담은 리스트로 돌려주는 함수 two_sum(nums, target)을 작성하라.

  • 답은 언제나 정확히 하나 있다.
  • 같은 원소를 두 번 쓸 수는 없다. 값이 같은 서로 다른 원소는 쓸 수 있다.
  • nums의 길이는 2 이상 100,000 이하이고, 음수가 들어 있을 수 있다.
numstarget출력이유
[4, 9, 2, 7]9[2, 3]2 + 7 = 9
[6, -2, 11, 3]1[1, 3]-2 + 3 = 1
[3, 3, 8]6[0, 1]값은 같아도 서로 다른 원소다
접근 방법먼저 생각해 보고 펼치세요

먼저 떠오르는 방법은 모든 쌍을 더해 보는 것이다.


def two_sum_slow(nums: list[int], target: int) -> list[int]:
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):     # 모든 쌍을 한 번씩 본다
            if nums[i] + nums[j] == target:
                return [i, j]
    return []


print(two_sum_slow([4, 9, 2, 7], 9))

[2, 3]

쌍이 n(n-1)/2개라 O(n²)이다. n이 10만이면 약 50억 쌍이라 시간 안에 끝나지 않는다.

관점을 바꿔 보자. 지금 보는 수가 x라면 짝은 target - x로 정해져 있다. 그러니 "그 짝이 앞에 나온 적이 있는가?"만 빠르게 알면 된다. 지금까지 본 값을 딕셔너리에 {값: 인덱스}로 적어 두면 평균 O(1)로 답할 수 있다.

  1. 빈 딕셔너리 seen을 만든다.
  2. 원소를 앞에서부터 보며, 짝 need = target - x가 seen에 있으면 [seen[need], i]를 돌려준다.
  3. 없으면 seen[x] = i로 지금 값을 적어 두고 다음 원소로 넘어간다. 짝을 확인한 뒤에 적어야 자기 자신과 짝을 짓지 않는다.
풀이 코드 

def two_sum(nums: list[int], target: int) -> list[int]:
    seen = {}                        # 값 -> 그 값이 나온 인덱스

    for i, x in enumerate(nums):
        need = target - x            # x 와 짝이 될 값
        if need in seen:             # 짝이 앞에 나왔는가: 평균 O(1)
            return [seen[need], i]
        seen[x] = i                  # 확인한 뒤에 적는다

    return []                        # 답이 항상 있으니 여기엔 오지 않는다


print(two_sum([4, 9, 2, 7], 9))
print(two_sum([6, -2, 11, 3], 1))
print(two_sum([3, 3, 8], 6))

[2, 3]
[1, 3]
[0, 1]

seen의 인덱스는 늘 i보다 작아서 결과가 저절로 작은 것부터 담긴다.

복잡도
시간
O(n) 원소를 한 번씩 보고, 원소마다 딕셔너리 확인과 기록이 평균 O(1)이다.
공간
O(n) 답이 맨 끝에 있으면 거의 모든 값을 seen에 적는다.

스스로 확인

리스트의 x in lst는 O(n)인데 집합의 x in s는 평균 O(1)인 이유는?

리스트는 앞에서부터 하나씩 비교한다. 집합은 x의 해시 값으로 칸을 계산해 그 칸만 확인하므로, 원소가 많아져도 확인 횟수가 거의 늘지 않는다.

two_sum에서 seen[x] = i를 짝 확인보다 먼저 하면 어떤 입력에서 틀리는가?

target이 어떤 원소의 두 배일 때 틀린다. nums = [3, 1, 5], target = 6이면 답은 [1, 2]인데, 3을 먼저 적고 짝 3을 찾으면 방금 적은 자기 자신이 나와 [0, 0]을 돌려준다.

count = defaultdict(int)에서 if count['x'] > 0:으로 확인만 하면 무슨 일이 생기는가?

'x'가 없었다면 읽는 순간 'x': 0이 새로 추가된다. 확인만 하려면 'x' in count를 쓰거나, 키를 만들지 않는 Counter를 쓴다.

[[1, 2], [1, 2], [3]]의 중복을 set()으로 없애려 하면 왜 실패하고, 어떻게 고치는가?

리스트는 해시 가능하지 않아 TypeError가 난다. {tuple(x) for x in data}처럼 튜플로 바꿔 넣으면 (1, 2)와 (3,) 두 개가 남는다.

정리

  1. 딕셔너리와 집합은 키를 해시 값으로 바꿔 칸을 바로 찾는다. 그래서 찾기, 넣기, 지우기가 평균 O(1)이다.
  2. 딕셔너리는 넣은 순서를 기억한다. in은 키만 확인하고, 없을 수도 있는 키는 get으로 읽는다.
  3. 세기는 get(k, 0) + 1, defaultdict(int), Counter 중 하나로 하고, 묶기는 defaultdict(list)가 편하다. defaultdict는 읽기만 해도 키가 생긴다.
  4. 집합은 중복을 없애고 | & - ^로 합·교·차집합을 구한다. 순서가 없으니 출력할 때는 sorted()를 쓴다.
  5. 키와 원소는 해시 가능한 불변 값이어야 한다. 리스트 대신 튜플을 쓴다.
  6. 반복문 안에서 "있는지"를 자주 묻는다면 리스트를 집합이나 딕셔너리로 바꿔 O(n²)을 O(n)으로 줄인다.
