자료형과 빅오

숫자 하나, 리스트 하나에도 알고 써야 할 성질이 있습니다. 파이썬 자료형의 특징을 익히고, 코드가 얼마나 빨리 도는지 빅오 표기법으로 어림하는 법을 배웁니다.

int · float가변 · 불변빅오시간 제한

이 장에서 배울 것

  • 파이썬 기본 자료형을 구분하고, 가변과 불변의 차이를 설명할 수 있다
  • int와 float의 차이, 실수 오차와 반올림 함정을 안다
  • 빅오 표기법이 무엇을 재는지 설명하고, 코드에서 복잡도를 읽을 수 있다
  • 문제의 입력 크기를 보고 시간 안에 도는 복잡도를 어림할 수 있다

자료형 한눈에

핵심

자료형마다 할 수 있는 일과 걸리는 시간이 다르다. 알맞은 자료형을 고르는 것이 빠르고 정확한 코드의 출발점이다.

파이썬에서는 변수가 아니라 값(객체)이 자료형을 가진다. 같은 변수에 숫자를 넣었다가 문자열을 넣어도 되는 이유다. 자료형(type)은 그 값이 어떤 종류인지, 그래서 어떤 연산을 할 수 있는지를 정한다.

알고리즘 문제에서 자주 쓰는 자료형은 아래 아홉 가지가 거의 전부다. "가변"은 만든 뒤에 내용을 고칠 수 있다는 뜻이고, "불변"은 고칠 수 없다는 뜻이다. 이 차이는 이 장 뒷부분에서 자세히 본다.

숫자: int와 float

정수는 int, 소수점이 있는 수는 float이다. 둘 다 숫자지만 성질이 꽤 다르다. int는 정확하고 끝이 없으며, float은 빠르지만 근삿값이다.

int에는 크기 제한이 없다

C++의 long long이나 Java의 long은 64비트라는 정해진 칸에 담기기 때문에, 약 9.2 × 1018을 넘으면 값이 엉뚱하게 바뀐다. 이를 오버플로(overflow)라고 한다. 파이썬의 int는 수가 커지면 저장 공간을 알아서 늘리므로 오버플로가 없다.


print(2 ** 100)
print(10 ** 18 * 10 ** 18)

factorial = 1
for i in range(1, 31):     # 30! = 1 × 2 × ... × 30
    factorial *= i
print(factorial)

1267650600228229401496703205376
1000000000000000000000000000000000000
265252859812191058636308480000000

다만 공짜는 아니다. 자릿수가 아주 커지면 덧셈·곱셈 한 번에 걸리는 시간도 그만큼 늘어난다. 코딩 테스트에 나오는 1018 정도의 수는 걱정하지 않아도 된다.

float은 2진수 근삿값이다

float은 수를 2진수 소수로 저장한다. 10진수의 1/3이 0.333…으로 끝나지 않듯, 10진수 0.1은 2진수로 쓰면 끝없이 이어진다. 컴퓨터는 이를 정해진 자리에서 잘라 저장하므로, 0.1은 정확히 0.1이 아니라 0.1에 아주 가까운 값이다.


import math

print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
print(f'{0.1:.20f}')                  # 소수 20자리까지 찍어 보면 보인다
print(math.isclose(0.1 + 0.2, 0.3))   # 충분히 가까우면 True

0.30000000000000004
False

True

그래서 실수끼리는 ==로 비교하지 않는다. math.isclose()로 "충분히 가까운지"를 보거나, 처음부터 정수로 계산하는 편이 낫다. 예를 들어 돈을 다룰 때 3.5원 대신 35전처럼 단위를 바꾸면 오차가 생기지 않는다.

float은 큰 정수를 정확히 담지 못한다

float은 유효 숫자를 약 15~16자리까지만 기억한다. 정확히는 253(약 9 × 1015)을 넘는 정수부터는 끝자리가 뭉개질 수 있다.

print(n)

이 성질 때문에 큰 정수 계산에서 /를 쓰면 틀린 답이 나온다. /는 결과를 언제나 float으로 만들기 때문이다. 이 장의 대표 문제에서 실제로 확인한다.

버림, 내림, 반올림

print(int(2.5 + 0.5))           # 0 이상에서 "사사오입"이 필요할 때

int()는 소수 부분을 그냥 떼어 내므로 -3.7이 -3이 된다. //는 수직선에서 왼쪽으로 내리므로 -3.5가 -4가 된다. round()는 딱 절반일 때 가까운 짝수를 고르는 짝수 반올림이다. 은행가 반올림이라고도 하는데, 많은 수를 반올림해 더할 때 오차가 한쪽으로 쌓이지 않게 하려는 규칙이다. 학교에서 배운 사사오입이 필요하면 0 이상의 수에 한해 int(x + 0.5)처럼 직접 계산한다.

None은 "값이 없음"을 뜻한다

None은 아직 값이 없거나 찾지 못했다는 표시로 쓰는 특별한 값이다. return 없이 끝난 함수도 None을 돌려준다(6장). 프로그램 전체에 None은 딱 하나만 존재하므로, 비교할 때는 같은 객체인지를 묻는 is를 쓴다.

if not x:로 대신하면 안 되는 이유가 있다. 0, 빈 문자열, 빈 리스트도 조건식에서 거짓이 되기 때문이다(1장). 찾은 값이 하필 0이면 "못 찾았다"로 착각한다.


def first_multiple(nums, k):
    for x in nums:
        if x % k == 0:
            return x
    return None            # 못 찾으면 None


found = first_multiple([0, 4, 7], 7)
print(found)
print('is None:', found is None)   # 정확하다: 0을 찾았다
print('not    :', not found)       # 0도 거짓이라 못 찾은 것처럼 보인다

가변과 불변

파이썬의 변수는 값을 담는 상자가 아니라 값에 붙인 이름표에 가깝다. b = a는 값을 복사하지 않는다. 같은 값에 이름표를 하나 더 붙일 뿐이다.

값을 고칠 수 없는 불변 객체라면 이 차이가 드러나지 않는다. 그런데 리스트처럼 고칠 수 있는 가변 객체라면, 한 이름으로 고친 내용이 다른 이름으로도 보인다.


a = [1, 2, 3]
b = a              # 같은 리스트에 이름을 하나 더 붙인다
b.append(4)
print(a)
print(a is b)      # is: 같은 객체인가?

c = a.copy()       # 내용이 같은 "새" 리스트
print(a == c, a is c)
c.append(5)
print(a)
print(c)

==는 "내용이 같은가"를, is는 "같은 객체인가"를 묻는다. c는 내용은 a와 같지만 다른 객체라서, c를 고쳐도 a는 그대로다.

불변 객체는 "고치는" 대신 새로 만든다

int나 str은 불변이라 내용을 고칠 방법 자체가 없다. x += 1은 10을 11로 고치는 것이 아니라, 11이라는 새 객체를 만들어 x라는 이름표를 옮겨 붙인다. 그래서 다른 이름은 영향을 받지 않는다.

y = x
x += 1             # 새 객체 11에 x를 붙인다. y는 여전히 10
print(x, y)

s = 'abc'
t = s

print(s, t)

빅오 표기법

같은 문제를 푸는 코드라도 입력이 커질 때 느려지는 정도가 다르다. 빅오(Big-O) 표기법은 입력 크기 n이 커질 때 기본 연산의 횟수가 어떤 모양으로 늘어나는지를 나타낸다. 기본 연산은 대입, 비교, 사칙연산처럼 한 번에 끝나는 작은 일을 말한다.

빅오는 정확한 횟수가 아니라 늘어나는 모양만 본다. 그래서 두 가지를 버린다.

  • 낮은 차수의 항: 3n² + 5n + 2에서 5n과 2를 버린다.
  • 상수 배: 남은 3n²에서 3을 버려 O(n²)이 된다.

낮은 차수를 버리는 이유는 n이 커지면 가장 높은 차수가 전체를 거의 다 차지하기 때문이다. 직접 계산해 보면 분명하다.


for n in (10, 1000, 1000000):
    total = 3 * n * n + 5 * n + 2
    share = 3 * n * n / total      # 전체 중 n² 항이 차지하는 비율
    print(n, total, f'{share:.6f}')

10 352 0.852273
1000 3005002 0.998335
1000000 3000005000002 0.999998

상수 배를 버리는 이유는 그 값이 컴퓨터, 언어, 구현 방식에 따라 달라지기 때문이다. 반면 "n이 두 배가 되면 연산은 네 배가 된다"는 n²의 성질은 어디서나 같다. 빅오는 이 변하지 않는 성질만 남긴 것이다.

빅오는 엄밀히 말해 "이보다 빨리 늘지는 않는다"는 상한이다. 코딩 테스트에서는 보통 가장 나쁜 입력이 들어왔을 때를 기준으로 따진다.

코드에서 복잡도 읽기

복잡도를 구할 때는 "n이 커지면 이 코드는 몇 번 도는가"만 따지면 된다. 대부분은 반복문의 모양을 보면 바로 나온다. 아래 세 함수는 각자 반복을 몇 번 했는지 세어 돌려준다.


def single_loop(n):
    steps = 0
    for _ in range(n):     # 쓰지 않는 변수는 관례상 _로 쓴다
        steps += 1
    return steps


def nested_loop(n):
    steps = 0
    for _ in range(n):
        for _ in range(n):
            steps += 1
    return steps


def halving_loop(n):
    steps = 0
    while n > 1:
        n //= 2            # 매번 남은 크기가 절반이 된다
        steps += 1
    return steps


for n in (10, 100, 1000):
    print(n, single_loop(n), nested_loop(n), halving_loop(n))

10 10 100 3
100 100 10000 6
1000 1000 1000000 9

n이 100배(10 → 1,000)가 될 때 반복문 하나는 100배, 이중 반복문은 1만 배로 늘었다. 반면 절반씩 줄이는 반복문은 3번에서 9번으로 6번 늘었을 뿐이다.

반복문 하나는 O(n), 겹치면 곱한다

n번 도는 반복문 하나는 O(n)이다. 그 안에 n번 도는 반복문이 또 있으면 n × n이라 O(n²)이다. 반복문이 겹치지 않고 나란히 있으면 곱하지 않고 더한다. O(n) + O(n)은 O(2n)이고, 상수를 버리면 그대로 O(n)이다.

절반씩 줄이면 O(log n)

남은 크기를 매번 절반으로 줄이면 1이 될 때까지 log₂n번 걸린다. log₂n은 "2를 몇 번 곱해야 n이 되는가"이기 때문이다. 20장의 이진 탐색이 이렇게 동작한다.

정렬은 O(n log n)

파이썬의 sorted()와 list.sort()는 O(n log n)이다. 정렬을 한 번 하고 반복문을 한 번 돌면 O(n log n) + O(n)이므로 전체는 더 큰 쪽인 O(n log n)이다. 정렬 알고리즘은 19장에서 다룬다.

한 줄짜리 코드에 숨은 비용

반복문이 안 보인다고 O(1)인 것은 아니다. 내장 함수와 연산자 중에는 안에서 원소를 하나하나 훑는 것이 많다. 아래 코드는 반복문이 하나뿐인 것처럼 보이지만, x in b가 b를 처음부터 끝까지 훑으므로 실제로는 이중 반복문이다.


def count_common(a, b):
    count = 0
    for x in a:            # len(a)번
        if x in b:         # 리스트의 in은 b를 앞에서부터 훑는다
            count += 1
    return count


print(count_common([1, 3, 5, 7], [3, 4, 5, 6]))

시간 제한 어림하기

코딩 테스트 문제에는 "시간 제한 1초"와 "1 ≤ N ≤ 100,000" 같은 입력 범위가 함께 적혀 있다. 이 둘만 있으면 코드를 짜기 전에 어떤 복잡도로 풀어야 하는지 알 수 있다.

어림값

파이썬(CPython)은 단순한 연산을 1초에 대략 1천만 번 안팎 처리한다고 잡는다. 채점 서버의 성능, 연산의 종류, 코드 모양에 따라 몇 배씩 달라지는 거친 기준이다. "이 정도면 확실히 된다 / 확실히 안 된다"를 가르는 용도로만 쓴다.

이 기준으로 입력 크기별로 1초 안에 노려볼 만한 복잡도를 정리하면 다음과 같다.

n의 최댓값노릴 복잡도연산 수 어림
약 10O(n!)10! ≈ 363만
약 20O(2ⁿ)2²⁰ ≈ 105만
약 200O(n³)200³ = 800만
약 3,000O(n²)3,000² = 900만
10만 ~ 50만O(n log n)10만 × 17 ≈ 170만
수백만O(n)n번
10⁹ 이상O(log n), O(1)수십 번 이하
팁

문제를 읽으면 입력 범위부터 본다. N ≤ 100,000이면 O(n²)은 100억 번이라 어림값으로 1,000초쯤 걸린다. 처음부터 O(n log n) 이하의 방법을 찾아야 한다는 뜻이다. 이렇게 복잡도를 거꾸로 정하면 풀이 방향이 빨리 좁혀진다.

백준처럼 PyPy3를 함께 제공하는 채점 사이트도 있다. PyPy3는 실행 중에 코드를 기계어로 바꿔 돌리는 파이썬 구현이라, 반복문이 많은 코드가 CPython보다 훨씬 빨라지는 경우가 많다. 다만 메모리를 더 쓰는 편이고, 복잡도 자체가 맞지 않는 풀이를 구해 주지는 못한다.

자주 하는 실수

실수를 ==로 비교하기

0.1 + 0.2 == 0.3은 False다. 실수 비교는 math.isclose()를 쓰거나, 단위를 바꿔 정수로 계산한다.

큰 정수에 / 쓰기

/의 결과는 항상 float이라 약 9 × 1015을 넘는 정수는 끝자리가 틀어질 수 있다. (10 ** 17 + 1) / 1은 1e+17이 되어 끝의 1이 사라진다. 나누어떨어지는 정수 나눗셈은 //로 한다.

round()를 사사오입으로 믿기

round(2.5)는 3이 아니라 2다. 딱 절반이면 짝수 쪽으로 간다. 게다가 round(2.675, 2)는 2.67이 나오는데, 2.675가 실제로는 그보다 아주 조금 작은 값으로 저장되기 때문이다. 반올림 규칙이 중요한 문제는 정수로 바꿔 직접 계산한다.

b = a를 복사로 착각하기

리스트에 b = a를 하고 b를 고치면 a도 바뀐다. 따로 쓰려면 a.copy()로 복사본을 만든다.

is로 값 비교하기

is는 내용이 아니라 같은 객체인지를 묻는다. 숫자나 문자열에 쓰면 실행 환경에 따라 결과가 달라질 수 있다. 값 비교는 언제나 ==로 하고, is는 None을 확인할 때만 쓴다.

Problem쉬움수학빅오

1부터 N까지의 합

정수 N이 한 줄로 주어진다(1 ≤ N ≤ 1018). 1부터 N까지 모든 정수의 합을 정확하게 출력하라. 시간 제한은 1초다.

입력출력
1055
1000005000050000
1000000000000000000500000000000000000500000000000000000
접근 방법먼저 생각해 보고 펼치세요

반복문으로 1부터 더하면 O(N)이다. N이 1018이면 덧셈만 1018번인데, 1초에 1천만 번이라는 어림값으로 나누면 1011초, 약 3천 년이 걸린다. 입력 범위가 1018이라는 것 자체가 O(1)이나 O(log N)으로 풀라는 신호다.

1부터 N까지의 합은 공식 N(N+1)/2로 한 번에 구할 수 있다. 1 + N, 2 + (N−1), …처럼 앞뒤를 짝지으면 합이 모두 N+1인 쌍이 N/2개 생기기 때문이다.

남은 함정은 나눗셈이다. /를 쓰면 결과가 float이 되어 큰 수에서 끝자리가 틀어진다.


n = 10 ** 18
print(n * (n + 1) // 2)        # 정수 나눗셈: 정확하다
print(n * (n + 1) / 2)         # float이 된다
print(int(n * (n + 1) / 2))    # 정수로 되돌려도 이미 틀렸다

N(N+1)은 연속한 두 정수의 곱이라 항상 짝수다. 그래서 // 2로 나눠도 버려지는 나머지가 없고, 결과가 정확하다.

풀이 코드 

import sys

input = sys.stdin.readline


def sum_to(n: int) -> int:
    # n(n+1)은 항상 짝수라 // 2 가 정확히 나누어떨어진다
    return n * (n + 1) // 2


n = int(input())
print(sum_to(n))

스스로 확인

0.1 + 0.2 == 0.3이 False인 이유는?

float은 수를 2진수로 저장하는데, 0.1·0.2·0.3은 2진수로 끝나지 않는 소수라 모두 가장 가까운 근삿값으로 저장된다. 근삿값끼리 더한 결과가 0.3의 근삿값과 마지막 자리에서 달라서 False가 된다.

int(-2.5)와 -5 // 2의 결과는 각각 무엇인가?

int(-2.5)는 0 쪽으로 버려서 -2, -5 // 2는 아래로 내려서 -3이다. 양수에서는 둘이 같지만 음수에서는 1만큼 차이 난다.

a = [1], b = a 다음에 b += [2]를 하면 a는 어떻게 되는가?

a도 [1, 2]가 된다. a와 b는 같은 리스트이고, 리스트의 +=는 새 리스트를 만들지 않고 그 리스트 끝에 원소를 붙이기 때문이다. 불변인 int의 +=가 새 객체를 만드는 것과 대조된다. 반면 b = b + [2]는 새 리스트를 만들어 b에 붙이므로 a는 그대로다.

N ≤ 100,000인 문제에서 이중 반복문(O(N²)) 풀이가 위험한 이유는?

N² = 100억 번이다. 1초에 1천만 번이라는 어림값으로 약 1,000초가 걸려 시간 제한을 크게 넘는다. 이 범위에서는 O(N log N) 이하의 방법을 찾아야 한다.

정리

  1. 값마다 자료형이 있다. 리스트·딕셔너리·집합은 가변이고, 숫자·문자열·튜플은 불변이다.
  2. int는 크기 제한이 없고 정확하다. float은 2진 근삿값이라 오차가 있으니 == 대신 math.isclose()를 쓰거나 정수로 계산한다.
  3. int()는 0 쪽으로 버리고, //는 아래로 내리고, round()는 짝수 쪽으로 반올림한다. 큰 정수 나눗셈은 //로 한다.
  4. bool은 int의 일종이라 sum()으로 개수를 셀 수 있다. None은 is None으로 확인한다.
  5. b = a는 복사가 아니라 같은 객체에 이름을 하나 더 붙이는 것이다. 가변 객체를 따로 쓰려면 copy()로 복사한다.
  6. 빅오는 n이 커질 때 연산 수가 늘어나는 모양이다. 낮은 차수와 상수 배는 버리고, 숨은 비용까지 포함해 센다.
  7. 입력 범위와 "1초에 대략 1천만 번"이라는 어림값으로, 코드를 짜기 전에 필요한 복잡도를 먼저 정한다.
